# Demo v4 待机、后跳、跳跃身体姿态

针对待机两帧僵硬、后跳重复旧蹲伏/空中姿势、跳跃身体偏向奔跑的问题，本轮用内置 `image_gen.imagegen` 生成专用无武器姿势。每帧保持银发红挑染、黑长风衣红内衬和红色近侧手臂；身体图中不包含刀、剑柄或剑鞘。

## 运行时映射

| Clip | 帧数 | 源姿势 | 建议身体阶段 |
| --- | ---: | --- | --- |
| idle | 8 | idleback:0–7 | 120 ticks（约 2 秒）循环，四帧吸气、四帧呼气 |
| back_dash | 8 | back:0–7 | 准备 0–1、蹬地 2、滑翔 3–5、落地缓冲 6、恢复 7；总 22 ticks |
| jump | 8 | jump:0–7 | 完整站姿→蓄力→蹬地→上升→顶点→下降→伸腿→缓冲姿态全集 |
| jump_rise | 3 | jump:2,3,4 | 上升时按跳跃进度选帧；由伸腿蹬地过渡到收腿 |
| jump_apex | 2 | jump:4,5 | 顶点附近的收腿与衣摆滞后 |
| jump_fall | 2 | jump:5,6 | 下落阶段展开腿、准备接地 |
| jump_land | 3 | jump:7,6,0 | 低姿势吸收冲击→起身→恢复站姿 |

`jump` 是完整姿态集合。建议运行时按上升、顶点、下降、落地选择 phase clip，避免在仍然腾空时播放准备蹲伏或着地帧。各动作额外带有 `motion_phases`，索引均为当前 clip 的本地帧索引。

`game/assets/actors_v4/manifest.json` 在 V3 manifest 基础上仅覆盖 idle/back_dash/jump，并增加四个跳跃 phase clip，共 24 个动作。其余 17 个动作的所有元数据、socket 和文件路径完全保留；仍引用 `assets/actors_v3/player/`，没有复制或改写旧贴图。

## 真实关键帧与尺度

待机 8 帧为真实独立源姿势，包含胸肩呼吸、肩胯重心变化、发梢与衣摆的滞后摆动。没有用两帧复制或图片淡入伪造 8 帧。后跳独立 8 帧有面朝右、向左后仰、空中收腿、下降伸腿和缓冲恢复。跳跃独立 8 帧以直立上身和垂直动作代替原来的奔跑空中姿势。

共使用 24 个新身体源姿势。`body_idleback.png` 的后八帧是最初的后跳尝试，因动作仍偏前跃而未被接受；运行时后跳全部来自随后生成的 `body_back.png`。该情况在 prompt provenance 与 bake report 的 `used` 字段中明确标记。

所有新帧沿用 320×248 画布、脚底 root `(144,230)`、约 190 px 站姿。每张 source sheet 使用一个骨架尺度，不对单帧分别缩放。腾空姿态使用审核后的虚拟地面基线，防止最低鞋底变化造成锚点上下跳动。

每帧提供 `sockets.hand`（相对脚底未翻转坐标）、`angle`（Godot y 向下，从右方向到刀尖角度）、`layer`、`source_pose`。待机武器角度 35°；后跳将刀收在胸前，使用 -115° 至 -135° 的护身方向；垂直跳跃在背后收刀（145°），伸腿与着地再恢复 35°。运行时武器继续独立渲染。

## 重建与核验

运行 `tools/bake_body_v4.py` 可完全离线重烘焙。工具读取 V3 manifest 和本目录源图，只写 V4 输出与审核文件。

- `generation.json`：完整实际提示词、引用图和内置工具保存路径。
- `bake_report.json`：32 个源主体坐标、24 个实际使用源姿势、逐帧 root/hand/angle 校准、动作数量与来源核验。
- `calibration_*.jpg`：原图上的握点（黄圈）、root（绿十字）与刀方向（蓝线）。
- `review_*.jpg`：最终帧画布校准，适合对照运行时 WeaponRig。
- `.gif`：真实身体连续帧预览；武器、角色整体移动和特效由运行时补充。

烘焙已验证真实透明 RGBA、主体数量、无帧画布裁切、每个握点邻域接触手部、socket/duration/source_pose 等长、motion phase 索引合法、每个新增 clip 的实际像素帧互不相同，以及 17 个继承 V3 动作的元数据完全未变。未在本子任务运行 Godot；战斗和移动状态映射由主任务进行实机验证。
