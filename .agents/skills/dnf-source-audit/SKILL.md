# DNF 原版数据审计

从当前仓库根目录执行。先读 [AGENTS.md](../../../AGENTS.md)、[协作总纲](../../../docs/project/00_协作总纲.md)、[28 分工](../../../docs/design/28_工作区分工与原版资料共享.md) 和 [原版拆解路线](../../../docs/design/26_DNF原版拆解与还原路线.md)。只读调查不等于批量改造授权，按用户目标决定是否继续编译和接入。

## 来源与依赖

- 从 `game_dnf/source_materials.json`、资源锁和 `.workspace` 的本机库位置确认来源。登记档案版本、原路径、SHA256、提取器和对应内容 ID。不同 PVF 分开查，静态档案存在不能证明原客户端实际加载它。
- 优先复用 `tools/dnf_pvf.py` 的 `open_library()`/`Library`，SQLite 通过现有只读入口访问；调查其它 PVF 时读 `tools/dnf_pvf_archive.py`。缺少整库先核对缓存/发布锁，不立即重建或全量下载。
- 从 LST 的 ID → 原路径 → 字段/字节 → 相对引用追踪。使用现有解析器的规范化与 `resolve()`，记录缺文件、未解字段和跨版本差异，不用空默认值掩盖失败。
- 对动作追 MOB/CHR 的动作表、ANI 时序/帧/锚点及 ATK 攻防盒；对技能追 SKL 与 ACT/被动对象、特效/声音。对 AI 读 [48 AI 边界](../../../docs/design/48_副本BOSS的AI数据边界.md)：区分怪物实例、族级共享目录、脚本空壳和实质选招逻辑；缺 think 不能直接认定无 AI。
- 原字节解析值、结构推断和实现适配分别按现行证据规范记录。名称翻译不是字段语义证据；中文展示与原档案保存分别处理。

## 编译与运行时核对

- 接入前读 [44 内容接入工作流](../../../docs/design/44_内容接入工作流.md) 和对应工具 `--help`。怪物侧用 `python tools/pipeline_dnf.py monsters`，按总账 → 内容包 → 图集 → 映射 → 检查依赖顺序执行；仅调查时不触发重建。
- 核对实际副本引用是否进入内容包、mob → kind → bank 是否一致、动作别名和实际图集帧是否存在。保留源字节和版本归档；局部生成只 stage 本轮相关产物。
- 改解析器时运行对应真实解析/依赖测试，例如 `tools/test_dnf_pvf.py`；运行时问题再使用独立战斗入口验证。`pipeline_dnf.py verify` 是内容闸门，不能替代怪物 AI、命中或用户观感验收。

## 交付

结论携带 ID、源版本/路径/哈希、字段原值、解释、代码消费位置、验证证据和未知项。分别说明档案覆盖、有效解析、资源可用、运行功能与用户验收，完整覆盖只按实际可证的层级表述。调查中取得的可共享工具/结论按当前分工发布，后续取证需求写成具体源字段和可测操作。
