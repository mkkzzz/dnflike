## 二、中文源阻塞更正与版本契约

旧任务包“串表只有键名，必须另找中文串表”和后续交接“111没有中文”的判断不成立。type-9表ID＋type-10键下标经n_string.lst可找到中文正文；直接字串须读取原字节按对应编码解码，不能把cp949乱码当加密。

现有111结构可立即使用本版本繁体正文，不再将“无中文源”列为阻塞。简体客户端是独立版本，身份及覆盖统计见取证报告；它不是已确认实际加载版本，也不是已经筛好的60级内容包。

- 保留原PVF/数据库SHA256、路径、数字ID、原表/键/行号或直接字串索引。
- 跨版本按ID＋路径＋字段语义核对后复用文本，不能跨PVF按字符串下标直接join。
- 保留当前结构基线；来源冲突、未索引文件和不支持规则须隔离，不静默覆盖。
- 60级白名单需排除后期、活动和历史候选；低等级、文件名或索引存在不足以单独证明应启用。

## 三、执行顺序

1. 整库迁移：全部索引、未索引源文件、别名、完整中文和未知字段保留；异常脚本保留原字节，不因解析失败丢弃。运行工程不依赖本地客户端。
2. 通用编译：按任务目标、奖励/前置、物品类型和效果语法逐类支持；一次接入一类的全部匹配记录，不逐条硬编码早期任务。
3. 物品统一接Inventory、装备属性、消耗品、服务、发奖和原图；索引归属优先于后缀。缺功能要补对应处理器，不能将配方、礼包、时装改成普通材料凑数。
4. 全任务图保留职业/等级/地区/前置条件，区分数据迁移、规则编译与当前角色实际可接取。缺NPC/地图的空间接入状态明确记录，不绕过前置，也不停止整库工作。
5. 依据整库缺口统计推进紧急/称号/日常/转职、条件通关、配方/礼包/时装/套装/触发效果等处理器，直至范围内全部迁移和功能补齐；不把只读查询计为可执行内容。

用户追加逐件武器外观已按整批接入，见[交付](../../reports/ws2/2026-10/2026-10-29_逐件原武器外观实装.md)。后续顺序固定为：通用任务目标/生命周期 → 原经验与奖励 → 任务掉落/获取 → 装备属性/套装/触发 → 其他消耗品效果 → 配方/礼包 → 其他装备类别/时装/称号/宠物。每类按整库匹配处理，目标未完成前不以只读迁移收尾。

## 四、交付与验收

- 每批任务更新运行时定义及总账implemented标记，运行 `python tools/check_dnf_quests.py`，要求一致且无回退。
- 物品保留源ID、字段、资产映射，验证堆叠/消耗/装备属性/选奖与失败回滚；预览与实装使用同一导出包。
- 按用户最新范围，跑相关模块与对应GM快验（如 `tools/run_dnf_loop.ps1 -Test -TeachingOnly`），验证正式接取、累计、交付和存读档；副本过程可用指令跳过，实战通关由对应工作流处理，不作为本区交付前置。文本解析通过不代表实装。
- 原始目标/奖励参数、恢复语义、重量单位等按批确认，不能因为能读取就声称完整原版还原。
- 整库迁移和批量执行入口：`tools/build_dnf_native_catalog.py`；包校验：`tools/check_dnf_native_catalog.py`；运行时按原ID/简体中文查询使用GM的native指令。只读全库、可执行子集、当前可接取及剩余功能分别报告。
