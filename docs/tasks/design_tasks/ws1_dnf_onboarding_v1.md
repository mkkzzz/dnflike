# ws1 无原客户端开发接入 v1

## 目标与边界

用户2026-10-22要求ws1参与新版开发，但ws1没有原DNF60整合包。
ws1可依靠共享提取库、配置数据库、来源记录、Godot工程和共用设计开发，无需先安装原客户端或服务端。
缺少原版环境会影响运行行为取证；这部分由有原环境的工作区补证据，不能用Godot现版结果替代。
本文是已准备好的接入与建议首任务，ws1同步后自行认领、校验和登记接收，不代填其状态文件。

| 入口 | 用途 |
|---|---|
| [共享接入](../../design/23_DNF资源共享与工作区接入.md) | 资源权限、缓存、版本锁、冲突和更新 |
| [原版拆解](../../design/26_DNF原版拆解与还原路线.md) | 共用设计、证据、全系统范围与现版差异 |
| [共同任务包](dnf_restore_baseline_v1.md) | T0～T5依赖、范围和交付要求 |
| [新版运行](../../../game_dnf/README.md) | Godot项目、操作、构建与回归入口 |

## 一、ws1能拿到什么

| 材料 | 已有共享位置 | 能支持什么 |
|---|---|---|
| Godot代码、配置、设计、任务与工具 | 主源码仓库main | 阅读、开发、回归与协作 |
| 小型运行包 | 独立资源库Release，按asset_store.json锁定 | 不装原游戏也能运行Godot样板 |
| 完整提取库 | 同Release的完整库包 | 选图、动作/配置查询、音频查看、资源/引用审计 |
| 图像/配置索引与原始内容 | 完整库catalog.sqlite、pvf_config.sqlite及资产文件 | 自行查MAP/TIL/SKL/MOB等，无需ws2反复发送文本 |
| 来源/异常与版本差异 | 完整库摘要、共同设计与审计记录 | 区分已证实、候选、未知和适配 |
| 原客户端、服务端磁盘、原版运行录像 | 不在当前已发布提取包内 | 原版实际加载/运行行为仍需ws2补证据；未发布录像不能假定已共享 |

完整库的配置来源仍是备份PVF，实际生效关系待核实；可研究结构和开发工具，不能把全部条目认定为目标版有效内容。
源码与私有资源库权限分开；403/404先核登录账号、邀请和仓库权限，无须重新找原游戏包。
同机同盘可复用外部缓存；不同电脑按同版本下载，不依赖ws2本机服务在线。

## 二、接入步骤

按正常“开工”顺序同步代码、读协作总纲并保留已有改动；已有.workspace不要重新初始化成其它区。
需要Python 3.11及以上；浏览/重建需要Pillow；Godot开发用仓库指定版本。

```powershell
# 在ws1仓库根执行；用自己的账号登录GitHub并取得私有资源库权限
python tools/dnf_asset_store.py sync --full

# 不需要原客户端；检查共享归档配置，或指定任意精确脚本路径
python tools/audit_dnf_design.py
python tools/audit_dnf_design.py --script dungeon/act1/lorien.dgn --script map/lorien/bn10.map --output temp/ws1_source_probe/audit.json

# 查看图像、动作与配置
python -m pip install -r requirements.txt
python tools/browse_dnf_assets.py

# 缺固定Godot时先安装，然后验证当前工程
powershell -NoProfile -ExecutionPolicy Bypass -File tools/setup_godot.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_dnf.ps1 -Test
```

sync --full同时包含运行包与完整库；只需运行样板时使用sync即可。
审计的--script可重复传数据库内精确脚本路径；不传时使用默认样本。
输出保留SHA256、CRC标签、token偏移/类型/原始值与重复标签顺序，不代表完整语义已恢复。
路径可通过资源浏览器配置页检索。浏览器只监听本机，ws1使用自己的库，不访问ws2的127.0.0.1地址。

## 三、建议分工

| 工作 | ws2负责提供/推进 | ws1可以独立推进 |
|---|---|---|
| 原版身份与行为 | 有效PVF、补丁顺序、原版环境/录像与实验 | 根据证据提出可验证问题，不猜原版答案 |
| 原数据与解析 | 已发布全库、来源差异、新版本、共同解析契约 | 查询全库、补解析工具、记录字段与引用并提交代码 |
| 首批开发 | 战斗主模拟、动作/判定与数值核实 | 建议先认领T2：原地图数据导出、加载器与场景还原 |
| 后续UI | 提供原版整屏、状态、图标/字体来源 | T2边界稳定后再认领T3：原HUD与窗口 |
| 集成与验收 | 提供原版对照，协调共同坐标/时钟/模拟接口 | 本区Godot运行、回归、同包截图/录像与差异记录 |

此表是建议，不固定永久职责；其它区的状态与工作由其自行认领。
ws1参与代码与工具开发不受此前“只做简单图片生成”的生图分工限制；复杂新生图仍沿用原分工。

## 四、ws1首任务：T2原地图加载与场景还原

目标：把一个原MAP及其依赖做成可追溯的Godot样本，逐步替代固定摆位；不能直接宣布原版完全一致。

1. 查询lorien.dgn与地图候选，保留原路径/哈希和上下文。bn10.map只是可读取的研究样本，不预先认定为原版实际起始房间。
2. 梳理MAP→TIL/ANI→IMG、门/物件/怪物ID引用；歧义、模板、缺失和未知字段输出诊断。
3. 保留有序原始记录，分别解释位置、层序、滚动、碰撞与门；单位/数组布局/加载顺序未知时记录假设和实验问题。
4. 先新增独立导出工具、native_map_loader.gd及独立验证场景。这些是拟新增模块，暂不改现版main.gd或战斗配置。
5. 用全库实际图像回放候选房间，记录层级、根坐标、相机、门方向与遮挡，不靠任意平铺凑原房间。
6. 与ws2交接数据/加载接口后再接正式场景；修改native_stage.gd等公共文件前登记占位。

候选导出接口至少包含schema/revision、来源资源版本/PVF身份/内部路径/SHA256、有序原始记录、解释结果、引用候选与diagnostics。
解释结果要有单位和依据，unknown不能静默变成0；怪物/门/物件保留原ID，由共同映射解析。
可先做独立验证场景，对未核实的层序/坐标明确标试验，不阻塞全部开发，也不写成原版事实。
对应DNF-D004～D006、D016，定义见[现版差异](../../design/26_DNF原版拆解_现版差异.md)。

交付：代码、字段/引用表、同包场景回放、Godot实测、需要ws2补的原版证据清单。
接收条件：ws1自行同步并运行；来源可追溯、诊断明确、候选场景可重建、未影响现版；最终一致性仍需原版对照和用户验收。

## 五、避免依赖停摆

- 新素材先在全库检索，记录原路径/帧/哈希，不让ws2反复手工发PNG。
- 全库没有的内容、真实加载顺序、原版截图/录像等，在本区过程记录列具体缺口，按既有交接流程交ws2。
- ws2补证据携带来源版本、角色/地图/装备条件、规则/差异ID与结果；新二进制按资源流程发新版本，不改旧包。
- 原版录像未交付时，继续结构解析、工具、独立加载与Godot测试，保留一致性验收缺口。
- 审计JSON在temp可重建，规则结论与接口进源码文档；不依赖聊天记忆或ws2的temp绝对路径。

## 六、给ws1的开工口令

> 开工：按 docs/tasks/design_tasks/ws1_dnf_onboarding_v1.md 接入DNF共享资源，先核对私库权限、完整库审计与Godot启动；成功后认领T2原地图加载与场景还原。先做独立导出工具、加载器和验证场景，原版未知项按规范登记，暂不改main.gd战斗主模拟。

用户将该口令发到ws1后，ws1按正常流程执行；本文发布不代表已向其它会话发消息或ws1已接收。
