# DNF 原版复刻并行计划

用户要求把依赖本机原版的取证留在 ws2，把共享数据足以支持的开发交给 ws1。总目标覆盖技能、战斗、界面、系统、任务、副本和城镇。现行接口及文件责任以[分工与共享](../../design/28_工作区分工与原版资料共享.md)为准。

鬼剑士是当前最高优先级。先做普攻、上挑、格挡与三段斩的可操作对照，再按职业分支推进。技能验收分别记录效果与数值、身体与武器动作、特效与音效，以及输入、取消、命中反馈和连续操作。自动回归与原版对照、实际操作验收各自记录。

独立专项通过 Godot 的 `--headless --path game_dnf --script` 运行，回归入口集成由 ws2 处理。上述任务不需要安装原客户端，也无需下载完整提取库。正式入口默认使用随仓库分发的运行包，复活资源按哈希核验；从源库重烘焙使用独立检查。报告分别标记“当前版本复现”和“已按原规则核对”。

分工按文件执行，同一文件及其生成物同一时间只有一方写。ws1 遇到跨面板问题时，附基准提交、复现输入、实际结果、预期结果和涉及文件，由现持有方修改。需要交接既有文件时，在交接日志写清文件、基准提交、原版证据或共享契约、验收用例与归还条件，接收方登记后再切换编辑方。测试共用入口和资源生成由现持有方统一接入，双方均可运行。后续职业分支按同样的文件级交接推进。

## 接续与验收

1. ws2 每批交接提供适用原版路径与 SHA256、已证规则、必要运行资产或版本锁、可复现输入与预期输出，以及仍缺的原证据。原客户端安装目录和临时取证目录留在本机。
2. ws1 以仓库提交和共享包为输入，从正常入口复现。缺原证时只退回具体字段、状态或资源版本，接着做同批其余工作。两边分别登记接收、实现与验收。
3. 房间、战斗和流程通过 [CombatSession](../../../game_dnf/combat/api/combat_session.gd) 及其视图、击杀、房间清场与死亡事件衔接。独立任务遵守上表及[分工契约](../../design/28_工作区分工与原版资料共享.md)，共享入口和生成物先按[工作区登记](../../project/03_工作区登记.md)占位并指定唯一编辑方。
4. 每批跑正常入口、专项和相邻旧路线。计划以本地运行回归、原版对照、用户实机验收分别登记。神殿正式入口、完整技能与后续章节都按对应证据开通。

ws1 开工入口见[项目待办](../../project/02_待办.md)。
