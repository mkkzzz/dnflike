# DNF 60 级单机内容还原计划

目标是交付可从建角连续游玩到 60 级的离线 PVE。以[60 级一致基线](../../design/49_单机60级一致基线.md)为总目标，用等级段组织联合交付，用地区和职业组织各区生产。每区负责本线的取证、实装、自验和发布。 [分工契约](../../design/28_工作区分工与原版资料共享.md)

上一批 ws1 系统模块的开发、自验和发布已结项，后续缺陷按原文件归属维护。项目级真人试玩和用户体验反馈独立记录。本轮两区都做内容还原，按原版取证、依赖确认、实装调校和回归的实际投入排程。

## 长期分工

| 工作区 | 长期负责 | 每批交付 |
|---|---|---|
| **ws1 世界内容线** | 目标范围内各等级段的城镇与区域、NPC 和对话、主支线任务内容、副本与路线、房间机关、怪物和领主、奖励与商店投放。拥有地区和怪物专属内容、资源及专项测试 | 按地区发布能实际进入、接任务、打副本、结算、回城并继续下一段的内容包。任务奖励与掉落用物品 ID 对账。已交付系统模块按原边界维护 |
| **ws2 可玩职业线** | 目标职业、转职与觉醒条件、角色成长、技能与武器表现、装备与物品规则。持有战斗、任务、经济、存档及正式流程的共用能力，负责原客户端专属取证 | 按职业和等级段发布能成长、学习、施放、换装及存读档的角色包。先打通鬼剑士到剑魂，扩到另外三条鬼剑士转职，再推进目标版本确认开放的职业 |

跨线内容按可独立改动的部分划分。转职和觉醒由 ws1 交付 NPC、任务与副本内容，ws2 交付职业条件、授予、存档和技能行为。奖励和商店由 ws1 决定已取证的内容投放，ws2 实现物品效果、经济规则和交易事务。两区在同一正式入口各自验证本线交付。

## 排程与交接

1. ws1 按地区列任务链、独有怪物或领主机制、路线与投放缺口。ws2 按职业列技能行为分支、成长、装备和共用能力缺口。两区先排阻断下一次等级段交付的事项。
2. 首轮各完成一个可重复验证的内容样板，用取证、实装、声画调校和回归的实际投入估算同类任务。按地区包或职业包发布后重估，原客户端等待与共同试玩时间单列。
3. ws1 独立写地区和怪物内容源、专属行为、资源和回归。已合用的生成表或入口暂由现持有方写入。首批正式接线时确定每类内容的稳定数据入口和唯一写入方，地区包后续沿用该入口发布。分区前登记已有共用文件的移交边界。
4. 只有原客户端才能确认的分支由 ws2 批量采样。请求写明源 ID、触发条件、武器或难度和需要记录的现象。缺证据的条目单列，两区继续做已具备输入的内容。

## 并行边界

1. 每项开工记录基准提交、可写文件和本区验收入口。两区使用发布的资源和接口作为只读基线，禁止同一文件或生成物并行写入。
2. 发现跨界问题时，在本区报告记录路径和复现条件，文件持有方自行修复、测试和发布。独立任务遇到跨界需求时，只做已闭合的本区范围。
3. 各区自验各自发布的内容。已有原档和正式入口的内容直接开工。缺少原客户端证据或共用入口支持的具体分支单列，按各自的依赖关闭。
4. 验收记录区分自动化、原版对照和实际操作。共用入口与依赖变更由 ws2 自行验证，包括现行窗口和装备服务调用的兼容性。共用测试由 ws2 维护，各区维护本区专属测试并自行发布结果。各区旧状态中的跨区验收安排以本页为准。
