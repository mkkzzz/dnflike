# DNF 原版复刻并行计划

两区按可独立交付的模块分工。每区负责自己任务的开发、回归、验收和发布。新任务以当前可取得的资料和已发布的接口开工。完整目标仍覆盖技能、战斗、界面、系统、任务、副本和城镇。 [分工契约](../../design/28_工作区分工与原版资料共享.md)

本批以 `81aa8f5f` 为开工基准。**ws1 约 52–76 工程小时，ws2 约 50–76 工程小时**。预算含资料核对、生产实装、界面或表现细节、专项回归、正式入口自验和证据整理。已发布的选人建角、技能面板、噬灵鬼斩三种冲波及两种附加效果、冰晶之萨亚阵地及鬼斩选择均已扣除。工时仅用于安排本批工作，实际取证和开发耗时由各区在交付时记录。

每区在首项交付及每批结束时，在本区报告记录实际工时、剩余项及估时。若两区剩余工时中点相差超过较小值的 20%，或一方提前做完，下一批优先把可独立交付的完整模块排给余量较大的一方。新增模块须能用已发布输入开工，有唯一写入方并能自行结项。

## 并行边界

1. 每项开工记录基准提交、可写文件和本区验收入口。两区使用发布的资源和接口作为只读基线，禁止同一文件或生成物并行写入。
2. 发现跨界问题时，在本区报告记录路径和复现条件，文件持有方自行修复、测试和发布。独立任务遇到跨界需求时，只做已闭合的本区范围。
3. ws2 发布内容由 ws2 验收。ws1 的开工、合入或结项不以 ws2 的新证据、新产物或验收请求为前提。两区可以各自同步已发布的主线。
4. 验收记录区分自动化、原版对照和实际操作。共用入口与依赖变更由 ws2 自行验证，包括现行窗口和装备服务调用的兼容性。共用测试由 ws2 维护，各区维护本区专属测试并自行发布结果。各区旧状态中的跨区验收安排以本页为准。
