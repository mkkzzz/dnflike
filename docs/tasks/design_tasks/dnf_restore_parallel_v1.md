# DNF 原版复刻并行计划

两区按可独立交付的模块分工。每区负责自己任务的开发、回归、验收和发布。新任务以当前可取得的资料和已发布的接口开工。完整目标仍覆盖技能、战斗、界面、系统、任务、副本和城镇。 [分工契约](../../design/28_工作区分工与原版资料共享.md)

本批按已发布的提交 `297d1dda` 重估剩余工作。**ws1 约 42–62 工程小时，ws2 约 42–64 工程小时**。每项预算含资料核对、生产实装、界面或表现细节、专项回归、正式入口自验和证据整理。已发布的选人建角、技能面板，以及 ws2 已完成的战斗修复从剩余预算扣除。范围是本批可并行交付的工作。

每区在首个剩余任务交付时，在本区报告记录实际工时与重估后的剩余工时。若两区剩余区间中点相差超过 20%，或一方提前做完，优先重排后续可独立交付的完整模块。新增模块须能用当时已发布的输入开工，有唯一写入方并能自行结项。

## 并行边界

1. 每项开工记录基准提交、可写文件和本区验收入口。两区使用发布的资源和接口作为只读基线，禁止同一文件或生成物并行写入。
2. 发现跨界问题时，在本区报告记录路径和复现条件，文件持有方自行修复、测试和发布。独立任务遇到跨界需求时，只做已闭合的本区范围。
3. ws2 发布内容由 ws2 验收。ws1 的开工、合入或结项不以 ws2 的新证据、新产物或验收请求为前提。两区可以各自同步已发布的主线。
4. 验收记录区分自动化、原版对照和实际操作。共用入口与依赖变更由 ws2 自行验证，包括现行窗口调用的兼容性。现有共用测试由 ws2 维护，ws1 新增本区专属测试，自行运行和发布结果。
