# 22 资产画面规格（2K / 1080p）

状态：草案（2026-10-16 提交评审）。适用范围：此后所有新美术资产。
关联：[15 统一风格与题材规范](15_统一风格与题材规范.md) · [19 音效生产工作流](19_音效生产工作流.md) · [21 美术目录与资产归档](21_美术目录与资产归档.md) · [23 副本设计工作流](23_副本设计工作流.md)。

## 一、结论

- 正式版游戏视口支持两种目标：**2560×1440（2K）与 1920×1080（1080p）**，均为 16:9。
- 美术**原生制作分辨率 = 2560×1440（取最高目标）**；1080p 运行时整体 0.75 等比缩放。
- 一句话规则：**按最高目标分辨率出图，只许缩小，不许放大。**
- 现存 1280×720 旧资产为旧规格：**不因 2K 额外重做，也不扩大既有重做范围**。
  - 不上屏的设计源（角色/怪物标准原画等）保持有效、不重做；将来出图若参考细节不够，只在任务内按需补局部，不整体重画。
  - 上屏资产（动作、场景、实体、UI/头像）随各自的重制或新建任务升级到 2K 原生；已在计划内的重做（如 D031 鬼剑士全量动作、普通哥布林与头目动作生成）按 2K 执行。
  - 未排重制的存量（现行 V3/V4/V6 等）继续作为现行版本使用；过渡期新旧混用的显示策略由实装区另立任务。

## 二、调研依据

- 行业通行做法：以最高目标分辨率（或更高）作为原生制作分辨率、向下缩放使用；反向放大必然损失清晰度，高清 2D 手绘尤其明显（"can always scale down, can't scale up"）。
- Godot 官方多分辨率指南要点：2D 手绘用 `canvas_items` 拉伸模式（在目标分辨率重绘、而非整张位图放大）、`fractional` 缩放、宽高比同为 16:9 时 `keep`/`expand` 等效、动态 MSDF 字体、UI 用锚点+容器；`viewport`+整数缩放只适合像素风。
- 降采样提示：0.75× 显示时，过细的线和小字易出现锯齿——关键细节不要做得太细。
- 引擎侧视口与拉伸设置由实装区配置，另行登记任务，不在美术产出范围。

## 三、基准数值（本项目默认）

- 一屏（2K 原生）= **2560×1440**；1080p 等效一屏 1920×1080。
- 角色与物体按**屏占比守恒**出图：世界比例不变，像素尺寸为现行 720p 版本的 2 倍。例：玩家身高 ≈ 屏高 26% → 2K 原生约 380 px（现行 190 px）；各身份的具体尺寸在其重制任务登记。
- 场景图：**横竖两个方向都必须超过一屏**；副轴余量默认约 10%，用于镜头抖动与小幅平移。

| 类型 | 2K 原生尺寸（默认） | 说明 |
|---|---|---|
| 横幅短图 | ≥3840×1600 | 约 1.5 屏宽 |
| 横幅长图 | 5120~7680×1600 | 约 2~3 屏宽 |
| 竖幅图 | ≈2816×（2880~4320） | 约 1 屏宽 + 余量；高 2~3 屏 |

- 非生物实体、关卡门、特效：2K 原生像素出图，不靠运行时缩放。
- UI：按 2K 基准出图；布局自适应（锚点/容器）；文字运行时渲染；图标出一套 2K 尺寸，另按需补小尺寸。
- 音频不受分辨率影响，仍按 [19 音效生产工作流](19_音效生产工作流.md)。

## 四、验收

- 每项新资产在 2560×1440 与 1920×1080 下检查：缩放后清晰、细线可读、无糊边、比例与锚点一致。
- 方式：原图检查 + 0.75× 离线缩样抽查；实机两分辨率截图由实装区在接入任务中提供。

## 五、维护

- 目标分辨率、缩放倍率或制作基准变化时必须更新本文，并回归已发布资产清单。
- 每张图/每套资源的具体尺寸在其任务包登记，不在本文逐一维护。
