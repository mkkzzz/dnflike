## 二、必须建立的内容台账

| 台账 | 主键与关联 | 必填字段 |
|---|---|---|
| 职业/角色 | 原始ID、职业/成长类型、CHR | 有效版本、转职/等级限制、基础动作、技能表 |
| 动作 | 逻辑动作ID、ANI/ACT、角色/武器上下文 | 原始路径/哈希、循环/等待、帧/时长、位移、事件、依赖 |
| 技能 | 原技能ID、SKL、职业/等级 | 显示名引用、学习限制、消耗/CD、行为/ATK/被动物、模式 |
| 怪物 | 原怪物ID、MOB、刷怪记录 | 图像/动作、AI/ATK、等级、变体、领主/精英条件 |
| 地下城 | 原地下城ID、DGN | 区域、等级/难度、有效房间、图生成、入场/结算 |
| 房间 | 地图路径/哈希、地图/房间ID | 尺寸/镜头、图块/层序、门/出生点、实体/怪物/音乐 |
| 装备/物品 | 原物品ID、EQU/STK | 名称引用、分类/部位、等级、属性、图标、使用/获得途径 |
| 任务/NPC | 原任务/NPC ID、QST/NPC | 接取条件、状态、文本引用、目标/交互、奖励/解锁 |
| UI | 屏幕ID、控件ID、资源路径/帧 | 可见条件、锚点/尺寸、状态图、数据绑定、输入/焦点 |
| 规则/差异 | rule_id、diff_id | 来源、适用条件、证据、当前实现、风险和验收 |

主键沿用已证明的原ID，并附命名空间；还没证明映射的项目用独立候选ID。
本地化名称需要解开间接引用，不靠文件英文名擅定中文技能名或怪物身份。

## 三、完整单技能拆解

1. 身份：原ID、职业/成长类型、版本、显示名、PVE/PVP上下文。
2. 学习：等级、前置、SP、可学上限、装备/职业限制。
3. 施放：输入/指令、可用状态、朝向/移动/空中条件、扣费/CD时点、失败反馈。
4. 时间线：起手、蓄力、逐段有效、收招、可取消、动作速度修正、等待状态。
5. 判定：每段盒体、攻击信息、目标筛选、命中去重/间隔、投射物、抓取/无敌/霸体。
6. 数值：逐级属性、武器/装备/被动修正、命中/暴击/防御/抗性、取整顺序与异常。
7. 表现：身体/衣装/武器图层、嵌套特效、偏移/混合/层序、声音、镜头、跳字。
8. 生命周期：命中/未命中、打断、死亡、切房、暂停、重开时的清理与持久状态。
9. 验收：原版与Godot同条件输入回放，关键帧/事件/数值对照，容差和反例。

只拿到ANI或SKL的一部分，不代表该技能拆解完毕。

## 四、完整房间拆解

必须从对应DGN/MAP及其依赖恢复房间身份，记录地图原点、可走区域、镜头轨迹、图块装配、远中近层、实体排序根与遮挡。
门包括图像/动作、四向坐标、朝向、触发体、连接目标、落点、锁定与开门事件。
怪物包括原ID、等级、坐标、随机/固定规则、AI覆盖、清房计数条件。
可破坏物/机关包括图像、碰撞、受击、破坏事件、掉落与切房状态。
音乐/环境声包括事件键、进入/退出、循环、混音与切换行为。
“使用森林图块”不等于“恢复原版森林房间”。

## 六、依赖与执行顺序

版本/ID锁定 → 坐标/时钟/资源路径 → 动作与地图解释 → 判定/属性/行为 → UI绑定与系统事务 → 成长内容与存档。
表现调研和系统台账可以同时进行；依赖未锁定的模块不得擅自定全局单位和公式。
各模块交付时附“已证实、推断、适配、未知”的规则清单和被哪些模块消费的接口清单。
新支持一个指令/字段后，先验证已有内容与边界，再扩到依赖该能力的内容批次。
