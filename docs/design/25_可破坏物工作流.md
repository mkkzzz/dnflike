# 25 可破坏物工作流

> 目的：新增一种**可被玩家打碎的场景物**（草丛、木栅栏、骨堆…）时，照本文走一遍即可，不必再摸索代码挂点。
> 首个对象：森林副本 10001 的草丛（`bush`，房间 1/2/4 共 3 处）。
> 相关：[19 音效生产工作流](19_音效生产工作流.md)（破坏音效走路线 A）、[23 副本设计工作流](23_副本设计工作流.md)。

## 一、总览：五步

| 步骤 | 做什么 | 改哪里 |
|---|---|---|
| 1 配置 | 给实体加 `destructible` 段 | `game/data/dungeons.json` → `entity_catalog.<id>` |
| 2 资产 | 确认 `intact.png` 存在（**必需**）；`damaged`/`debris` 可选 | `game/assets/dungeon/<id>/entities/<实体>/` |
| 3 音效 | 新增一个 kind，3 个变体 | `tools/bake_foliage_audio.py`（模板）+ `combat_audio.gd` |
| 4 回归 | 加断言 | `game/scripts/dungeon_regression.gd` |
| 5 文档 | 更新总清单/交接日志 | 见第七节 |

**代码本身不用改**——机制是通用的，配置驱动。只有"新增一个全新音效种类"才需要动代码（见第四节）。

## 二、配置：`destructible` 字段表

写在 `game/data/dungeons.json` 的 `entity_catalog.<实体id>` 里，与 `file`/`anchor`/`collision` 同级：

```json
"bush": {
  "file": "entities/bush/intact.png",
  "anchor": [89, 134],
  "collision": false,
  "destructible": {
    "hits": 1,
    "debris": {
      "columns": 4, "rows": 3,
      "scatter": 130, "rise": 95, "gravity": 620,
      "spin": 240, "life": 0.55
    },
    "dust": 10,
    "sound": "foliage_break",
    "shake": 1.1
  }
}
```

| 字段 | 缺省 | 含义 |
|---|---|---|
| `hits` | 1 | 需要打几下才碎。多段破坏配合 `damaged.png`（中间态）使用 |
| `debris.columns` / `rows` | 4 / 3 | 把 `intact` 贴图切成几列几行抛散。**这是「破坏动画」的实现方式**，不需要额外美术 |
| `debris.scatter` | 120 | 碎片水平初速（px/s） |
| `debris.rise` | 90 | 碎片向上初速（px/s） |
| `debris.gravity` | 620 | 碎片重力（px/s²） |
| `debris.spin` | 220 | 自转幅度，内部乘 0.06 转成弧度/帧 |
| `debris.life` | 0.55 | 碎片存活秒数；后 55% 时间线性淡出 |
| `dust` | 0 | 追加尘土粒子数量（走 `BattleFX.spawn_dust`） |
| `sound` | 空 | 破坏音效 kind 名；留空则静音 |
| `shake` | 1.0 | 震屏强度（走 `BattleFX.add_shake`） |
| `debris_file` | 空 | 可选：破坏后**留在原地**的残骸贴图（相对 `asset_root`），如骨堆 |
| `debris_root` | 空 | `debris_file` 的前缀目录（不填则按 `res://` 全路径处理） |

**放置**：同一实体在房间里的 `entities: [{ "id": "bush", "x": 1520, "depth_y": -50 }]` 不需要任何变化——只要目录里有 `destructible`，该房间这份实例就能被破坏。

## 三、代码接入点（已经做好，改机制时才动）

| 文件 | 负责 |
|---|---|
| `game/scripts/dungeon_entity.gd` | `setup()` 读 `destructible` → `destructible/hits_left`；`world_hit_rect()` 给命中判定；`take_hit()` 扣次数并触发 `_shatter()`；`_shatter()` 切图抛散 + 尘土 + 音效 + 震屏；`_process()` 推进碎片物理与淡出 |
| `game/scripts/player.gd` | `destructibles`（与 `monsters` 一样的共享数组）；`_emit_melee()` 里用**同一个命中矩形与景深容差**判定实体，每挥只打一次；破碎时 `destroyed_prop` 信号 |
| `game/scripts/main.gd` | 每房 `destructibles.clear()`；建实体时 `bind_fx(bm)` 并把可破坏的收进列表；接 `destroyed_prop` → `_on_prop_destroyed()` |
| `game/scripts/ground_space.gd` | `remove_entity()`：破坏后把该物的 footprint 从 `solids` 摘掉，避免还挡路 |

**关键约定**

- 命中判定用的是**视觉包围盒**（`world_hit_rect()` = `position - anchor` 到贴图尺寸），不是碰撞框；草丛 `collision=false` 也能被打到
- 景深容差沿用 `moves.json` 的 `hitbox.lane`（缺省 `lane_hit_tolerance`），与打怪一致
- `hit_targets` 用 `"<segment>:e<instance_id>"` 作键，保证**一次挥砍只打一下**，不会按 tick 连击
- 破坏后 `render_slices` 会被清空 → **回归里任何依赖 `render_slices` 的断言必须放在破坏断言之前**

## 四、音效：走 19 文档的路线 A

可破坏物属于"物体相撞/撕裂"类，用**原创程序合成**（路线 A），不走外部素材：

```powershell
python tools/bake_foliage_audio.py          # 生成 foliage_break_1..3.wav
```

脚本里三层配方可直接改：**木质脆断 + 叶片摩擦 + 落地闷响**。换成石材就把低频/共振改硬，换木质就把颗粒调稀。

然后在 `game/scripts/combat_audio.gd` 登记：

```gdscript
"foliage_break": [-9.0, 1, 140],   # [基准dB, 抢占优先级, 节流ms]
```

再在 `ALIASES` 里加一个语义别名（可选，如 `"bush_break": "foliage_break"`）。

**必做**：导入后检查 `.import` 的 `compress/mode`，**必须是 0**（本次又被默认导成 2/ADPCM，会导致回归的音效检查失败）。判据：`.godot/imported/<name>.wav-*.sample` 体积约为 WAV 的 **1.01 倍**；若只有 **0.21 倍**就是被压成 ADPCM 了。

## 五、回归断言（照抄这 6 条）

加在 `game/scripts/dungeon_regression.gd` 里、**依赖 `render_slices` 的断言之后**：

```gdscript
check.call(bush.destructible and not bush.destroyed, "bush is configured destructible and starts intact")
check.call(main.destructibles.has(bush) and p.destructibles.size() == main.destructibles.size(), "destructible props share the player's hit list")
check.call(bush.world_hit_rect().has_area(), "destructible prop exposes a world hit rect for melee")
var bush_destroyed: bool = bush.take_hit(1.0, 1)
check.call(bush_destroyed and bush.destroyed and not bush.collision_enabled, "one hit destroys the bush and clears its collision")
check.call(bush.render_slices.is_empty(), "destroyed prop stops rendering its intact slices")
main._on_prop_destroyed(bush)
check.call(not main.destructibles.has(bush), "destroyed prop is removed from the shared hit list")
```

跑法：`tools/run_demo.ps1 -Test`。本轮基线 **379 项 failures=0**。

## 六、验收清单

| 检查 | 判据 |
|---|---|
| 打得碎 | 普攻/技能命中草丛 → 立即碎成碎片抛散 |
| 有声音 | 能听到"木质脆断 + 叶片摩擦"，**不是**金属声 |
| 有反馈 | 有尘土、有轻微震屏 |
| 碎完消失 | 碎片约 0.55 s 后淡出，原地不留碰撞、不能再被打 |
| 只打一次 | 同一挥不会因多 tick 重复触发 |
| 打不烂别人 | 同房间的石头/木桩等没配 `destructible` 的不受影响 |
| 进出房 | 切房再回来，草丛是**新的一份**（每房重建，不保留破坏状态） |

> **已知取舍**：破坏状态不跨房间保存（`DungeonRun` 只存怪物状态）。若以后要"打碎后回房间仍是碎的"，需要在 `room_states` 里加 `props` 字段并在 `_load_room` 里回填——目前没做。

## 八、踩过的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **只改了 `_emit_melee`，游戏里还是砍不碎** | 回归全绿，但实机普攻打不烂草丛 | **最容易踩**：`player.gd` 有**两条**命中循环——`_seq_hit()` 给 V6 招式（三段普攻/拔刀斩，即主力招式），`_emit_melee()` 给旧动作。两处都要加实体判定。回归里用 `p._seq_hit(0,10)` 直接驱动 V6 路径才能盖住 |
| 新音效被导成 ADPCM | 回归报 `offline foley variants contain valid sixteen-bit PCM` | `.import` 的 `compress/mode` 改成 `0` 再导入 |
| 破坏断言放太早 | 遮挡测试依赖 `render_slices`，先碎就全红 | 破坏断言放到遮挡测试之后 |
| 以为要给每种物做 debris 图 | 没有 debris 图就没法做动画 | 用 `debris.columns/rows` 把 `intact` 切块抛散即可，**零美术成本** |
| 碰撞物破坏后还挡路 | 石头类 `collision=true`，碎了还挡人 | `main._on_prop_destroyed()` 已调 `ground_space.remove_entity()`；新增可破坏**碰撞**物时确认这条链没断 |
