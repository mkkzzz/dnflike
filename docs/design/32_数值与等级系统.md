# 数值与等级系统

> 用户于 2026-10-23 授权：先实装功能，玩法循环、奖励与成长节奏后续调整。接口依照[29 契约](29_新版工程框架_接口契约.md)，参照边界依照[26 证据规范](26_DNF原版拆解_证据与版本.md)。本页为数值功能与调参入口的权威说明。

## 一、范围与默认策略

- 数值模块负责等级经验、基础成长、属性汇总、技能等级/SP、装备实例与效果；战斗负责模拟、判定、效果时钟与伤害应用。
- 玩法来源只通过事务接口增加经验；击杀、任务、通关的奖励量独立配置，不将升级系统绑定到某个地下城循环。
- 技能采用源数据职业树：起步仅有上挑与鬼斩，等级、职业列、前置、SP 和技能上限默认强制；`force` 仅供调试。技能栏 A~H 由存档槽位驱动，不再写死招式。
- 初始等级上限为 60；升级保留当前 HP/MP 的绝对值，并夹到新上限。可配置升级回满。城镇出征仍按现有流程补满；不擅自决定后续恢复/疲劳玩法。
- 强化、品质、附魔、套装均参与属性计算；强化材料、成功率、收费与附魔服务已由[38](38_强化与附魔养成服务.md)接入，精确平衡与掉落分布后定。
- 所有新增界面复用现有原版皮肤、字体和按钮；训练上衣/项链为数值验证定义，不冒充原版物品，不制作替代图标。

## 二、数据与证据

配置入口为 `game_dnf/data/numbers.json`，修改后重启游戏；GM 用于即时改变当前角色/战斗测试条件。修改规则或解释时递增 revision，并更新关联验收。

| 配置组 | 职责 |
|---|---|
| progression | 等级上限、逐级经验表及缺省曲线、SP预算、升级恢复策略、当前试炼经验来源 |
| base / growth / growtypes | 初始属性、逐级增长、成长类型的附加增长 |
| formula / limits | 属性换算、伤害常数、修正范围与上下限 |
| equipment / equipment_slots / sets | 装备定义、部位、品质范围、强化、附魔与套装阈值 |
| skill_defaults / skills / skill_index / growtype_index | 初始赠送等级、购买成本、等级上限、被动、学习限制、原ID映射 |
| effects | 时长、刷新/叠加上限、属性修正、周期伤害、控制、元素攻击 |
| monsters | 等级成长与难度修正 |

数值基线、公式常数、训练装备、血之狂暴持续修正、武器精通换算和十字斩触发出血选择均为 **E-ADAPT**；不是情怀60的已核实平衡值。

原备份 SKL 的逐级表、学习条件与模式结构为 **E-PARSE**。技能伤害/控制参数按对应行读取，MP/CD/施放时间的双端点插值为 **E-INFER**。原版经验表索引、怪物基础表列定义、强化无视防御旧规则等仍未核实，本轮不将推断冒称已还原。

不修改原内容包；运行时只生成各角色独立的技能投影。原数据、适配配置、当前生效结果分别保留。`numbers.json` revision 2 增加 `hardattack/moonlight/charge_crash/buff`、三类武器精通、武器奥义、血气旺盛、物理暴击和生命之源；旧档只补齐缺失键，不覆盖已学等级。

可执行技能共 16 条：鬼斩、上挑、三段斩、十字斩、月光斩、格挡、拔刀斩、破军升龙击、血之狂暴、短剑/太刀/巨剑精通、武器奥义、血气旺盛、物理暴击、生命之源。主动伤害与 MP/CD/施放读取对应 SKL；被动 `level_row` 读取 SKL 等级行，武器精通只在匹配武器类型时生效。血气旺盛使十字斩消耗 HP，并将出血触发率提高至源静态数据对应的适配值。

## 三、计算与运行规则

属性按以下顺序从头汇总，撤装备/移除Buff后重新计算，避免反向扣除的取整漂移：

```text
基础 + 等级成长 + 成长类型
→ 装备/品质/强化/附魔/套装 + 被动 + 调试修正 + 临时效果
→ 固定增加 → 同属性百分比相加 → 独立倍率相乘
→ 体力/精神衍生 → 上下限 → 攻击面板
```

力量/智力只在伤害主属性修正中使用一次；面板物攻/魔攻作为展示结果，伤害管线使用基础攻击，避免重复乘算。体力/精神分别参与生命/魔法上限和对应防御。速度、暴击、抗性等直接接入模拟。

伤害分为百分比、固定伤害与可配置的无视防御/真伤部分；物理与魔法分别取攻击、主属性、防御和暴击。再计算元素、技能、伤害/承伤、破招/背击修正。随机数来自当前战斗 RNG；未命中、免疫和零伤害允许结果为 0。

当前属性在命中时读取；飞出物携带生成时的招式参数。调整数值不会清动作、重扣MP或重置冷却。角色属性来源与最后一次伤害分项可查询。

怪物使用等级、种类和领主基础值，再应用难度修正；修改怪物等级同时更新当前与后续生成的怪物，保留当前血量比例。

## 四、公开接口与存档

外部仅通过 `game_dnf/stats/api/numbers.gd` 使用静态功能，或 `game_dnf/stats/api/actor_numbers.gd` 使用战斗内临时状态。层级为 core → content → stats → combat。UI不进入战斗内部取数。

| 入口 | 行为 |
|---|---|
| Numbers.profile_stats(profile) | 最终属性和逐属性来源 |
| Numbers.combat_spec(profile) | 战斗属性、计算种子、技能等级、六槽顺序、武器与元素 |
| Session.command("numbers.xp", {amount, transaction}) | 奖励入账、连续升级、满级溢出处理；transaction跨存档去重 |
| Session.command("numbers.skill", {id, delta}) | 花SP升级或按实际购买成本退点 |
| Session.command("numbers.skill_reset") | 清购买记录、退点；保留初始赠送技能 |
| Session.command("numbers.gear_equip", {uid}) | 按实例穿戴；校验等级、成长类型和部位 |
| combat.update_numbers(spec, policy) | 保留或回满当前血蓝，更新进行中战斗 |
| combat.configure_monsters(level, difficulty) | 更新怪物数值 |
| combat.apply_effect({kind:"effect"/"remove_effect", id, target}) | 添加/移除指定实体的效果；不写长期Profile |

任务接入方使用公开经验事务入口，成功后通过外层同步战斗属性/保存；不直接改 level/xp。推荐 transaction 形如 `quest:<稳定任务ID>:<奖励批次>`；改奖励文本不改变已支付标识。

数值字段迁移保留兼容；当前存档与物品所有权以[35](35_物品背包与掉落拾取.md)、[37服务扩展](37_回城交易分解与耐久服务.md)为准，沿用原子写与备份恢复。装备实例持有品质、强化、附魔与耐久；装备部位引用实例ID，背包数量只作兼容视图。

## 七、运行配置与性能约束

数值配置包含全量装备/技能定义，运行代码统一读 `Numbers.shared_config()`，不得修改其返回值或深拷贝整库。需要调整某个字段时只复制目标小字典；存档候选、事务回滚及对外快照继续保持必要的隔离复制。

旧 `Numbers.config()` 已移除。测试或离线调试需要可变整库时显式调用 `Numbers.config_snapshot()`；运行路径调用会被 `tools/check_dnf_performance.py` 拒绝。服务/强化定义同样按会话缓存，读取方不得修改；修改配置文件后重新启动游戏。

技能点选/加退点不得重建整个技能树，必须保留滚动、拖拽源与当前节点；该行为由静态检查与 viewport 交互测试共同约束。性能检查不是一般 GDScript 分析器，新增界面热点需补到 `game_dnf/tests/flow/test_ui_performance.gd`，保留实际内容规模、预热条件、操作耗时预算与只读不变性断言，不能用功能断言通过代替性能验证。

`tools/run_dnf_loop.ps1`、`tools/test_dnf_combat.ps1` 和 `pipeline_dnf.py verify` 均接入静态检查；正式 `-Test` 在其它规则回归前运行检查器反例自测及 headless 界面性能测试。GitHub Actions 对相关 push/PR 自动执行静态检查和反例自测，不声称替代本机 Godot 测试。改动产出与证据见[同类卡顿排查](../reports/ws2/2026-11/2026-11-06_同类卡顿排查与性能防回归.md)。
