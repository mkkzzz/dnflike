# 20 音效任务模板

> 用途：**提一条音效需求 = 填一张本表**，Agent 按 [19 音效生产工作流](19_音效生产工作流.md) 执行。
> 字段与美术模板（[17](17_美术资源任务模板.md)）保持同构，便于同一套协作机制管理。
> 不确定的字段写「待建议」，不要空着——留空会让 Agent 猜，猜错要返工。

## 1. 身份与需求

| 字段 | 填写 |
|---|---|
| `task_id` / `asset_id` | 唯一任务 ID、稳定语义 ID（如 `sfx.monster.goblin.hurt`） |
| `revision` / `replaces` | 本轮版本；替换既有音时写被替换的 kind，新增写「无」 |
| `route` | **A 原创合成** / **B 外部素材加工** / 待建议 |
| `scope` | 本次做什么、不做什么（如「只做受击，不含死亡」） |
| `gameplay_purpose` | 功能用途、触发事件、玩家要读到的信息（挨打了？打中了？暴击？） |
| `owner` / `integration_owner` | 制作工作区 / 接入工作区 |
| `lifecycle` | 规划中 → 源图制作 → 已发布 → 已实装 → 已验收（状态词见 [05](../project/05_版本注册表.md#状态词总表)） |

## 2. 触发与接入点

| 字段 | 填写 |
|---|---|
| 触发时机 | 哪个动作/事件；具体到相位或 tick（如「`attack_event()` 的 `phase == "active"` 首帧」） |
| 接入位置 | 代码位置：`battle_fx.gd` / `monster.gd` / `player.gd` / `main.gd` |
| 与既有音的关系 | **替换** 还是 **叠层**；叠层时写明与哪些 kind 同帧（用于算混音余量） |
| 空间化 | 是否跟随世界坐标（`world_x`）；UI/环境音一般为否 |
| 建议 kind 名 | 如 `goblin_hurt`；不确定写「待建议」 |

## 3. 期望听感（越具体越好）

| 字段 | 填写 |
|---|---|
| 材质 | 金属 / 血肉 / 皮革 / 石材 / 布料 / 嗓音（生物）… |
| 层数倾向 | 单层干脆 / 多层叠加（如「撞击 + 生物叫」） |
| 时长 | 目标秒数或区间（**短音 < 0.5 s 适合连击，长音会与连击叠加**） |
| 音高倾向 | 低沉 / 中性 / 偏高 / 尖细；如走路线 B 请写明**半音数**而非「度」（口径易混，见 19 文档 3.3） |
| 轻重变化 | 是否需要按攻击强度分档（如重击更响） |
| 参照 | 参考作品或现有音效；「像 X 但更 Y」 |
| 变体数 | 默认 3；写明是否需要更多 |

## 4. 路线 B 专用（外部素材）

| 字段 | 填写 |
|---|---|
| 素材类型 | 生物叫声 / 真实录音 / 环境声 |
| 可接受许可 | 默认 **Public domain / CC0**；CC BY 需在此明确同意并指定署名位置 |
| 来源偏好 | Wikimedia Commons（默认）/ 其他（写明） |
| 声音身份 | 物种与性格（哥布林？小怪？BOSS？），是否需要与角色体型匹配 |
| 是否允许多素材混合 | 允许 / 不允许 |

## 5. 交付规格（一般不用改，确认即可）

| 项 | 约定值 |
|---|---|
| 格式 | 48 kHz / 单声道 / 16 bit PCM |
| 峰值 | < 0.76（落地用 0.72） |
| 首尾 | 采样为 0，各 3 ms 渐变 |
| 削波 | 0 |
| 变体 | 3 个（音高一致、音色有区分） |
| 路径 | `game/assets/audio_v3/<kind>_<n>.wav` |
| **`.import`** | **`compress/mode` 必须为 `0`**（为 2 会导致回归失败，见 19 文档 6.1） |
| 出处 | 路线 B 需 `source.json`：来源、许可、作者、SHA256、派生链 |

## 6. 运行时参数（可留空由 Agent 建议）

| 字段 | 填写 |
|---|---|
| 基准 dB | 不填则按同类惯例（撞击 -4.5~-8 / 生物叫 -12 / 脚步 -14~-16.5 / UI -18） |
| 抢占优先级 | 0~4；击打类通常 2~3，移动类 0 |
| 节流 ms | **不得短于该音效自身时长**；不填由 Agent 按此规则定 |
| 强度分档 | 如重击 1.10 / 轻击 0.90 |

## 7. 影响分析

| 依赖 | 变化后本任务的动作 |
|---|---|
| 同帧已有的音效 | 是否触发压音（余量系数降到多少）；需要时提前降基准 dB |
| 既有 kind 被替换 | 是否有其它触发点也在用该 kind（会一起变） |
| 下游 | 回归项、文档、版本注册表是否需要同步 |

## 8. 校验与验收

| 检查 | 必需证据 | 结果 |
|---|---|---|
| 技术 | 格式/峰值/首尾/削波/变体数/`.import` 模式的报告 | 未执行不写通过 |
| 回归 | `tools/run_demo.ps1 -Test` → checks / failures | 待填 |
| 文档 | `python tools/check_docs.py` 通过；出处记录齐全 | 待填 |
| **人工试听** | **必须由人听并确认**（Agent 无法判断音色） | 待填 |
| 混音余量 | 叠层时的峰值和与余量系数 | 待填 |

## 9. 交接与实机验收

| 字段 | 填写 |
|---|---|
| 产出位置 | 入库路径 + 出处记录路径 + 报告路径 |
| 交接 | 交接日志是否已追加一行 |
| 实机验收 | 由谁、在哪一轮试玩中确认；结论回填到状态词 |

## 10. 修改复盘

| 字段 | 填写 |
|---|---|
| 返工原因 | 音色不符 / 时长不当 / 压音过重 / 授权问题 … |
| 流程改进 | 本表哪个字段没写清导致了返工（回填进本模板） |

## 附：示例（已完成的真实需求）

以哥布林受击叫声为例，一张表即可说清：

| 字段 | 值 |
|---|---|
| `asset_id` | `sfx.monster.goblin.hurt` |
| `route` | B 外部素材加工 |
| `scope` | 只做受击；死亡另开 |
| 触发时机 | 命中时，`battle_fx.gd` `on_hit()` 分支之前 |
| 与既有音关系 | **叠层**（在 `light`/`heavy`/`launch`/`metal_hit` 之上，不替换） |
| 预期 kind | `goblin_hurt` |
| 材质 | 生物嗓音 |
| 时长 | 短促（最终 0.34~0.43 s） |
| 音高 | 升 16 个半音（负责人试听选定） |
| 变体 | 3 个 |
| 许可 | Public domain（Wikimedia Commons） |
| 基准 dB / 节流 | -12 / 320 ms |
| 强度分档 | 重击 1.10 / 轻击 0.90 |
| 实测代价 | 三段普攻命中余量系数 1.00 → 0.82 |
