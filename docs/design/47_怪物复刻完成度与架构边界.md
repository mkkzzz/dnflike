# 47 怪物复刻完成度与架构边界

> 结论先行：**当前 16 个副本用的 74 种怪物，原版能给的数据已经 100% 接入运行时**。
> 剩下的“未实装”项（连击、BOSS 技能、召唤、血量阶段）**不是没解出来，而是这些怪在新老架构里根本没有对应文件**。

## 一、两套怪物架构（这是所有困惑的根源）

| | 老架构（**当前副本全在这**） | 新架构 `newmonsters/` |
|---|---|---|
| 实例 | `monster/draconian/mirkius.mob` | `monster/newmonsters/realsky/mirkius/` |
| 定义 | `.mob` 里写全部（数值/动作/攻击/掉落） | `.mob` 只剩壳，拆分到多个文件 |
| 动作 | `[attack motion]` → ANI | `action/*.act`（每动作一文件） |
| AI | **无**（引擎内置简单逻辑） | `ai/*.ai`（可反编译的脚本） |
| 条件行为 | **无** | `action/proc.act`（`[CHECKUP][HP]<=N[%]` → `[BEHAVIOR]`） |
| 召唤 | **无** | `.act` 的 `[SUMMON MONSTER]` |
| 数值 | `[ability category]` 百分比 | 部分依赖 `table/*.tbl` |

实测：**74 种副本怪，目录下有 `proc.act` 的 0 种**；17 个副本 BOSS 有 `.ai` 的 4 个（且是 newmonsters 版，不是副本用的那版）。

## 五、要往前走只有两条路

**路线 A：换血到 newmonsters 版**（能拿到完整 AI、召唤、阶段）

- 做法：把副本 `[monster]` 引用的 mob 换成同名新版（`monster/goblin/goblin.mob` → `monster/newmonsters/goblin/...`）
- 代价：**外观、数值、动作都会变**（那是另一套怪），需要接受“看着像但不是同一只”
- 覆盖率：17 个 BOSS 里只有 4 个有同名新版，其余 13 个原版没有重制版

**路线 B：把老架构还能榨的榨干**

- `.ptl` 全量接入（4327 个粒子）：需要写一个 Godot 粒子渲染器（`.ptl` 参数已全部解析出来），老怪的攻击粒子是**纯轨迹**（无序列帧），只能用 `CPUParticles2D` 还原运动，没有图可播
- 装备分层渲染：只有 28 个老架构 `.act` 有 `[SUB ANI]` 引用，副本怪基本不用

**建议**：A 的收益最大但会改变怪物外观，需要使用者确认；B 的收益有限。若不换血，当前状态就是“老架构的完整复刻”。

## 六、方法论：这轮逆向踩过的坑（供后续参考）

1. **先试 `strings.get(value)`**：`0x05`/`0x07`/`0x09`/`0x0a` 的参数全是 stringtable 索引，解出来就是脚本关键字——这一条让 `.ai`/`.act` 从“不可解析”变成“可读源码”；
2. **“查不到”先怀疑路径**：ANI 在 `DLAni/`、`.atk` 在 `DLAttackInfo/`、装备在 `equipment/monster/`、地图归属是 `[dungeon]=[[11]]` 需要展平；
3. **表要查全**：`monster/` 有 8 张 `.tbl`，漏一张就得出“基准值不存在”；
4. **区分“没数据”和“没解析”**：`.act` 判空是解析器问题，`proc.act` 不存在是真没数据；
5. **同扩展名可能有两套架构**：老 `.mob` 全量定义 vs 新 `.mob` 空壳 + `.act` + `.ai`。
