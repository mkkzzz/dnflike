# 19 音效生产工作流

> 目的：让音效需求**可批量提出、可复现产出、可验收**。单条需求的填写模板见 [20 音效任务模板](20_音效任务模板.md)。
> 现状：**两条生产路线并存**，必须先选路线再动手，否则会在"该不该下载素材"上反复。
> 相关：[10 美术与音频管线](10_美术与音频管线.md)（历史管线记录）、[决策清单](决策清单.md) D023 / D032。

## 一、两条路线（先选路线）

| 路线 | 用于 | 出处要求 | 可复现性 |
|---|---|---|---|
| **A 原创程序合成** | 打击、挥砍、脚步、格挡、UI 等**非生物**音效；以及任何"听感可由物理模型描述"的声音 | 必须原创，**不得**含下载素材 | `tools/bake_combat_audio.py` + 固定种子，**完全可复现** |
| **B 外部素材加工** | **生物叫声**（哥布林、怪物、BOSS）、真实环境声等"需要真实嗓音/录音"的声音 | 必须记录来源 + 许可 + SHA256；**优先公有领域** | 派生链可复现，但源素材不可再生成；哈希入库可校验 |

**选择判据**：

- 声音是"物体相撞/空气流动"的物理结果 → **路线 A**（合成更可控、无版权风险、可复现）
- 声音需要"活物的嗓音" → **路线 B**（合成不出可信的叫声；已验证）
- 拿不准 → 先按 A 试，A 做不到再走 B

**路线 B 的授权红线**：只接受 **Public domain / CC0**；CC BY 需署名，仅在负责人明确同意时使用并登记署名位置；**禁止**来源不明、需购买、或"免费素材站"授权含糊的素材。

## 二、路线 A：原创程序合成

```powershell
python tools/bake_combat_audio.py
```

- 入口：`tools/bake_combat_audio.py`，配方表在 `audio/combat_v3/source_spec.json` 的 `recipes`
- 输出：`game/assets/audio_v3/<kind>_<1..3>.wav`，每类 3 个独立种子变体
- 新增一类音效 = 在生成器里加一个配方 + 在 `recipes` 登记一行说明材质与层次
- 验证：`audio/combat_v3/validation.json` 记录每个 PCM 的时长、峰值、RMS、DC、削波数、哈希

**写配方的要求**：用"材质 + 层次"描述，例如 `light` = `damped flesh body + leather slap + blade edge scrape`。避免"单频滑音"这类无材质感的写法（历史上被否过）。

## 三、路线 B：外部素材加工（关键技术）

这是本工作流的核心技术段。完整实例见 [audio/goblin_hurt/](../../audio/goblin_hurt/README.md) 与 [哥布林受击音效实装报告](../reports/ws3/2026-10/2026-10-15_哥布林受击音效实装.md)。

**已固化为工具**，不必重写脚本：

```powershell
# 1) 预检：识别容器与流数量（不需要 node）
python tools/bake_audio_source.py --inspect --raw raw/a.ogg raw/b.ogg

# 2) 加工：多流解复用 + 解码 + 选段 + 变调 + 归一化，并写出校验报告
python tools/bake_audio_source.py --raw raw/a.ogg raw/b.ogg ^
    --out-dir temp/sfx --kind <kind> --semitones 16 --per-file 3 ^
    --node-dir <装了 stb-vorbis 的目录> --node-exe <node 路径>
```

| 文件 | 作用 |
|---|---|
| `tools/bake_audio_source.py` | 主工具：预检、选段、变调、归一化、写 `validation.json` |
| `tools/bake_audio_source_decode.mjs` | 解码辅助：按 serial 解复用多流 Ogg，用 stb-vorbis 解码为 f32 |
| `tools/bake_goblin_death.py` | **派生变体**：从既有音效做出"更高更长的同源变体"（相位声码器 + 重采样），见 3.5 节 |
| `tools/bake_goblin_death_scream.py` | **原创合成人声嘶吼**：「啊~~」共振峰 + 抖动 + 过载，见 3.6 节 |
| `tools/bake_skill_impacts.py` | **技能命中声**：每个技能一记自己的"打中"，见 3.7 节 |
| `tools/bake_sword_swings.py` | **真实录音招式音**：CC0 挥剑录音加工成九个招式音，见 3.8 节 |
| `tools/bake_effort_voices.py` | **出招人声**：CC0 男声切片做成四档起手"用力"，见 3.8 节 |

**注意**：node 的 `import` 按**脚本所在目录**向上解析模块，而 `stb-vorbis` 通常装在仓库外，所以必须用 `--node-dir` 告知（工具已用环境变量与第 3 参数把该目录传给辅助脚本）。若 `node` 不在 PATH，用 `--node-exe` 指定。

### 3.1 取素材

选站优先级：**Wikimedia Commons**（授权干净、API 可查、无需登录）> 其他公有领域库。
Commons 用法：

```
搜索：https://commons.wikimedia.org/w/api.php?action=query&format=json&list=search
      &srnamespace=6&srlimit=8&srsearch=<关键词> filetype:audio
元数据（直链/许可/作者）：同上 + &prop=imageinfo&iiprop=url|size|mime|extmetadata
```

- `srnamespace=6` 限定 File 命名空间；`filetype:audio` 过滤音频
- 许可看 `extmetadata.LicenseShortName`，作者看 `extmetadata.Artist`
- **注意限流**：`upload.wikimedia.org` 下载会返回 **HTTP 429**，需退避重试（实测连续重试仍可能全失败，分批次隔开时间更有效）

### 3.2 解码（最容易卡住的一步）

**坑 1：Commons 的 Ogg 常是「多流 Ogg」。**
文件同时含 **Ogg Skeleton**（`fishead`/`fisbone`/`index`）与 **Vorbis** 两条复用流（两个不同 `serial`）。

- `stb_vorbis` / `stb-vorbis` **不支持多流**，直接解码报 `Failed to decode Ogg Vorbis stream`
- 验证方法：读前 200 字节，若看到 `fishead` 且有多个不同 `serial`，就是多流
- **解法：按 serial 解复用**——只挑出 Vorbis 流的页（识别法：首页 payload 以 `\x01vorbis` 开头），拼接成单流后再解码

**坑 2：本机没有 ffmpeg，Python 只有 numpy。**
因此需要纯 JS/WASM 解码链：

| 依赖 | 用途 | 授权 |
|---|---|---|
| `stb-vorbis` | 同步解码 Ogg Vorbis 为 Float32（127 KB，零依赖，**无原生编译**，WASM 内联 base64） | Apache-2.0 |

- 安装到**仓库外**目录（如 `D:/dnflike_local/audio_src/`），不要把 node_modules 放进仓库
- 调用：`await StbVorbis.ready; const audio = StbVorbis.decode(new Uint8Array(buf));` → `audio.sampleRate` / `audio.channels[]`
- **若目标环境有 ffmpeg**，`ffmpeg -i in.ogg -ac 1 -ar 48000 -c:a pcm_s16le out.wav` 一步到位，本文的解复用/解码部分可整体跳过

### 3.3 加工成工程规范

**工具的默认行为就是按下面顺序做**（`tools/bake_audio_source.py`），列在此处便于核对与排障：

1. **选段**：用 20 ms 窗 RMS 找有声段；**按"平顶长度"（高于峰值 70% 的窗数）排序**，不要只按时长——只按时长容易选到长尾静音。要求平顶足够长，避免从发声中间切断
2. 首尾留余量：前 8 ms、后 45 ms
3. **重采样到 48000 Hz**（线性插值即可）
4. **变调（可选）**：用重采样比例实现，**升调必缩时**（升 1 个八度时长减半）。需要"又高又不短"才用相位声码器，但短促叫声不值得（金属伪影）
5. 去直流
6. **归一化到峰值 0.72**（工程上限 0.76，留余量）
7. 首尾各 **3 ms 渐变**
8. 输出 **48 kHz / 单声道 / 16 bit PCM**

**音高换算（避免口径误解）**：「8 度」在中文通常指 **8 个半音**（×1.588），不是 8 个八度（×256，会变超声静音）。实测参考：源质心 760 Hz 时，+8 半音→1176 Hz、+12→1455 Hz、+24→2693 Hz（像小生物）、+36→4990 Hz（尖细）。

### 3.4 变体

每类产出 **3 个变体**（与合成音一致），供运行时随机选择：

- 变体间**音高一致、音色有区分**（取不同源段或不同处理）
- 意义：避免连续命中时同一声音机械重复

### 3.8 招式音改用真实录音（合成做不出来的"手感"）

**结论先说**：挥剑/挥砍这类音，**合成不如真实录音**。程序合成的 whoosh 只有
噪声包络，缺少真实空气摩擦的细节与非平稳性，实机上就是"不像游戏里的挥剑"。

#### 用了什么（都是 CC0，可商用）

| 包 | 作者 | 素材 | 用途 |
|---|---|---|---|
| [Swishes Sound Pack](https://opengameart.org/content/swishes-sound-pack) | artisticdude | 13 段真实挥动 WAV，44.1 kHz 立体声 | 普通挥砍（质心 1.4~2.3 kHz，暖气流） |
| [20 Sword Sound Effects](https://opengameart.org/content/20-sword-sound-effects-attacks-and-clashes) | StarNinjas | 10 段剑击 Ogg | 技能/重击（源质心 12~14 kHz，需压高频） |
| [Male Grunt/Yelling sounds](https://opengameart.org/content/male-gruntyelling-sounds) | HaelDB | 62 段男声嘶吼/发力 WAV | 出招人声四档（0.22/0.34/0.44/0.58 s） |

来源、许可、加工参数都登记在 `audio/sword_swing/` 与 `audio/effort_voice/`
（各有 `README.md` + `source.json` + `validation.json`）。

#### 金属剑击的"太刺"怎么修

StarNinjas 那包是刀对刀的真实录音，源质心 **12~14 kHz**，直接用会像刮玻璃。
修法（按效果排序，实测）：

1. **降高频**：低通 **级联四次 5 kHz**（一阶只有 6 dB/oct，两级/三级都压不下来；
   实测四级才从 ~9.9 kHz 降到 5~7 kHz）
2. **降调加长**：变速比 0.82~0.95（既更长也更沉），时长上限同步放宽到 0.28~0.34 s
3. 补 RMS：金属类峰值归一化后 RMS 只有 0.04~0.11（暖气流 0.14~0.16），
   需要靠 `SOUND_SPECS` 的 dB 补回来

#### 加工链（`tools/bake_sword_swings.py`）

1. **按有声段裁剪**：1% 峰值门限，前后留 6 ms（门限取 2% 会削掉尾部气流，听感变"咔"）
2. 重采样到 48 kHz 单声道
3. **变速当音色工具**：突刺/空斩 1.12~1.25（升调变短），重招 0.88~0.92（降调变长）
4. StarNinjas 那包**先过 11 kHz 二级低通**（源质心 12~14 kHz，直接用会刺）
5. 归一化峰值 0.72、首尾 3 ms 淡出、首尾采样 0

#### 三条硬教训

- **变体必须同包**：第一版让"同一个招式的三个变体"分别来自暖气流包和金属包，
  结果同一招三下声音一个暖一个尖，玩家会以为在放不同技能。变体差异应该是
  **同源微调**，不是换素材
- **金属类录音的 RMS 天生低**：峰值归一化后，短促金属瞬态 + 长尾的 RMS 只有 0.05~0.11
  （暖气流 0.14~0.16）。要么缩短尾巴，要么在 `SOUND_SPECS` 里补 dB，否则实测偏轻
- **合成人声也不行**：试过用共振峰合成"用力"的人声（0.11~0.30 s 四档），
  负责人实机反馈依然不像。人声这类音同样必须走真实录音
  （最终用 CC0《Male Grunt/Yelling sounds》，按"有声段长度"自动分四档 +
  每档硬时长上限，见 `tools/bake_effort_voices.py`）
- **起手声要有硬时长上限**：素材里混着整句长啸，直接用会盖住招式音。
  起手只需 0.2~0.6 s，按档设上限并补收尾

#### 判断该用哪条路线（与 3.6 互补）

| 音的类型 | 建议路线 |
|---|---|
| 挥砍、脚步、金属撞击、人声 | **真实录音（路线 B）** —— 有大量 CC0 素材，合成难达"手感" |
| 破坏、尘土、能量、UI | 合成（路线 A）—— 现实中不存在"正确录音"，合成可控 |

## 四、必过的交付检查（每类音效都要做）

| 检查 | 判据 | 不通过的后果 |
|---|---|---|
| 格式 | 48 kHz / 单声道 / 16 bit PCM | 与工程不一致 |
| 峰值 | **< 0.76**（落地用 0.72） | 混音削波 |
| 首尾采样 | 为 0 | 爆音 |
| 削波样本数 | **0** | 失真 |
| 变体数 | 3 个 | 重复感 |
| **`.import` 的 `compress/mode`** | **必须为 `0`** | **回归项 `offline foley variants contain valid sixteen-bit PCM` 直接失败**；见第 6.1 节 |
| 出处 | 路线 B 必须有 `source.json`（来源/许可/SHA256） | 违反出处声明 |
| 运行时登记 | 已加进 `CombatAudio.SOUND_SPECS` 与 `ALIASES` | 无声或无法触发 |

## 五、运行时接入约定

`game/scripts/combat_audio.gd`：

- **`SOUND_SPECS`**：`"<kind>": [基准dB, 抢占优先级, 节流ms]`
  - 基准 dB 参考：撞击 `-4.5 ~ -8`、生物叫声 `-12`、脚步 `-14 ~ -16.5`、UI `-18`
  - 节流取值的判据：**不能短于该音效自身时长**，否则连击时会叠成一片（哥布林叫声 0.34~0.43 s 用 320 ms；撞击类短音用 40~65 ms）
- **`ALIASES`**：把语义名映射到实际 kind（如 `monster_hurt` → `goblin_hurt`）
- **资源路径**：`res://assets/audio_v3/%s_%d.wav`（缺文件会在启动时报 `Missing baked combat foley`）
- **混音余量**：0.86 硬预算；所有活跃声道峰值和超出时**整体等比例降增益**。加新层前先估算：

```
峰值和 ≈ Σ(0.76 × 10^(基准dB/20))
余量系数 = min(1, 0.86 / 峰值和)
```

**同帧多层的常见组合**（用于判断是否会压音）：挥砍 + 命中撞击 + 生物叫声。实测：轻击 0.57（不影响）、上挑 0.93（压 8%）、三段普攻命中 1.05（压 18%）。

**触发位置**：`battle_fx.gd`
- 主角出招音 → `attack_event()` 的 `phase == "active"`；V6 招式另有 `seq_swing_sound()`
- 命中音 → `on_hit()`。**注意 `on_hit()` 有两条分支**（V6 走 `if authored:` 提前 `return`；旧动作继续走），要覆盖全部招式必须放在**分支之前**（`_impact_sound()` 就是这么放的）

## 六、两个已知坑（务必先读）

### 6.1 新音频会被导成 ADPCM，导致回归失败

Godot 对**新增** WAV 可能按 `compress/mode=2`（IMA-ADPCM）导入，使 `stream.format != FORMAT_16_BITS`，回归项 `offline foley variants contain valid sixteen-bit PCM` 失败。

- 现象：`.godot/imported/<name>.wav-*.sample` 体积只有 WAV 的 **约 0.21 倍**（正常应为 **1.01 倍**）
- 处理：把该 `.import` 的 `compress/mode` 改为 `0`，再跑一次 `--editor --quit` 重新导入
- `.import` 是**入库文件**，修好即对其它 clone 生效

### 6.2 变调会改变时长

用重采样变调 = 升调同时缩短。若需求同时要求"更高"和"不更短"，必须提前说明，改用相位声码器（有伪影）。

## 七、验收流程

1. 产出后先跑 **`tools/run_demo.ps1 -Test`**（回归 271 项，含音频格式校验）
2. 跑 **`python tools/check_docs.py`**（若改了文档）
3. 跑过引擎后确认 **`git status` 为空**（`.gitattributes` 已消除 `.import` 假脏）
4. **人工试听**：Agent 无法判断音色好坏，必须由人听。给出可直接播放的文件路径
5. 涉及**新层叠入**时，报出混音余量估算（第 5 节公式），并说明压音代价
6. 路线 B 必须在报告里写明：来源、许可、派生链、未采用候选及原因

## 八、需求的"量产"方式

提出新音效需求时，**照 [20 音效任务模板](20_音效任务模板.md) 填一张表**即可，Agent 按此文执行。能一次说清的关键字段：

- **触发时机**（哪个动作/事件、哪个 tick 或相位）
- **期望听感**（材质、轻重、长短、音高倾向；可给参照作品）
- **路线倾向**（合成 / 外部素材；不确定可留空由 Agent 建议）
- **是否替换既有音**（换掉哪个 kind，还是叠层）

**一次一批的写法**：同一事件的多层（挥砍/命中/惨叫）放同一张表，便于统一混音余量。
