# DNF 原版拆解：证据与版本

> 上级入口：[还原路线](26_DNF原版拆解与还原路线.md)。本页定义设计事实的来源，不增加Git审批流程。

## 一、证据分类与结论边界

| 标记 | 含义 | 可以证明 | 不能证明 |
|---|---|---|---|
| E-FILE | 原始文件与哈希 | 某版本存在这些字节、路径和字段 | 文件被实际加载或字段生效 |
| E-PARSE | 可复现结构解析 | 字段序列、数值、索引、时序与引用 | 字段单位、公式、优先级和全部语义 |
| E-RUN | 对应版本的实机实验 | 给定条件下观测到的行为与误差范围 | 所有等级/装备/模式均相同 |
| E-CODE | 当前Godot实现 | 现版如何计算和显示 | 原版也这样实现 |
| E-INFER | 有依据的推断 | 待检验的解释与预测 | 原版事实 |
| E-ADAPT | 明确的项目适配 | 当前替代规则与代价 | 原版规则 |
| E-UNKNOWN | 未知或证据冲突 | 需要补什么证据 | 不得填默认答案掩盖缺失 |

上述是证据分类，不替代[项目状态词](../project/05_版本注册表.md#状态词总表)。
同一规则可同时有多种证据；运行结果与文件解释冲突时保留两者并登记适用条件。

## 二、参照版本锁定清单

| 身份 | 必填信息 | 当前问题 |
|---|---|---|
| 客户端 | 用户实际启动入口、可执行文件哈希、显示设置 | 尚未记录一次可复现的原版启动与录像 |
| 配置 | 实际加载PVF的路径角色、哈希、加载证据 | 根目录、ImagePacks2与相邻备份不同；有效者未知 |
| 资源 | 资源包哈希、重复路径候选、补丁覆盖顺序 | 当前采用常规sprite包优先，未证明是客户端优先级 |
| 服务端 | 实际连接对象、版本、配套脚本/数据库身份 | DNF1031虚拟机存在，但配套关系未知 |
| 角色条件 | 职业、等级、技能等级、武器、衣装、装备、属性、Buff | 当前样板使用固定试验参数，不等同原版角色 |
| 测试环境 | 地图/难度/怪物、分辨率/显示缩放、帧率、录制时间基准 | 必须与对照媒体同时记录 |

### 2.1 已复算的静态身份（ws3，2026-10-27，E-FILE）

客户端内 `Script.pvf` 有三份、相邻另有一份备份，四份互不相同；哈希均在本机资源库的副本上复算过：

| 角色 | 字节数 | SHA256 | 文件头 |
|---|---|---|---|
| 客户端根目录 `Script.pvf` | 183,230,422 | `3c0e8050…bcea4` | 版本 `0xBF58`（48984） |
| `ImagePacks2/Script.pvf` | 202,396,005 | `3893d5d1…1fe01` | 36 字节 GUID 前缀 + 版本 |
| `Video/Script.pvf` | 182,490,884 | `cfea184b…99542` | 同根目录格式 |
| 相邻 `111Script.pvf` 备份 | 202,404,709 | `f4885045…79be0` | 同 ImagePacks2 的 GUID 前缀 |

当前资源库的 `pvf_config.sqlite` 由 **111 备份**建立（`config_summary.json` 记录，336,082 个文件，`pvf_version` 48984）。

**仍未锁定**：客户端实际加载哪一份、补丁覆盖顺序、服务端配套。本机没有客户端，加载证据需在有客户端的机器上用文件访问监控取证；步骤与完整哈希见[四份 PVF 静态凭证](../reports/ws3/2026-10/2026-10-27_DNF来源锁定_四份PVF静态凭证.md)。

先用用户指定的启动方式观察，再用加载日志、文件访问证据或可控实验确定配置；不能仅凭文件名判定。
不启动或挂载相邻服务端来猜配套关系，不更改原文件验证猜测。
原版若连接远端服务器，本地缺少的公式与表格继续标未知。

## 三、来源分层

- 主参照：实际可玩的“情怀60复古”及已证实与其配套的配置与服务端。
- 备份参照：当前共享库的111Script.pvf；只证明该备份内容，不自动升级为主参照。
- 其它版本：DNF1031、现代官网、论坛攻略等；用于提出实验问题，不能替换主参照数值。
- 当前实现：新版代码与配置，用来定位差异和建立回归基线。

本机绝对安装路径、运行录像与大体积提取表放本地证据目录；共用规则使用来源角色+哈希+相对内部路径。
保持资源库既有权限与发布方式；不把服务端磁盘、凭据或个人存档塞进源码库。

## 四、一条规则必须记录什么

| 字段 | 要求 |
|---|---|
| rule_id / revision | 稳定标识与修订，不用中文显示名称当主键 |
| module / scope | 所属系统、版本、PVE/PVP、职业/等级/装备等适用条件 |
| claim | 可被实验推翻的一句具体行为描述 |
| evidence_class / evidence_ids | 证据分类与关联证据ID |
| source | 来源角色、SHA256、内部路径、记录偏移或帧号 |
| raw / decoded | 原始字段值与结构解释分别保存；重复标签和嵌套顺序不丢失 |
| semantics / unit | 含义、单位、坐标轴、取整与边界；未知写unknown |
| preconditions / transitions | 前置状态、输入、事件、结果、打断与失败路径 |
| dependencies | ID映射、引用资产、嵌套行为、其它规则 |
| observation | 原版测量方式、重复次数、实际结果与误差 |
| implementation / diff_ids | Godot配置/函数位置、适配与差异ID |
| acceptance | 对照操作、容差依据、反例和人工验收范围 |

示例：rule.player.combo3.active_frames，范围先写“备份PVF的指定ANI”，可记录原文件的帧与盒体。
在没有实机与依赖链证据时，不把它改写为“情怀60复古三刀实际命中公式已还原”。

## 五、解析必须保留的内容

1. 字节哈希、原始路径大小写与规范化路径；重复路径保留所有候选及选择依据。
2. 原始token类型、偏移、值和未识别内容；本地化9/10类间接引用不可猜成普通字符串。
3. 原始六维判定盒；坐标与尺寸解释需单独验证，不能先压成reach/depth再宣称无损。
4. 原始帧时长、等待帧、循环和全局标记；不把等待帧自动改为普通播放时长。
5. 未支持字段、CRC异常、缺引用、越界和动态路径模板，必须进入明确的诊断结果。
6. SKL中副本/PVP等上下文与重复标签；不能只取最后出现的一组cool time。

“解析成功”只表示结构读取完成；“引用匹配”只表示存在候选；两者都不等同于可正确执行。
全库缺引用统计涉及未启用内容、版本差异与模板，不能直接当作有效内容损坏率。

## 六、可复现审计入口

先按[共享说明](23_DNF资源共享与工作区接入.md)取得完整库，然后在仓库根运行：

```powershell
python tools/audit_dnf_design.py
python tools/test_dnf_design_audit.py
```

若本机有原客户端，可额外传 --client 加本机实际客户端目录，收集三个PVF位置的指纹。
该参数只读取指纹，不执行客户端，也不确定运行时加载关系。
默认输出为temp中的dnf_design_audit/audit.json；每区可重跑，生成物不进入源码Git。
工具只读SQLite与原文件，只做结构解析，不是原版行为解释器。
首轮检查的实际范围、结果和哈希见[审计记录](../reports/ws2/2026-10/2026-10-22_DNF原版拆解首轮审计.md)。
