# 44 内容接入工作流

> 目的：把"原版数据 → 可跑运行时"的批量工作固化成流水线，避免每次靠记忆串工具、靠试错补漏。
> 一句话入口：`python tools/pipeline_dnf.py <dungeon|monsters|verify>`。

## 一、为什么需要流水线

接入一条内容要按依赖顺序过 6~8 个工具，顺序错了不会报错，只会**静默失败**，例如：

| 错序 | 现象 | 真实原因 |
|---|---|---|
| 先烘图集、后编内容包 | 图集有了但副本里没怪 | `move_table._build_monster` 从内容包读 `.mob`，查不到就返回空 |
| 先同步映射、后烘图集 | 战斗场景初始化直接崩 | `battle_view` 用 `bank["atlas"]`，映射指向不存在的图集 |
| 只导出地图、不重编内容包 | 新副本的怪不出现 | 内容包按 `dungeons.json` 的引用范围编译 |
| 只补 `dungeons.json`、不跑 BGM | 副本无声 | `check_dnf_bgm.py` 会拦住，但要在提交前跑 |

所以顺序与幂等必须由工具保证，不能靠人记。

## 二、三条流水线

### 1. 接入一个新副本

```bash
python tools/pipeline_dnf.py dungeon dungeon/act1/grakkarak.dgn --id grakkarak --name 格拉卡 --region granfloris --level 10
```

内部顺序（**不能调换**）：

1. `export_dnf_map.py` —— `.dgn` → `map_export.json` + 原生像素图；
2. `build_dnf_dungeon_route.py --write` —— 按 cell 图 BFS 出主线，写 `dungeons.json`；
3. `build_dnf_monster_catalog.py` —— `.mob` 总账（属性/动作表/攻击判定）；
4. `compile_dnf_content.py` —— **按 `dungeons.json` 的引用范围**编内容包（mob/ani/atk/ptl）；
5. `build_dnf_combat_assets.py` —— 逐怪烘动作图集（`motion_map`）+ 特效 bank；
6. `sync_dnf_monster_mapping.py` —— mob → kind → bank 写 `combat.json`；
7. `bake_dnf_bgm.py` —— 补副本 normal/boss 曲；
8. `verify` —— 四道检查。

### 2. 怪物侧变更（副本引用变化、或改了 `.mob` 解析）

```bash
python tools/pipeline_dnf.py monsters
```

顺序：总账 → 内容包 → 图集 → 映射 → 检查。只跑怪物链路，不碰地图。

### 3. 提交前校验

```bash
python tools/pipeline_dnf.py verify
```

四道闸门，任一失败非零退出：

| 检查 | 拦什么 |
|---|---|
| `check_dnf_dungeons.py` | 副本路线、门方向、房间数据、入口覆盖、前置任务、等级范围 |
| `check_dnf_bgm.py` | 新增城镇/副本没配 BGM |
| `check_dnf_walk.py` | 走区脚点不在地面美术上、并集不连通、门触发带不可达 |
| `check_dnf_quests.py` | 已实装任务与总账不一致、epic 进度回退 |

## 三、新增其它内容的固定动作

| 内容 | 必须同时做的 |
|---|---|
| 新城镇 / 房间 | `towns.json` 加 location + 双向 portal → `apply_dnf_town_rooms.py`（若是 `rooms/` 导出）→ `bake_dnf_bgm.py` 加 TOWNS 一行 → `check_dnf_walk.py` |
| 新 NPC | `build_dnf_town_npcs.py` 重跑（自动从地图 animation 识别）→ `bake_dnf_npc_voices.py`（立绘与语音，key 从 `audio.xml` 查）→ `towns.json` 补站位与 NPC 定义 |
| 新任务 | `data/quests.json` 加条目（带 `source.path/sha256`）→ `check_dnf_quests.py` 确认未回退 |
| 新物品 | `build_dnf_item_catalog.py`（结构/图标引用）→ 名称待中文源 |
| 新技能 | `build_dnf_skill_panel.py` 重跑 → 面板自动出现，未实装的标灰 |

## 四、已知的静默失败点（流水线已覆盖，手改时要自觉）

1. **内容包范围**：`compile_dnf_content.py` 只编"哥布林家族 + 副本实际引用"的 mob。手工往 `combat.json` 加映射而不重编内容包，怪会构建失败。
2. **pose 名**：运行时播 `stay/move/attack/damage1/damage2/down/overturn/sit`。旧 clip 目录约定叫 `attack1`，烘焙器已做别名；新增动作时不要自创名字。
3. **图集缺帧**：`monster_bank` 遇到没有动作表的怪会返回空 bank，`battle_view` 会崩。`sync_dnf_monster_mapping.py` 已跳过无 `motions` 的 mob。
4. **空数组**：`.mob` 的 `waiting_motion` / `attack_infos` 可能为空，`move_table` 已容错；新增字段解析时保持同样防御。

## 五、耗时参考（本机）

| 步骤 | 单副本 | 说明 |
|---|---|---|
| 地图导出 | 2–10 分钟 | 瓶颈在解码 tile/背景 PNG，大副本（grakkarak）更久 |
| 内容包编译 | 1–2 分钟 | 1418 条记录、4.1 MB |
| 战斗资源重建 | 2–4 分钟 | 74 种怪 × 8 动作 |
| 其余 | 秒级 | — |

所以批量接入时，导出可以并行（`ThreadPoolExecutor`），编译/构建必须串行。
