# 单机 60 级一致基线

> 上级入口：[原版拆解与还原路线](26_DNF原版拆解与还原路线.md)。
> 机器产物与当前快照见[60 级单机一致基线报告](../reports/ws1/2026-11/2026-11-02_60级单机一致基线.md)。
> 本页定义长期范围、完成状态和推进顺序，不重复易变统计。

## 当前执行目标

用户于2026-11-06明确要求持续推进全游戏近乎一致的原版复刻，范围包含技能、战斗、UI、系统、任务、副本和城镇。不能将任何单模块修完作为总体收尾。原目录为用户指定的D盘“纯60复古”；代码、配置与资源引用是主要依据，录像只作可选交叉验证，不作为工作的前提。

游戏表现统一以该客户端的成人版为准。遇到原版按年龄区分的动画、特效或界面，直接采用成人版分支，运行时只保留这一套表现。

现有离线单机工程继续作为实现载体；原版外围功能也保留在全系统目录中，既有范围取舍不算已还原。不得因暂未实现、需要原生代码分析或服务端规则未知而从完成度分母中悄悄删除。实际生效版本、开放职业和功能仍需取证，资料包含某内容并不等于目标版本开放它。

持续执行以[全系统目录](26_DNF原版拆解_全系统目录.md)的SYS-00～18为范围，以原始依据、解析支持、运行功能、表现一致性、用户验收分别记录。当前所有自动化通过均不能提升到accepted；用户已否定的技能整体表现保持返修状态。

| 推进批次 | 工作重点 | 可交付依据 |
|---|---|---|
| 当前基础 | 排除正式验证入口的误报，核现有事务/存档/流程基线，关闭已完成接收项 | 可复跑的正式全流程；保留真实数据损坏/变化的拒绝检查 |
| 战斗与技能 | 输入状态、动作时钟、武器层、特效组合、ATK、伤害列和异常效果 | 原代码/配置消费链与针对性行为反例；不再以通用模板补齐目录 |
| 任务与城镇 | 前置/目标/奖励/生命周期、NPC交互、服务和区域连通 | 原QST/NPC/TWN/RGN引用与候选事务、存读档闭环 |
| 副本与怪物 | 原DGN拓扑、MAP锚点/层序、刷怪、ACT/AI和领主机制 | 同源依赖闭合、状态分支与原始坐标，适配项单列 |
| UI与表现 | 所有正式屏幕的资源/帧/控件状态、字体、输入、遮挡和声音时序 | UI字段与资源引用、后台实际渲染和交互验证 |
| 系统与内容扩展 | 成长、物品、装备、经济、恢复、各职业及等级段 | 原始字段和本地权威规则；逐段可玩，不用数量代替一致性 |

每批修复先保留失败证据，再更新实现、相关回归与差异记录并发布；总体目标持续有效。首批接续见[全游戏目标与验证入口修复](../reports/ws2/2026-11/2026-11-06_全游戏还原目标与任务验证入口修复.md)。

## 一、目标范围

目标是**离线单机、60 级 PVE 内容与表现一致**。

不做更新器、热更新、联网服务端、登录/频道、组队、玩家交易、邮件、公会、拍卖和 PVP。

当前完成度按 60 级内容对账；60 级以上内容继续保留在源库与运行库，作为后续拓展层，不删除、不要求隐藏，也不计入当前 60 内容分母。

“不做服务端”只表示不运行网络服务和协议，不表示可以继续使用项目自创结算。原服务端负责的结果必须由本地权威逻辑执行，包括：

- 等级经验、升级、SP 和成长曲线。
- 怪物/副本/任务的金币、经验、掉落和翻牌。
- 商店库存、价格、回购、修理、耐久、强化、附魔和分解。
- 疲劳、入场限制、冷却、每日/重复刷新和物品限制。
- 任务前置、职业条件、奖励、消费与一次性事务。
- 随机种子、防止重复领取、失败回滚和存档一致性。

只固定一次目标内容基线，不维护更新链。

## 二、完成状态

每项内容必须沿以下状态推进，不能跨层填入完成：

| 状态 | 含义 |
|---|---|
| `target` | 已确认属于目标 60 级内容 |
| `parsed` | 原文件结构、ID、依赖可解析 |
| `available` | 所需图像、动画、音频、数据和代码依赖齐全 |
| `runtime` | 可从正式游戏入口执行 |
| `accepted` | 已做原版同条件对照并由使用者验收 |

`runtime` 只表示能运行，不表示数值、动作、AI、UI 或操作手感已经一致。

内容存在但等级、开放职业、活动属性无法确认时保持 `unknown`，不静默进入目标分母。

## 三、三份核心基线

| 产物 | 用途 |
|---|---|
| `game_dnf/data/target_60_manifest.json` | 目标候选、来源、依赖和逐类状态 |
| `game_dnf/data/local_rules_spec.json` | 原服务端逻辑的本地化清单、当前实现和阻塞项 |
| `game_dnf/data/target_60_parity.json` | 按内容类别和规则状态聚合的对账矩阵 |

生成入口：

```powershell
python tools/build_dnf_60_baseline.py --write
python tools/build_dnf_60_baseline.py --check
python -m unittest tools.test_build_dnf_60_baseline -v
```

工具只读现有资源库与仓库数据。生成物不包含原文件大字节，不修改已发布资源包。

## 四、本地权威层

从原客户端可直接读取的规则优先编译为数据；原客户端文件不足但可由可复核行为确定的规则，写成带证据的本地规则；两者都无法确定时才保留 `E-ADAPT`。

本地权威层必须满足：

1. 所有奖励、消费和状态变化走同一候选快照。
2. 成功写盘后才替换活动角色和世界状态。
3. 随机结果由可保存种子驱动，重开不重掷。
4. 时间、暂停、切房、死亡和退出在同一事务模型中处理。
5. 同一规则只有一个执行入口，战斗、UI、任务和工具不各写一份公式。

## 五、推进顺序

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| B0 基线 | 目标来源、职业范围、内容候选和规则阻塞清单 | 决策项冻结，目标分母可复跑 |
| B1 通用能力 | 内容读取、职业/技能、战斗、AI、物品、任务、经济、存档 | 新内容只需接数据，不再写专用分支 |
| B2 鬼剑士样板 | 鬼剑士→剑魂，覆盖 1～18、19～35、36～50、51～60 | 不用 GM，从建角到 60 级完整可玩 |
| B3 同职业扩展 | 鬼泣、狂战士、阿修罗 | 四条转职线共用已完成的 1～60 世界内容 |
| B4 全职业 | 目标版本开放的全部基础职业与转职 | 职业、技能、装备限制和任务分母闭合 |
| B5 收口 | 时装、套装、配方、宠物、称号、特殊副本和表现 | 全部目标内容达到 `accepted` |

第一条样板选剑魂，因为当前运行基础和技能树最深，最容易暴露通用能力缺口。

## 六、等级段批次

每个等级段都按同一顺序交付，不能先把地图或数据全部迁完，再回头补规则：

1. 冻结该段任务、副本、怪物、技能、装备和商店清单。
2. 编译依赖闭包，未知字段进入诊断。
3. 补技能、AI、地图、任务和经济执行能力。
4. 接正式 UI、音效、动作与结算。
5. 从上一等级真实存档继续玩到下一等级。
6. 做原版/Godot 同条件对照并登记验收。

建议分段：

- `1～18`：建角、基础战斗、第一段主线、正式转职。
- `19～35`：中段地区、任务链、装备和怪物机制。
- `36～50`：高阶技能、套装、特殊副本与中后期主线。
- `51～60`：终盘副本、BOSS、毕业装备与完整评价结算。

## 七、每批内容模板

| 步骤 | 必须产物 |
|---|---|
| 领取内容 | 目标 ID、原路径、SHA256、适用版本 |
| 依赖闭包 | 地图/动作/ATK/SKL/AI/音效/文本/物品引用 |
| 编译 | 标准运行数据与未支持字段诊断 |
| 执行 | 战斗、流程、物品、任务和经济入口 |
| 表现 | UI、动作、特效、声音和镜头 |
| 验证 | 自动化、真实输入、存读档、失败路径 |
| 验收 | 原版同条件证据、差异说明、用户结论 |

没有原版对照的内容最高只能填 `runtime`。

## 八、待决策闸门

以下事项会改变目标分母，冻结前必须由使用者确认：

1. 以哪份固定文件作为目标来源。
2. 目标版本开放哪些基础职业和特殊 CHR。
3. 原版仅支持组队的任务/副本是排除还是改写为单机等价。
4. 60 级以上后续扩展内容的版本批次和验收顺序。
5. 等级未知物品如何根据任务、商店和版本依赖分类。

技术实现仍需继续推进，但未决策项不能提前写成目标事实。

## 九、完成判据

“完全一致”至少同时满足：

- 目标白名单中的职业、技能、任务、副本、怪物、物品和 NPC 全部依赖闭合。
- 1～60 级无需 GM、无需修改存档即可连续游玩。
- 原服务端逻辑均有本地确定实现，且失败路径不重复发奖或回滚一半。
- UI、动作、判定、音效、结算和错误提示完成同条件对照。
- 所有目标内容在 `parity` 中达到 `accepted`。

只要仍有内容停留在 `unknown`，或核心规则仍为 `E-ADAPT`，就不能声称完全一致。
