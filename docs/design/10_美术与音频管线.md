## 角色帧条接入（AI 帧图 → 实机）

链路：**AI 整张动作帧图 → `tools/bake_ai_frames.py` → `game/art/{player,monster}/<action>.png` + `anim.json` → Godot 零改动**

`bake_ai_frames.py` 不重复实现算法，全部复用 `tools/make_anim.py` 已在 CLI 里验证过的
绿幕抠图 / 连通域切帧 / 脚底锚点，只补三件事：**多动作**、**归一化到实机尺寸**、**写 anim.json**。

```powershell
python tools/bake_ai_frames.py --list     # 看规格要求哪些帧图、哪些还没出
python tools/bake_ai_frames.py            # 烘焙所有已存在的帧图
python tools/bake_ai_frames.py --only idle,attack1
```

出图规格在 `tools/ai_anim_spec.json`（含 `how_to`：绿幕、网格、朝向、禁止画刀光/UI）。
帧图放 `art/sheets/<group>/<action>.png`。

### 管线自检

改过 `make_anim.py` / `bake_ai_frames.py` 之后跑一次：

```powershell
python tools/test_anim_pipeline.py
```

不需要任何真实美术——它自己造一张合成 2x3 绿幕帧图（6 个不同姿势 + 一根**极细的剑身**，
用来检验腐蚀后靠测地线生长把剑身归属回本体），然后断言：
切满 6 帧、无空帧、**无帧贴到画布边缘（裁切）**、脚底锚点在画布内。

> 它抓到过一个隐蔽 bug：画布高度只算了脚底**以上**，导致**指向下方的刀尖被整段裁掉**。
> 该守卫已用**注入法**验证过确实会失败（而不是加了个永远不会失败的检查）。
> `bake_ai_frames.py` 里另有一道同类自检，每次烘焙都会报出贴边帧。

### 出图硬要求（踩过的坑）

| 要求 | 原因 |
|---|---|
| 纯绿幕背景，不要影子/地面/渐变 | 灰底立绘的地面投影会被当成前景留下（见 `art/characters/goblin.png` 的实测） |
| 同一张图内角色外形完全一致 | 一次出整张，这是文档里验证过一致性最好的做法 |
| 一律朝右 | 朝左由 Godot 水平翻转 |
| **不要**在图上画刀光/残影/速度线 | 那是实机 FX（`battle_fx.gd`）的活，画在图里会切帧错位、且无法随攻击方向翻转 |
| 不要画血条/UI | 同理，HUD 是独立层 |

### 两个待定的尺度问题（会影响手感，需拍板）

1. **角色尺度**：`ai_anim_spec.json` 的 `target_body_h`（player 190 / monster 140，保持当前实机观感）与
   M1 碰撞盒假定的尺度（player ≈104 / monster ≈70）不一致，**约差 1.8 倍**。
   用 190 这档必须按同比例放大判定框，否则视觉与判定错位。
2. **攻击前伸**：preview 的攻击前伸约为身高的 **98%**，Godot 现在只有 **44%**
   （`moves.json` 的 `hitbox.x` 42~52）。即使尺度对齐，攻击距离仍需单独调。

两处的具体数值都写在 `tools/ai_anim_spec.json` 的 `tuning` 段里。

### 占位与正式的优先级

`anim.json` 每个条目带 `source` 字段（`ai` / `procedural`）。
`bake_game_assets.py` **逐条**合并，且**绝不用占位覆盖 `source=ai` 的条目**。
想回到纯占位状态：删掉 `game/art/anim.json` 再跑一次 `bake_game_assets.py`。

想在动作帧图就位前先看到正确画风：
```powershell
python tools/bake_ai_frames.py --spec tools/ai_anim_spec_portrait.json
```
（用 `hero_cool.png` / `goblin.png` 当单帧静态占位——替代的是**画风**，不是**动画**。）
