# 新版工程框架：原版内容编译（F2）

> 上级入口：[新版工程框架](29_新版工程框架.md)。本页记录 F2 的工具、内容包、覆盖率与已读到的原版结构。
> 全部来自共享库的备份 PVF（DNF-D001 未锁定实际生效配置）；结构解析为 E-PARSE，字段含义与单位除注明外未经实机核对。

## 一、工具与产物

| 位置 | 作用 |
|---|---|
| `tools/dnf_pvf.py` | 通用解析库：B0D0 token → 有序字段树；成对 `[x]…[/x]` 成为区段；枚举槽位挂到父字段；原版拼写错误经别名表归一 |
| `tools/compile_dnf_content.py` | 编译内容包与全库字段覆盖报告；需完整库（`dnf_asset_store.py sync --full`） |
| `tools/test_dnf_pvf.py` | 合成 token 流单测，不依赖完整库 |
| `game_dnf/assets_local/content/` | 产物（Git 忽略）：`combat_content.json`、`field_coverage.json`、`compile_summary.json` |
| `game_dnf/combat/fields/handled.json` | 运行时已执行的原版字段登记；覆盖报告的"运行时"列读它 |
| `game_dnf/content/api/content_db.gd` | `record`/`original`/`evidence`/`index`/`record_ids`：内容包作为原版基线层，按需加载 |

内容包含原版数据，不进公开主仓库；各区用同一编译器和同一资源锁在本地生成，产物哈希写在 `compile_summary.json`，可互相核对。

## 四、已读到的原版结构（供 F3~F5 使用）

- **攻击信息 ATK**：`[damage bonus]`、`[push aside]`（击退）、`[lift up]`（浮空）、`[damage reaction]`（硬直 damage / 倒地 down / 无）、`[attack direction]`（水平 / 下劈 / 上挑）、`[hit info]`（打击类别 blow/cut… + 是否出血 + 特效参数）、`[hit wav]`（命中音键）、`[active status]`（出血/眩晕/冰冻等异常及数值）、`[stuck]`（疑似停帧相关）。
- **技能 SKL**：`[dungeon]`/`[pvp]`/`[death tower]`/`[warroom]` 四种模式各有一套 `[consume MP]`、`[cool time]`、`[static data]`、`[level info]`；v1 只取 `[dungeon]`。部分技能把这些字段写在顶层（无模式区段）。
- **角色 CHR**：基础属性（HP/MP、攻防、移速 850、攻速 850、跳跃力 430 等），每个转职与觉醒各有成长组；普攻三段动作与三段攻击信息一一对应；6 种武器各有挥砍音、命中音与命中特效参数（`[weapon wav]`、`[weapon hit info]`）。
- **动作 ANI**：逐帧时长、攻击盒（如三段斩第 3~4 帧、100~200ms）、受击盒；首两段普攻身体 ANI 无攻击盒，需从武器或其它依赖找（DNF-D011）。
- **怪物 MOB**：普通哥布林指向 `Animation_Goblin2`（现版用的是 `Animation_Goblin`，DNF-D013 待核）、攻击间隔 `[attack delay]` 1200、视野 300、等级 1~6；AI 与难度分档在区段内，F5 解码。
- **原版拼写**：ATK 中有 `[hit horizono]`、`[warter element]`、`[noblood]` 等写法，说明引擎做了容错；别名表全部标 E-INFER。

## 五、下一步

F3 起用内容包替换手写值：ANI 时间线执行器读帧时长与攻击盒，ATK 处理器读击退/浮空/硬直，SKL 读 `[dungeon]` 的蓝耗与冷却。每接入一个字段，在 `handled.json` 登记并重跑编译器更新覆盖率。
