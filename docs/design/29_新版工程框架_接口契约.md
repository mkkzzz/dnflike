# 新版工程框架：接口契约

> 上级入口：[新版工程框架](29_新版工程框架.md)。本页是各模块之间的约定，改字段先改本页再改代码（只增字段可直接做）。
> 标"v1"的格式在 F0 落地；字段语义未经原版核对的，按[证据与版本](26_DNF原版拆解_证据与版本.md)标记。

## 一、空间、时间与标识

| 项 | 约定 |
|---|---|
| 世界坐标 | x 横向、y 地面纵深、z 离地高度；单位为原版像素；与 T2 地图导出同一套（screen_y = y + 偏移 − z，偏移由 MapQuery 给出） |
| 朝向 | facing = 1 向右、−1 向左；镜像只在 core 的 Box6 变换与 ActorView 中处理 |
| Box6 | 原始 [x, y, z, 宽, 纵深, 高]，相对实体锚点、朝右；语义 E-INFER，由 F3 盒体叠加实验确认 |
| 时间 | 毫秒浮点；ANI 帧时长原值；World 以固定模拟步推进，步长为配置项 |
| 随机 | 每个 Run 一个种子；World 内只用自带随机源 |
| 实体 ID | World 内自增整数，Run 内唯一；不使用系统时间生成 |
| 动作实例 | 实体 ID + 自增序号；用于命中去重与事件关联 |
| 内容 ID | 原版内部路径小写（如 character/swordman/attackinfo/attack1.atk）；显示名不作主键 |

## 二、命令（v1）

命令是"请求"，可被拒绝；拒绝原因以事件返回，不静默吞掉。

| 命令 | 字段 | 发送方 |
|---|---|---|
| combat.move | 实体、方向向量、是否奔跑 | 控制器 |
| combat.press | 实体、逻辑键（attack/jump/backstep/guard/skill槽位） | 控制器 |
| combat.release | 实体、逻辑键 | 控制器 |
| combat.start_room | run_id、room_id、角色战斗属性快照、技能/装备映射、实体出生记录、MapQuery | flow（ws2） |
| combat.pause / combat.resume / combat.stop | 战斗会话 | flow（ws2） |
| combat.apply_effect | 实体、效果（消耗品/属性变化），已由 items 校验 | items（ws2） |
| flow.* | 出征、撤退、回城、确认结算 | UI → flow |

物理按键到逻辑键的映射属于 UI/设置，不进入内核。
战斗场景单独运行时由验证入口发 start_room 默认数据；外部管理模式下不自动出征、领奖或重开（28第三节）。

## 三、事件（v1）

所有事件公共字段：type、tick（模拟步序号）、time_ms、event_id（会话内唯一，供流程侧去重）。各模块只能发自己前缀的事件。

战斗内部与表现用：

| 事件 | 主要字段 | 典型订阅方 |
|---|---|---|
| combat.action_started | 实体、动作ID、动作实例 | 音频、调试 |
| combat.action_rejected | 实体、动作ID、原因（CD/缺蓝/状态不允许） | HUD提示 |
| combat.frame_cue | 实体、动作实例、帧号、提示类型（音效/特效）、键 | 音频、FxView |
| combat.hit | 攻击者、目标、攻击实例、命中组、命中点、是否被格挡 | 闪白、FxView、镜头 |
| combat.damage | 目标、数值、暴击、伤害类别 | 跳字、HUD、统计 |
| combat.reaction | 目标、反应类型（硬直/浮空/倒地/起身/霸体） | 调试、音频 |
| combat.hitstop | 冻结实体列表、时长 | 镜头、调试 |
| combat.status | 目标、状态ID、施加/刷新/移除 | HUD |

对流程侧（命名沿用28第三节草案，v1 与ws2共同锁定）：

| 事件 | 主要字段 | 订阅方 |
|---|---|---|
| combat.monster_defeated | run_id、room_id、entity_id、原怪物ID、位置 | flow、items（只记账，按event_id提交收益） |
| combat.room_combat_finished | run_id、room_id、统计、角色状态快照 | flow（判断门/领主/结算） |
| combat.player_defeated | run_id、room_id、统计、角色状态快照 | flow |

门、切房、清房后的开门与结算由ws2的世界/流程模块处理并以 world.* / flow.* 事件发出，战斗不直接切房、写存档或切城镇。

事件只描述已经发生的事实；订阅方不能借事件回写发送方状态。

## 四、快照（v1）

World 每步结束生成只读快照，表现层只依赖以下字段：

| 对象 | 字段 |
|---|---|
| 实体 | id、类型、阵营、x/y/z、facing、动作ID、ANI键、ANI时钟、受击闪白、着色、存活、外观包键 |
| 玩家附加 | 血/蓝当前与上限、技能槽CD与可用状态、Buff列表 |
| 怪物附加 | 血量比例、是否领主、名称键 |
| 全局 | 连击数、本房存活敌人数、停帧中的实体集合 |

快照不含引用，表现层修改快照不影响模拟。

## 五、内容包（v1）

编译产物位于 assets_local 下的内容目录（Git忽略），由 L0 编译器生成。每条记录统一结构：

| 键 | 含义 |
|---|---|
| id | 内容ID（原版内部路径） |
| kind | chr / ani / atk / skl / mob / ai / action_graph 等（地图数据走ws2的 dnf_native_map） |
| raw | 原始 token 序列或原字段（保留重复标签与顺序） |
| decoded | 编译器解释后的结构化字段 |
| evidence | 每个 decoded 字段的证据等级与来源偏移 |
| unsupported | 本记录中未识别或无处理器的字段 |
| source | 来源文件、SHA256、资源锁版本 |

ContentDB 查询接口：按内容ID取记录；按实体类型取动作定义与动作图；取叠加后的最终值，同时可查该值来自基线/适配/超越哪一层。

超越层与适配层文件按"内容ID + 字段路径 → 值 + 原因"书写，不复制整条记录。

## 六、模块公开入口

| 模块 | 对外提供 | 不对外提供 |
|---|---|---|
| combat | 创建/销毁 World、提交命令、推进一步、读快照、订阅事件 | 实体内部部件、管线中间态 |
| content | 查询、叠加来源查询、覆盖率报告 | 编译过程 |
| map（ws2） | MapQuery：走区判定、阻挡、有效门区域、出生点、镜头范围、坐标换算 | 加载与绘制细节 |
| flow | 当前状态、Run/Profile 只读视图、命令入口 | 内部状态机实现 |
| debug/test_api | 测试所需的读状态、注入命令、跳到指定房间/状态 | 直接改内部字段 |

combat 通过 MapQuery 接口取得走区与阻挡，不依赖 map 模块的具体实现；测试时可换成简单的矩形走区。

## 七、字段处理器文件约定

每个处理器文件声明：

| 声明 | 例 |
|---|---|
| 原字段 | ATK 的 push aside |
| 阶段 | 命中前 / 伤害 / 受击反应 / 命中后 / 动作开始 / 帧事件 |
| 证据等级 | E-PARSE、E-INFER、E-ADAPT 等 |
| 执行函数 | 读 HitContext 与字段值，写 HitContext |
| 依据说明 | 一句话 + 证据位置链接 |

同一字段只能有一个处理器；需要改语义时修改该文件，并在字段覆盖报告中更新证据等级。
