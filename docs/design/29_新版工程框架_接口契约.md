# 新版工程框架：接口契约

> 上级入口：[新版工程框架](29_新版工程框架.md)。本页是各模块之间的约定，改字段先改本页再改代码（只增字段可直接做）。
> 标"v1"的格式在 F0 落地；字段语义未经原版核对的，按[证据与版本](26_DNF原版拆解_证据与版本.md)标记。

## 一、空间、时间与标识

| 项 | 约定 |
|---|---|
| 世界坐标 | x 横向、y 地面纵深、z 离地高度；单位为原版像素；与 T2 地图导出同一套（screen_y = y + 偏移 − z，偏移由 MapQuery 给出） |
| 朝向 | facing = 1 向右、−1 向左；镜像只在 core 的 Box6 变换与 ActorView 中处理 |
| Box6 | 原始 [x, y, z, 宽, 纵深, 高]，相对实体锚点、朝右；语义 E-INFER，由 F3 盒体叠加实验确认 |
| 时间 | 毫秒浮点；ANI 帧时长原值；World 以固定模拟步推进，步长为配置项 |
| 随机 | 每个 Run 一个种子；World 内只用自带随机源 |
| 实体 ID | World 内自增整数，Run 内唯一；不使用系统时间生成 |
| 动作实例 | 实体 ID + 自增序号；用于命中去重与事件关联 |
| 内容 ID | 原版内部路径小写（如 character/swordman/attackinfo/attack1.atk）；显示名不作主键 |

## 二、命令（v1）

命令是"请求"，可被拒绝；拒绝原因以事件返回，不静默吞掉。

| 命令 | 字段 | 发送方 |
|---|---|---|
| combat.move | 实体、方向向量、是否奔跑 | 控制器 |
| combat.press | 实体、逻辑键（attack/jump/backstep/guard/skill槽位） | 控制器 |
| combat.release | 实体、逻辑键 | 控制器 |
| combat.start_room | run_id、room_id、角色战斗属性快照、技能/装备映射、实体出生记录、MapQuery | flow（ws2） |
| combat.pause / combat.resume / combat.stop | 战斗会话 | flow（ws2） |
| combat.apply_effect | 实体、效果（消耗品/属性变化），已由 items 校验 | items（ws2） |
| flow.* | 出征、撤退、回城、确认结算 | UI → flow |

物理按键到逻辑键的映射属于 UI/设置，不进入内核。
战斗场景单独运行时由验证入口发 start_room 默认数据；外部管理模式下不自动出征、领奖或重开（28第三节）。

## 三、事件（v1）

所有事件公共字段：type、tick（模拟步序号）、time_ms、event_id（会话内唯一，供流程侧去重）。各模块只能发自己前缀的事件。

战斗内部与表现用：

| 事件 | 主要字段 | 典型订阅方 |
|---|---|---|
| combat.action_started | 实体、动作ID、动作实例 | 音频、调试 |
| combat.action_rejected | 实体、动作ID、原因（CD/缺蓝/状态不允许） | HUD提示 |
| combat.frame_cue | 实体、动作实例、帧号、提示类型（音效/特效）、键 | 音频、FxView |
| combat.hit | 攻击者、目标、攻击实例、命中组、命中点、是否被格挡 | 闪白、FxView、镜头 |
| combat.damage | 目标、数值、暴击、伤害类别 | 跳字、HUD、统计 |
| combat.reaction | 目标、反应类型（硬直/浮空/倒地/起身/霸体） | 调试、音频 |
| combat.hitstop | 冻结实体列表、时长 | 镜头、调试 |
| combat.status | 目标、状态ID、施加/刷新/移除 | HUD |

F1 已实现（战斗 → 表现，均同步派发）：

| 事件 | 字段 | 订阅方 |
|---|---|---|
| combat.cue | kind（sound/fx/fx_clear/ghost）、key；fx 另有 point（地面坐标）、height、facing、scale（命中特效缩放，来自 ATK/CHR hit info）、tag/follow/max_ms（招式特效：所属招式、跟随实体、最长存在时间）；fx_clear 按 tag 清除；ghost 为被打断姿势的残影（pos、z、facing、ani、clock） | AudioRouter、BattleView |
| combat.action_cancelled | entity_id、action、by（如 backstep） | 调试/统计 |
| combat.damage | 在上表基础上加 point（受击后的 x/y/z）、victim（monster/player）、reaction（none/stagger/launch/down/air） | 跳字 |
| combat.room_loaded | room_index、room_id、props（副本） | BattleView 重建物件、清理角色与特效 |
| combat.entity_spawned / entity_removed | entity_id、kind、appearance（怪物资源包键 goblin / goblin_thrower）、chief | BattleView 增删角色视图 |
| combat.appearance_changed | entity_id、weapon | BattleView 换纸娃娃包 |

F4 起 cue 的键由数据决定：音效键为原版键（ATK [hit wav]、CHR [weapon wav]、ANI 帧事件）或试玩喊声键，特效键为战斗资源包里的原版特效。

对流程侧（命名沿用28第三节草案，v1 与ws2共同锁定）：

| 事件 | 主要字段 | 订阅方 |
|---|---|---|
| combat.monster_defeated | run_id、room_id、entity_id、monster_id（F5 起为原版 MOB 路径，如 monster/goblin/goblin.mob）、boss、位置 | flow、items（只记账，按event_id提交收益） |
| combat.room_combat_finished | run_id、room_id、统计、角色状态快照 | flow（判断门/领主/结算） |
| combat.player_defeated | run_id、room_id、统计、角色状态快照 | flow |

门、切房、清房后的开门与结算由ws2的世界/流程模块处理并以 world.* / flow.* 事件发出，战斗不直接切房、写存档或切城镇。

事件只描述已经发生的事实；订阅方不能借事件回写发送方状态。

## 四、快照（v1）

World 每步结束生成只读快照，表现层只依赖以下字段：

| 对象 | 字段 |
|---|---|
| 实体 | id、类型、阵营、x/y/z、facing、动作ID、ANI键、ANI时钟、受击闪白、着色、存活、外观包键 |
| 玩家附加 | 血/蓝当前与上限、技能槽CD与可用状态、Buff列表 |
| 怪物附加 | 血量比例、是否领主、名称键 |
| 全局 | 连击数、本房存活敌人数、停帧中的实体集合 |

快照不含引用，表现层修改快照不影响模拟。

F1 过渡实现：`game_dnf/scripts/main.gd` 的 view_snapshot()，每帧交给 view/battle_view.gd 的 present(快照, 帧毫秒, 模拟毫秒)。

| 键 | 内容 |
|---|---|
| frame、paused | 帧序号、是否暂停 |
| player | pos、z、facing、ani、clock、flash、buff、weapon、aura（增益光环特效键，空=无） |
| enemies[] | id、pos、z、facing、ani（该怪物 MOB 动作文件名，如 attack1/throw）、clock、flash、alive、death_ms、hp_ratio、chief |
| objects[] | id、bank（飞出物资源包键）、pos、z、facing、clock |
| props[]、stage | 物件状态副本（原版地图房间为空）；room_index、placement（原版地图导出的房间 id，如 1_0:s3）、cleared、doors |
| hud | room_name、alive、room_cleared、route[]（cell 为原版 dgn 格子）、combo、toast/toast_ms、skills[]（name/label/key/cooldown/mp）、monster_bar（id/mob/name/level/rank normal\|elite\|boss/hp/max_hp/lines，空=不显示）、player（血蓝/上限/职业/武器/buff/buff_label/CD）、overlay（结算/暂停/帮助）；视图另加 camera（水平镜头） |

模拟毫秒只在暂停时为 0（F4 起停帧是局部的，只冻结攻防双方）；特效时钟随它推进；跳字按帧毫秒老化。
外部管理模式按键：X 普攻、C/空格 跳、V 后跳、G 格挡、Z 上挑、A 拔刀斩、S 三段斩（连按续段）、D 十字斩、F 暴走。

## 五、内容包（v1）

编译产物位于 assets_local 下的内容目录（Git忽略），由 L0 编译器生成。每条记录统一结构：

| 键 | 含义 |
|---|---|
| id | 内容ID（原版内部路径） |
| kind | chr / ani / atk / skl / mob / ai / action_graph 等（地图数据走ws2的 dnf_native_map） |
| raw | 原始 token 序列或原字段（保留重复标签与顺序） |
| decoded | 编译器解释后的结构化字段 |
| evidence | 每个 decoded 字段的证据等级与来源偏移 |
| unsupported | 本记录中未识别或无处理器的字段 |
| source | 来源文件、SHA256、资源锁版本 |

ContentDB 查询接口：按内容ID取记录；按实体类型取动作定义与动作图；取叠加后的最终值，同时可查该值来自基线/适配/超越哪一层。

超越层与适配层文件按"内容ID + 字段路径 → 值 + 原因"书写，不复制整条记录。

## 六、模块公开入口

| 模块 | 对外提供 | 不对外提供 |
|---|---|---|
| combat | 创建/销毁 World、提交命令、推进一步、读快照、订阅事件 | 实体内部部件、管线中间态 |
| content | 查询、叠加来源查询、覆盖率报告 | 编译过程 |
| map（ws2） | MapQuery：走区判定、阻挡、有效门区域、出生点、镜头范围、坐标换算 | 加载与绘制细节 |
| flow | 当前状态、Run/Profile 只读视图、命令入口 | 内部状态机实现 |
| debug/test_api | 测试所需的读状态、注入命令、跳到指定房间/状态 | 直接改内部字段 |

combat 通过 MapQuery 接口取得走区与阻挡，不依赖 map 模块的具体实现；测试时可换成简单的矩形走区。

F0 已实现的战斗入口：`game_dnf/combat/api/combat_session.gd`。

| 项 | 内容 |
|---|---|
| 挂载 | mount(父节点) 以外部管理模式实例化战斗场景：不自动开局；R/Tab/1~3/Esc/F2/F3 归流程侧；不画结算；默认不放副本 BGM |
| 方法 | start_room(spec)、pause()/resume()/set_paused(bool)（同时清掉按住的键与缓冲输入）、apply_effect(effect)、stop()、read_view()、events() |
| spec | run_id、room_id、room_index（过渡期指现版五房路线）、from（入口方向）；player {hp, mp, hp_max, mp_max, damage_multiplier, job, weapon}（不给 hp_max/mp_max 时取 CHR 1 级初始值 180/140）；audio {muted, bgm_volume_db}；show_hud（默认 true；false 只隐藏底栏/房间信息/小地图/提示/覆盖层，跳字、连击与上方怪物血条仍显示） |
| apply_effect | 流程侧已校验并扣除物品后调用；v1 支持 {kind:"heal", amount}，满血/暂停/结束时返回 false |
| read_view | run_id、room_id、room_index、room（1起）、room_count、room_name、hp/hp_max、mp/mp_max、pos、facing、job、weapon、attack_damage（F4 起=攻击力 25×damage_multiplier，各招再乘原版百分比）、cooldowns（秒）、buff_ms、enemies[{id,pos,hp,chief}]、alive_monsters、exit_target、room_cleared、finished、victory、paused |
| 循环键位 | submit_key(code, pressed, echo=false)：循环先映射ASDFGH再提交；独立main仍由自身输入。打开面板时pause清输入 |
| 试炼适配 | configure_trial(movement_scale, difficulty)：start_room后每Run只调用一次，私有副本加快玩家移动，怪物HP/攻击使用普通/冒险/王者适配系数；不修改ws1共享规则对象 |
| 技能说明 | game_dnf/combat/api/skill_catalog.gd的get_skill(id)只读投影相同编译内容/MoveTable的MP、冷却秒与伤害百分比，UI不直接导入内核 |
| 信号 | monster_defeated、room_combat_finished（含 boss、final_room）、player_defeated，载荷即第三节事件（含 event_id；stats 含 time_ms、damage_taken、hits） |
| 过渡限制 | 房间为原版洛兰五房（room_id 形如 lorien:0）；门与切房仍在战斗场景内，按28移交前不对外承诺 |
| 使用方 | `game_dnf/flow/loop_root.gd`（2026-10-22 由 ws1 接入，取代 legacy_combat_port） |

## 七、字段处理器文件约定

### 数值扩展（2026-10-23 用户授权）

- 新增 `stats/api/numbers.gd`，依赖层级为 core → content → stats → combat；外部仅引用 stats/api。
- start_room 的 player 可增 numbers（最终属性）、number_seed（level/growtype/modifiers）、number_sources（来源）、skills（技能等级）；旧调用无这些字段时保留旧验证入口。
- combat.update_numbers(player_spec, vitals_policy="preserve") 更新当前会话，保留动作与冷却；preserve 保留血蓝绝对值并夹到新上限，refill 回满。参数不写入长期存档。
- combat.apply_effect 增 effect/remove_effect（id、target 可选实体ID），数值更新允许暂停面板操作；时长仅随模拟推进。read_view 增 numbers/sources/effects/skills/last_damage。
- 长期角色数值经 flow 的 numbers.* 事务修改；经验以独立 transaction ID 去重，不依赖通关来源。装备实例与技能购买记录随存档保存，派生面板读档后重算。
- 数据基线及公式常数是 E-ADAPT；备份 SKL 逐级结构是 E-PARSE，蓝耗端点插值为 E-INFER；不能宣称已还原主参照平衡。

每个处理器文件声明：

| 声明 | 例 |
|---|---|
| 原字段 | ATK 的 push aside |
| 阶段 | 命中前 / 伤害 / 受击反应 / 命中后 / 动作开始 / 帧事件 |
| 证据等级 | E-PARSE、E-INFER、E-ADAPT 等 |
| 执行函数 | 读 HitContext 与字段值，写 HitContext |
| 依据说明 | 一句话 + 证据位置链接 |

同一字段只能有一个处理器；需要改语义时修改该文件，并在字段覆盖报告中更新证据等级。
