# 城镇联通与赫顿首批

入口：[前期城镇与NPC](30_前期任务城镇与NPC设计_城镇与NPC.md)、[任务详细契约](31_任务系统详细设计.md)。本批在既有洛兰小闭环后扩展赫顿，不代表整个城市/所有服务已还原。

## 一、原结构与本批范围

读取town.lst确认1=艾尔文、2=赫顿。MAP的town movable area按六项x/y/w/h/城镇索引/地区索引解释，利用两端反向引用核对；前四项是出口触发范围，不是整张地图可走范围。virtual movable area四项组作为城镇地面区域的依据。

| 衔接 | 源记录 | 本批处理 |
|---|---|---|
| 艾尔文左→赫顿城市区右 | Elvengard [-5,192,29,141,2,1]；City [3777,219,20,117,1,0] | 双向保留；左边界触发略向可走区展开，落点离开出口避免回跳 |
| 城市区上→主街下 | City [747,163,106,18,2,0]；(r)Hendon [1016,456,100,40,2,1] | 双向街区，不能从艾尔文一步传到风振旁 |
| 主街上→后街下 | (r)Hendon [298,157,107,21,2,2]；Auction [341,350,95,19,2,0] | 风振在主街，辛达/G.S.D在后街；沿原坐标分开 |
| 后街赛丽亚入口 | Auction [781,170,79,24,2,5] | 共用既有原房间美术，记录入口归属，退出回后街 |
| 艾尔文赛丽亚入口 | 已有主街→房间连接 | 保留，退出仍回艾尔文；切角色不串归属 |

主街通用Hendon.map在原库缺失，明确选(r)Hendon.map，不能按文件名猜它是唯一生效版本。City与Auction用对应原文件；源路径、SHA、原坐标和诊断随Hendon资源manifest发布。原文104也明确要求沿艾尔文左侧进赫顿，支持这条路径，而不是把右边洛兰副本口替换成城市门。

西海岸、月光酒馆、雪山、格兰副本口等其它连接本批不开放。可见但未实现的方向给中文状态，不创建无效点击或传送到相似场景。TWN的等级限制不直接作为剧情进城硬锁；本地安全城镇可探索，任务等级仍按QST。

## 二、运行定义与职责

[城镇配置](../../game_dnf/data/towns.json)是运行唯一入口，包含locations、portals、npcs。TownWorld负责校验和纯查询，NativeTown装配原图/人物与移动，flow负责角色状态/场景事务/存档，任务模块不拥有场景节点。

| 数据 | 字段与规则 |
|---|---|
| location | 稳定ID、中文名、原素材manifest/placement、默认安全落点、可走矩形并集、NPC脚点、方向标识、镜头范围 |
| portal | 稳定ID、from/to、边缘自动触发rect、目标spawn、reciprocal、中文名、source_raw和适配证据 |
| npc | 稳定ID、中文名、明确开放的服务、中文对白；世界形象/大立绘来自本批原素材 |
| 角色位置 | town_location、town_position[x,y]、inn_return入口ID；随独立角色存档，不写全局设置 |

每条启用出口必须有反向边，目标必须存在，落点在可走区；运行plan还要校验当前场景、实际距离、城镇状态和入口归属。UI传来的目标字符串不能直接赋给角色位置。共有房间的返回边由inn_return筛选，不能每次固定返回艾尔文。

按用户要求，走到启用的出口边缘自动进入，不需E；E仅用于NPC交谈与既有战斗拾取。NativeTown移动后查询TownWorld.entry_at并发出入口事件，流程侧重新核对实际入口，不受附近NPC优先级干扰。艾尔文副本选择用location.dungeon_entry配置右端边缘，原1355起的宽泛接近区不再当入口。赛丽亚外门/房间下门也收紧到门口与地面边缘，经过门前或在房内活动不应提前切场。

地面按矩形并集约束，不能把各区域外接成一个可穿建筑的大矩形。赫顿主街原扩展地砖是独立224×120源图，接在480像素主地面下，不放大或用色块补地；纵向镜头配合下出口，让脚点保持在HUD上方。原IMG/ANI像素、帧时钟和前后层保留。

## 三、场景事务与输入

流程：核对出口→预装目标原资源→复制当前角色快照→写目标场景/安全坐标/入口归属→验证并保存→短暂淡出→替换活动会话与可见场景→淡入→恢复输入。

- 缺资源或保存失败：保留旧场景、坐标和角色状态，提示可重试；不先隐藏旧场景或把目标位置写入活动角色。
- 过渡期间锁住移动、NPC交互和面板输入；只允许一条切场事务。持续按住方向不应在落地后自动奔出，松开后重新响应。
- 目标落点避开回程触发区，读档/切场先松开方向再行动。同一入口每次走入只触发一次：保存/资源失败、取消副本选择后持续顶边不重复尝试，离开触发区后重置。载入时已位于入口内也先抑制，防止读档立即跳场。多个场景共用一个玩家演员和姓名节点，旧场景缓存隐藏，动画只推进当前场景。
- 任务、背包、数值和掉落的角色字段均来自同一候选深拷贝；切城不能重建一个空角色覆盖它们。
- F5/离开选人/出征前记录当前位置；副本回城恢复实际出征地区与落点，不固定回林纳斯旁。中断战斗读档沿用既有安全回城规则，不补通关奖励。
- 旧档缺坐标时取所属场景安全落点；未知/移除场景回艾尔文，非有限坐标/建筑内坐标投影到合法地面；入口ID失效回艾尔文入口。

## 四、任务与NPC

| 原任务 | 源等级/前置 | 原人物关系与目标 | 本地奖励（E-ADAPT） |
|---|---|---|---|
| 104 流动的丛林 格兰之森 | 3 / 4301 | 林纳斯→风振，会面 | 100金币、100XP |
| 1901 鬼剑士之路—开始 | 3 / 104 | 风振→风振，再次对话 | 200金币、200XP |
| 501 鬼剑士之路—赫顿玛尔的辛达 | 4 / 1901 | 风振→辛达，会面 | 300金币、120XP |
| 502 鬼剑士之路—所谓的转职是？ | 4 / 501 | 辛达→辛达，再次对话；保留原int data [4,0] | 200金币、120XP |

再次对话以接取后实际交互为准，接任务不自动完成。原前置/等级/人物/目标字段来自现有取证与本批只读原QST；XP与金币属于适配，不能把原reward int data的0擅自当作已解码经验/金币公式。首批结尾的正常角色能顺接104，并由这些奖励达到501等级，无需GM跳级。

G.S.D放在原后街1496/208脚点，提供已有技能页；风振不向鬼剑士出售格斗家技能。辛达提供现有装备管理入口，未实现的修理/制造/正式商店不摆假按钮。卡妮娜、凯丽、诺顿、歌兰蒂斯和阿尔伯特按原白名单坐标入街景，可正常交谈，后续服务按各自任务开放。

本批不把最低13级的506强行提前，也不把502交付当作真正转职。职业变化、分解、强化经济和森林新副本后续另接。对白为基于原人物职责的简体适配，不宣称逐字恢复原条件对白。

## 五、验收出口

1. 只用真实方向键从艾尔文左边进入City，走上方出口到Main，再进Auction；从同一图的反向门完整返回。赛丽亚两地入口和艾尔文副本选择也自动进入，全程不按E切场。
2. 104/1901/501/502通过实际NPC对话和任务按钮接交；错误人物、重复交付与不足等级拒绝。
3. 赛丽亚房间分别从艾尔文/后街进入，保存并重载后仍返回对应街区；换角色不继承别人入口。
4. 切场缺素材/写盘失败无部分提交；淡入淡出锁输入；持续按键不多次触发，取消副本选择不立即重开，退开再走入可重开；经过门前不提前进入，角色不留在对面门的触发区。
5. 赫顿出征、撤退/回城、返回选人/重载均保留城市与安全位置、物品/装备/任务。
6. 城市远近景、风振/辛达/G.S.D大立绘、下出口扩展地面、中文招牌和多任务追踪实机检查。原版同条件对照和用户美术认可另记。
7. 新原图必须进不可变资源包；无原版库新目录只拉Git与共享包即可运行，不依赖ws2本机完整库。
