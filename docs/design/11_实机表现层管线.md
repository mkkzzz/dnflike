## 二、美术源的分层（**重要，别搞错**）

这个项目里有**两个** Python 渲染器，职责完全不同，不可混为一谈：

| | `tools/render_preview.py` | AI 帧图 → `tools/make_anim.py` |
|---|---|---|
| 性质 | **手感验证工具**（见 [会话记录与美术定稿](../../2026-10-13_会话记录与美术定稿.md) §五） | **正式美术生产线**（见 [10_美术与音频管线.md](10_美术与音频管线.md)） |
| 产出 | 640×360 程序化预览视频，用于验证帧表/打击感/浮空连段 | 手绘质感的透明帧条，进游戏 |
| 角色美术 | 几何图元拼的**低保真示意**，且配色属**已弃用的「白衬衫深蓝外套」旧方案** | 按定稿标杆生成 |

**不要作为参照**。

> ⚠️ 历史教训：曾误把 `render_preview.py` 当作"唯一美术源"，据此烘焙了角色帧条。
> 那些帧条**画风与保真度都不对**（等于把已弃用旧方案的低保真近似当成了美术），
> 现仅作为**占位**保留，必须由 AI 帧图产物替换。

### 正确的美术链路

```
AI 生成整张动作帧图（同图内角色一致性最好）
        │
        │  tools/make_anim.py（已有能力：绿幕抠图 → 连通域切帧 → 脚底对齐
        │                      → 统一画布 → 微弱像素化 → 输出水平透明帧条）
        ▼
game/art/{player,monster}/<action>.png  +  game/art/anim.json
        │
        ▼
game/scripts/anim_lib.gd   ← 只按契约切帧播放，不含任何美术细节
```

**帧条契约**（`anim.json` 每项）与 `anim_lib.gd` 一致，因此换美术源时 Godot 侧零改动：

```json
"idle": { "file": "art/player/idle.png", "frames": 6,
          "frame_w": 259, "frame_h": 221, "ax": 175, "ay": 193,
          "durations": [3,3,3,3,3,3], "fps": 30, "loop": true }
```

- `ax/ay` = **脚底锚点**相对帧左上角的像素偏移（`ax` 取髋部横坐标，`ay` 取脚底纵坐标）
- 同一动作的所有帧**共用同一画布**（否则播放时会抖）
- 一律朝右（facing = +1），Godot 侧水平翻转处理朝左

`game/art/` 是烘焙产物，已加入 `.gitignore`（与 `temp/`、`tools/godot/`、`game/.godot/` 同理）。
换机器 / 改完美术后重跑烘焙脚本即可。

## 三、坐标系约定（实测确定，改之前先读这里）

preview 的世界画布是 640×360，实机是 1280×720，倍率：

```
SCALE = 1280 / 640 = 2
```

preview 是**伪 3D 横版**：每个实体有 `x`（横向）、`z`（景深）、`h`（离地高度），
脚底屏幕坐标 = `(GROUND0 + z) * SCALE`。

实测取值：

| 项 | preview 世界 | 实机（×2） |
|---|---|---|
| `GROUND0` | 224 | 448 |
| 玩家 `z` | 64 | — |
| **实机物理地面线 `GROUND_Y`** | — | **576** |
| 玩家站立总高 | ≈77.6 px | ≈155 px |

因此 `main.gd` 的 `GROUND_Y = 576`（= `(224 + 64) × 2`）。

**怪物不共用这条物理线**：`Player`/`Monster` 都是 `CharacterBody2D` + `is_on_floor()`，
改它们的 `position.y` 会破坏地面判定。所以用**纯视觉景深 `depth_y`**（只偏移绘制）
复现 preview 的远近层次——见 `main.gd` 的 `SPAWNS` 与 `monster.gd` 的 `depth_y`。

preview 的实体景深：哥布林战士 `z=56`、红皮哥布林 `z=80`，相对玩家 `z=64` 即 `-8 / +16`。

## 四、帧条与锚点规范

- 帧条为**水平排列**的 PNG：`game/art/player/<action>.png`、`game/art/monster/<action>.png`
- 一律烘焙成**朝右（facing = +1）**，Godot 侧靠水平翻转处理朝左
- 每个动作的**所有帧共用同一画布尺寸与锚点**，否则播放时会抖
- 锚点是**脚底**相对帧左上角的像素偏移，记录在 `game/art/anim.json`
- 实体的 `position` 即脚底位置，绘制时用锚点反推左上角

索引在 `game/art/anim.json`。

玩家动作：`idle run jump back_dash guard attack1 attack2 attack3 upper hit air down getup
quick_draw rage_slash thrust`
怪物动作：`idle patrol chase attack hit air down getup`

`game/scripts/anim_lib.gd` 是帧条仓库（`RefCounted`），只做「读清单 + 切帧 + 推进时钟」，

## 七、HUD

- **静态层**（底板 / 经验条 / 技能格框 + 按转职分的图标 / 头像 / HP·MP 球底 / 铭牌框 / 小地图）
  由 `tools/bake_hud.py` 烘焙成 `game/art/hud/*.png`，几何清单在 `game/art/hud/hud_manifest.json`。
- **动态层**（分段血条填充 / 数值文字 / COMBO / 冷却遮罩 / 球体液面）在 `game/scripts/hud.gd` 按
  manifest 给的坐标叠加。
- manifest 的坐标**已经是实机像素**（preview 的 HUD 本来就画在 1280×720 上），不要再乘 `SCALE`。

`main.gd` 的接线：

```gdscript
hud = Hud.new(); add_child(hud); hud.set_font(font)   # CanvasLayer 由 Hud 内建，不随相机滚动
hud.set_player_info("幽影剑士", 30, 0); hud.clear_room()   # M2 房间系统未实现，不显示假数据
# 每帧：
hud.set_vitals(hp, max_hp, mp, max_mp); hud.set_combo(combo)
hud.set_job(job); hud.set_target(最近的存活怪物)
_hud_cooldowns()   # player.cds(帧) + skills.json 的 slot/cd → 格子索引，画冷却扇形与秒数
```

HUD 必须挂 `CanvasLayer`——挂在 `Node2D` 下会随相机一起滚动（M1 的调试文字就有这个 bug）。

## 八、表现层怎么验证

**单靠读代码或看日志验证不了观感**，本项目用这套流程：

```powershell
# 让自动化测试驱动战斗，同时录制 —— 这样不用键盘输入也能看到连招/技能/跳字
tools/godot/Godot_v4.7.2-stable_win64_console.exe --path game `
  --write-movie temp/x.avi --fixed-fps 60 --quit-after 800 -- --test
# 抽帧（ffmpeg 来自 imageio-ffmpeg）
ffmpeg -y -i temp/x.avi -vf "select=eq(n\,165)" -vframes 1 temp/x_165.png
```

然后**用图像工具实际看这张图**。本阶段靠这个流程抓到的真问题：

| 问题 | 只看代码/日志会怎样 |
|---|---|
| 地面线取 448 导致角色悬在走廊中景 | 探针实测才发现 preview 有景深轴 `z`，正确值是 576 |
| `depth_y` 为负的怪物被背景吞掉 | `z_index` 为负 → 跑到背景背后，两只怪只剩一只可见 |
| 暗角层号压住了 HUD | 合成顺序应为 `world(含暗角) → hud` |
| HP/MP 球没有液面 | 球底贴图中心 `alpha=255` 不透明，且在液面之后被画了第二遍 → 盖住液面 |
| 伤害跳字显示 `40.0` 而非 `40` | Godot 把 JSON 数字解析成 float，`str()` 直接带出小数点 |
| 技能图标疑似不随转职变化 | 裁图放大对比后**证伪**，避免了一次误报 |
