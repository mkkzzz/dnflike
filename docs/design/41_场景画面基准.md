# 场景画面基准（城镇 / 副本 / 战斗共用）

> 本文件是**唯一权威**：任何场景的纵向定位、HUD 位置、门与角色落点都按这里换算。
> 代码常量在 `game_dnf/view/world_frame.gd`，改动规范必须同时改这里与常量。

## 一、基准

| 项 | 值 | 依据 |
|---|---|---|
| 逻辑画布 | 800×600 | 原版窗口；循环与独立战斗入口共用 |
| 呈现方式 | 1:1 像素 | 只允许整数倍整体放大，禁止分数缩放 |
| HUD 底图 | 800×92，贴 y=508 | `interface2/HUD/HUD.img` 帧0；控件坐标 = 底图坐标 +508 |
| HUD 镂空行 | 508…556 | HUD 图内 y=0…47 只有 12%～21% 不透明 |

## 二、三层坐标与换算

原版导出数据（`tools/export_dnf_map.py`）有三套纵向量：

| 层 | 含义 | 数据范围 |
|---|---|---|
| 美术坐标 | TIL 地砖、background 层，屏幕空间 | 背景 −80…295，地砖 245…480 |
| map 坐标 | 通行格、门锚点、角色脚点 | 0…360（30 行 × 12） |
| 画布坐标 | 最终绘制 | 0…600 |

换算（`world_frame.gd`）：

- `ART_DY = 80`：美术坐标 + 80 = 画布坐标。取 80 是因为美术顶端 −80 必须落在画布顶端 0。
- `MAP_DY = ART_DY + 120 = 200`：map 坐标 + 200 = 画布坐标。其中 120 是导出器的 `screen_y_offset`（地砖底 480 − 通行格 360）。

落地结果（所有洛兰房间与艾尔文一致）：

| 元素 | 画布纵向 |
|---|---|
| 背景层 | 0 … 375 |
| 地砖 | 325 … 560 |
| 通行格 | 200 … 560 |
| 下方门锚点（map y 348） | 548 |
| HUD | 508 … 600 |

560 > 556，所以 HUD 镂空那几行看到的是真实地砖，画面底部不存在任何空洞。

## 三、职责划分

| 模块 | 负责 |
|---|---|
| `scripts/native_map_loader.gd` | 输出画布坐标：地砖/背景 +`ART_DY`，锚点走 `ground_to_screen()` 内含 `MAP_DY` |
| `view/map_stage.gd` | 地图根节点固定在原点，不再自行加减纵向偏移；相机窗口宽 800 |
| `view/battle_view.gd` | map 坐标（角色/敌人/物件/特效/跳字）经 `_canvas()` 加 `MAP_DY` |
| `town/native_town.gd` | 角色脚点 = ground + `MAP_DY`；门光墙锚点同一偏移 |
| `flow/loop_root.gd` | 不缩放、不位移战斗与城镇节点 |
| `ui/combat/*` | 画布宽高由视图给出，控件不写死 640×360 |

## 四、禁止事项

- 禁止为了让画面"填满"而复制地砖、拉伸贴图、放大地图（原 48px 地面补条已删除）。
- 禁止在场景根节点上加纵向偏移或缩放；偏移只在上面两张换算表里出现。
- 禁止按 640×360 或 640×480 设计新场景：战场相机与画布都是 800×600。
- 新增场景（新城镇、新副本）只要用原生 MAP/TIL，即自动满足本基准；若某张图原版自带扩展地砖（赫顿主街 224×120），直接接在 480 之下，不需要额外处理。

## 五、走区与地面一致性

判定口径：走区矩形的底边（角色最深的落脚点）必须落在该场景地砖/背景/物件美术的某一纵向区段内，容差 ±2 px。副本按原 MAP 通行格的可走行底边判定。

`python tools/check_dnf_walk.py` 可各机复跑，只读 `data/` 与 `assets_local/`，不启动引擎；不对应时以非零退出码结束。

2026-10-28 实测（7 个城镇 + 洛兰 16 张图）：

| 场景 | 美术纵向 | 走区脚点 | 结论 |
|---|---|---|---|
| 艾尔文防线 | −33…560 | 375…552 | 脚点在地砖上，距地面底 8 px |
| 赛丽亚房间（双入口） | −1…565 | 378…548 | 脚点落在房间大图（closeback）上 |
| 赫顿城市区 | −12…560 | 371…531 | 含一处台阶矩形 371…430 |
| 赫顿主街 | 0…681 | 367…674 | 含原版扩展地砖（480…600 +80）与纵向镜头 120 |
| 赫顿拍卖行 | −36…576 | 366…566 | 末段 526…566 由台阶物件支撑 |
| 森林入口区 | 0…640 | 344…522 | 走区只占上半段，原版如此 |
| 后街小巷 | 0…640 | 411…559 | 同上 |
| 洛兰副本 16 张 | 地砖 325…560 | 344…548 | 全部落在通行格对应的地砖内 |

走区最深脚点会进入 HUD 覆盖区（508 以下），这是原版走区与 HUD 叠加的结果，不是坐标错位：脚点下方仍然是真实地面，只是被 HUD 底图挡住。

## 六、验证

`tools/run_dnf_loop.ps1 -Test` 内含三条固化断言：

- 城镇美术底边 ≥ 556，且不存在 `hud_ground_extension` 补条节点；
- 战斗美术底边 ≥ 556；
- 战斗根节点 `scale == 1`、`position == 0`，地图根节点纵向偏移为 0。

本机缺掉落贴图时循环套件会挂 5 项（掉落原版精灵/金币翻转/光柱/拾取音效），先跑 `python tools/bake_loot_sprites.py --library <完整库>`。
