# 美术目录与资产归档

2026-10-16 用户要求：原画、场景、UI、动作等清晰分层，正式源资源不放评审路径。本文规定目录归属；实际资源状态仍以任务包/版本注册表为准。

## 1. 分类层级

| 一级分类 | 二级/三级细分 | 内容 |
|---|---|---|
| art/concepts | characters → players / monsters / npcs → 身份 → 版本 | 角色标准原画、转面、表情、颜色材质、武器与握法设定 |
| art/concepts | scenes → 区域/房间 → 版本 | 场景原画、构图与材质设定 |
| art/concepts | items → 武器/装备/道具 → 版本 | 独立物品设定；角色专属装备设定可放对应角色包 |
| art/animations | players / monsters → 身份 → 版本 → sources / exports | 动作原画图集、标定、actor 导出、动作 manifest |
| art/animations | shared → 批次 → sources / exports | 历史玩家/怪物共用一套标定和烘焙流程的演示包 |
| art/effects | combat / environment → 效果或版本 | 独立刀光、命中、环境特效的源和成品 |
| art/ui | hud / icons / panels → 用途/版本 | UI 设计与可复用源资源，不包含动态数值 |
| art/explorations | 技术或题材 → 试验版本 | 3D/骨架/技术探针、搁置概念，仅留追溯，不作正式母版 |

当前没有资源的分类只规定位置，不用空文件冒充完成；按实际任务建目录。正式包的 candidates/details/source/exports 放在各自身份与版本下，不把所有候选集中成无主目录。

## 2. 包内归档

- source 或 sources：原始源图与真实生成记录；生成后保留原输出，不能只有下载 URL。
- candidates：未批准候选；同版本 c1/c2 不覆盖。已弃用保留原文件并标原因，不混进正式母版。
- details/parts/weapon：真实细节裁切、部件和握点规格；有背景的裁切不能称透明部件或新增原画。
- exports：经加工验证的成品。既有 seq/actor 包保持原内部结构，避免破坏 manifest/root/混合和帧时钟。
- manifest 与 calibration：包入口、来源/批准、依赖与参数；物理路径改变不更改语义 ID、clip 名和版本号。

## 3. 原画、动作与运行资源的边界

- art 是源资产与离线成品，不直接作为游戏运行资源根；game/assets 是已接入的消费副本。
- docs/previews 只放对比板/回放/评审媒体，不放唯一正式源图。正式资源入口必须指向 art 或 game/assets。
- docs/screenshots 是实机证据，不把离线合成图放入其中。
- docs/tasks/art_tasks 是单项规格、批准与交接；docs/reports 是过程快照，不把历史报告当现行资产入口。
- 动作与其强耦合特效可保留在同一版本交付包，不能为目录好看拆坏已有相对引用。独立可复用特效才进入 effects。

## 4. 迁移安全与验收

1. 迁移以目录/完整版本包为单位，先登记占位；混合图集按实际主体/功能分类，不只看文件名。
2. 不删除或重新编码二进制图像；移动前后核对文件数量与内容哈希。
3. 现行代码/任务/资产 JSON 更新到实际新路径；分段 Path 拼接和相对路径单独核对，不只替换 art/ 字符串。
4. 交接日志旧行保持不变。历史路径的查找通过明确的迁移表，不能用创建软链接/假空目录掩盖漏改。
5. 技术验收包括资源引用、文档、工具读取与既有静态资源测试；目录迁移不触发游戏重新烘焙或替换贴图。
6. 游戏实机测试未跑时明确写未跑；目录检查通过不代替原画审美批准。

分类、迁移映射与正式入口见 [art/catalog.json](../../art/catalog.json)；详细校验快照见[迁移报告](../reports/ws1/2026-10/2026-10-16_art_layout_validation.json)。可重跑 `python tools/migrate_art_layout.py --check` 核对图像内容。该目录表不是游戏资源 resolver，不声称引擎已支持动态资产 ID 解析。
