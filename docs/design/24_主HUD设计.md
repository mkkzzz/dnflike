## 一、结论

- **现行 HUD 的问题**：信息挤左上、技能单排无道具格、无左右球体、无经验/评价/增益、字体层级弱、底栏只有一层半透明渐变；与参考的"金属底板 + 分区锚定"完全不是一个结构，按使用者判断重做。
- **已确认（2026-10-18）**：
  1. 队伍栏**暂不实装**，只在左上留 880×58 空位；
  2. 技能栏**双排 12 格**，键位 Q W E R T Y / A S D F G H，只用于技能，与移动/普攻/跳跃等基础动作键无关；格内放什么由玩家自定义，**默认填当前已有技能**（每职业 2 个），其余空槽；
  3. 视觉**完全参考原图**（藏蓝珐琅 + 古金浮雕）；
  4. 评价面板**先不做真数据**，只出样式占位；
  5. 中央圆形轮盘**要做且要留功能**，当前功能先留空；
  6. **所有 UI 资源必须通过生图生成**（特殊小元素除外），不能用纯色块代替。
- **本轮已交付**：13 分区布局线框、5 件生图资产（底板/双球/槽框/轮盘）、一张 1920×1080 合成样张；正式实装与图标集未开始。
- **水印**：参考截图只用于测量，不进入仓库、不切像素；样张与线框均为重绘/生图产物，不含任何第三方水印或昵称。

## 四、组件规格

- **A**：虚线占位，仅实装期渲染一次静态框。
- **B 首领条**：**左对齐**，条长随怪物 `max_hp` 变化：`W = clamp(120 + max_hp × 0.115, 240, 720)`。W 达到 720 后不再增长；计算值超过 720 时右侧显示 `×N`，`N = ceil((120 + max_hp × 0.115) / 720)`，表示血条层数。条内红=当前 HP、暗红=掉血残影、紫=霸体/护盾；名字在条上方、类型标签（人形）在条左上；无目标 0.3s 淡出。
- **C**：进房名称淡入 0.4s；房间号随门切换刷新；FPS/计时只在调试开关下显示。
- **D**：四行固定顺序；**当前全部为占位值**，不与战斗数据绑定。
- **E/F**：胶囊内百分比 20px；低于 30% 呼吸红闪（仅 HP）。
- **G**：无经验系统时固定 0%，不伪造进度。
- **H**：左上技能等级、右下键位；状态 = 就绪 / 冷却（径向遮罩+秒数）/ 蓝量不足（蓝框）/ 禁用（灰度）；空格保持空槽。
- **I**：数量右下、冷却覆盖；空槽不可点。
- **J**：图标 + 底部 2px 剩余时间条；到期淡出。
- **K**：连击 ≥10 金、≥30 橙红；2.5s 未命中淡出。
- **L**：单行居中，与播报队列共用，避免叠字。
- **N 轮盘**：4 个圆钮（上左右下）+ 中央八边形；本轮**只做按钮与键位占位**，点击/悬停留空接口；后续接系统快捷（背包/属性/技能/任务）。

## 五、视觉规格

- **方向**：完全参考原图的藏蓝珐琅 + 古金浮雕；底板两端卷草纹、铆钉，槽位内凹，球体齿轮环 + 玻璃胶囊。
- **色板**：底板 `#141C26`（88%）、内凹 `#0B0F14`、古金 `#8A6B3A` / 高光 `#E2C07A`、文本 `#F0EADC` / 次 `#B7A98E`、HP `#C0262E→#E8453C`、MP `#2B6FB8→#4FA8E8`、评分金 `#E2C07A`。
- **生图约束**：纯黑底出图 → 边框连通域泛洪去底（保留内部珐琅）→ 按目标尺寸缩放；不允许用色键抠图（会吃掉暗部金属）。
- **字体**：暂用系统回退字体；正式版建议引入 OFL 中文字体（**待确认**）。

## 七、实装方案

- 节点结构（新建 game/scenes/hud.tscn，待建）：`CanvasLayer` → `HudRoot` → 分区节点；底部整组一个父节点做整体让位。
- 静态层 `NinePatchRect`/`TextureRect`；液面、冷却、条填充、文字用 `_draw` 或轻量子节点。
- 数据接口保留现有 `set_*`，新增 `set_exp / set_rank / set_buffs / set_party / set_items / set_skill_slots / set_wheel`（轮盘本轮空实现）。
- 技能格内容由 `skills.json` 的 `slot` 字段驱动，默认当前技能；玩家自定义后由存档覆盖。
- 键位：技能键 QWERTY/ASDFGH 与基础动作键分开注册，互不覆盖。
- 回归：`tools/run_demo.ps1 -Test` 369 项不得减少；1920×1080 与 2560×1440 截图各一张。
