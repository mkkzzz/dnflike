## 一、分工

| 工作区 | 负责 | 交付目标 |
|---|---|---|
| ws1 | 1～60 级世界内容。各等级段的城镇与区域、NPC、任务内容、副本、房间机制、怪物与领主、奖励与商店投放。已发布系统模块按本页边界维护 | 按地区交付任务、副本、结算、回城与后续衔接，在正式入口自行验收。龙人之塔是首轮工程样板 |

| ws2 原版资料供应 | 原版身份/加载关系调查、原始数据与依赖、规则说明、对照媒体、已知差异和工具发布 | 交接内容可从Git仓库/资源Release取得，不只存在本机或聊天中 |

## 三、战斗与流程的共同接口草案

以下保留为战斗与流程接口草案，共用接口及其集成由 ws2 维护。

| 方向 | 接口与字段 | 职责 |
|---|---|---|
| 流程→战斗 | 开始房间：run_id、room_id、角色战斗属性快照、技能/装备映射、实体出生记录、地图坐标契约 | 流程给数据，战斗初始化并保留长期 Profile |
| 流程→战斗 | 暂停/恢复、停止/卸载、合法属性或消耗品效果请求 | 只影响指定战斗会话；状态/资源校验有明确失败结果 |
| 战斗→流程 | monster_defeated：run_id、room_id、entity_id、原怪物ID及位置 | 击杀事件不直接发金币/经验；ws2按稳定事件ID提交收益 |
| 战斗→流程 | room_combat_finished、player_defeated：run/room标识、统计与角色状态快照 | 流程按事件判断门、领主、结算与回城，并管理存档 |
| 战斗→流程 | 战斗读视图：HP/MP、CD/Buff、角色/怪物状态与统计 | 战斗HUD消费；跨场景携带字段由Profile/Run规则决定 |
| 世界→战斗 | 地图根坐标、走区/阻挡、有效门区域、相机变换 | ws2提供世界查询或稳定数据接口；双方只转换一次高度/屏幕坐标 |

战斗计算伤害、命中和状态，流程管理装备与等级的持久数据，并提供战斗属性快照。
奖励、任务、背包和存档只有流程事务入口，防止战斗事件与结算按钮双重发奖。
正式流程经 `CombatSession.mount/start_room` 管理战斗；`main.tscn` 不提供单独试玩入口，只保留 headless 战斗内核回归和 act8 隔离测试夹具。外部管理模式不得自动出征、领奖或重开。
ws2 自行完成共用正式入口的成功、失败和重载验证。ws1 自行完成本区模块和正式地区内容验收。等级段闭环以同一条真实角色存档验证两线的衔接。

## 五、持续更新与当前缺口

原始数据变化 → 生成来源/依赖/字段变化记录 → 发布不可变资源版本 → 主仓库锁与任务入口更新 → 接收区本机校验 → 集成回归。
原版运行对照、实际生效PVF选择、服务端对应规则仍未全部查明；共享已有原文件不等于这些问题已解决。
新取得的设计/数值/录像当轮发布必要内容与复现入口，不把ws2变成每个文件都要人工转发的瓶颈。
所有工作区须遵循[游戏中文规范](15_统一风格与题材规范.md#游戏语言所有工作区)：不将韩文UI/名称/提示或原图内韩文带入游戏；新战斗HUD与内容包同样适用，保留原始档案不等于可直接上屏。
需要其它会话行动时，用户可将对应任务口令发送到该会话；本页更新本身不声称已发送或对方已接任务。
