# 统一风格与题材规范

2026-10-14。这是风格治理和换题材设计，不是已实现的“一键换皮工具”。入口：[美术全流程](14_美术资源全流程.md)。

## 一、四层分离

| 层 | 定义 | 例子 | 更改后影响 |
|---|---|---|---|
| 玩法语义 | 不依赖画风的功能和事件 | player.combo.1、skill.quick_draw、enemy.melee、hit.light | 改变需要战斗/系统设计 |
| 风格 profile | 画面共同的表现语法 | 描边、明暗、细节密度、相机、动画节奏、效果明度 | 全类型样板重新对照 |
| 题材 pack | 世界、角色、阵营、材质与装饰内容 | 当前暗色幻想；未来其他原创题材 | 重做受影响原画和声音 |
| 技术 contract | 引擎如何定位/播放/混合资源 | anchor、normal/add、action/effect clock、actor含武器 | 变更需导入适配/回归 |

稳定语义 ID 不用文件路径代替。版本、题材、profile 在任务元数据中描述；当前文件夹不强制搬迁，先登记外层映射，后续另做 resolver。

## 二、当前 profile：`handpainted_action_v1`

**已认可的核心方向：** 高清手绘横版动作风、清晰深色描边、赛璐璐主明暗加柔和渐变、轻微像素感。人物/剑共同发力；蓄势有重心，释放短促，余势收住。特效服务动作，不盖掉人物。

| 维度 | 共同规范 | 对照方式 |
|---|---|---|
| 轮廓 | 人物、怪物、交互物一眼能辨，外轮廓强于内部细节 | 实机尺寸缩略图、低饱和对照 |
| 描边/细节 | 清晰深色描边；小图保留大形，不能用复杂花纹填满 | 1:1 角色与 32/48/64 px 图标 |
| 上色/材质 | 有明确主阴影面、局部渐变；金属/皮革/布料保持同一光向和表现层次 | 同材质样板拼板 |
| 明度 | 角色在场景中可读；白热核心只短暂出现，背景不能同等刺眼 | 背景＋人物＋受击多层组合 |
| 色彩 | 使用题材与阵营 palette；玩家攻击、敌人危险提示、可交互项功能区分 | 不能只靠红/绿辨别，另用形状/动势 |
| 相机/比例 | 横版三分之四视角；地平线、脚底和纵深一致 | 同场站立玩家/怪物/门/道具 |
| 动作 | 起手/释放/接触/余势/恢复明确；刀手同方案 | 裸动作实速先于特效预览 |
| 光效 | 主刃缘/主体流光/少量副线层级清楚，短促消散，物质与光分开 | 暗/灰/亮底、多效果叠加 |
| UI | 延续材质与配色，但正文可读优先；动态信息不烘死 | 真内容、不同状态与缩放 |
| 后处理 | 历史 2px/40阶是局部旧加工参数，不是所有资产必须重复量化 | 记录每任务实际处理；不未经评审降低 V6 清晰度 |

这里不规定所有贴图都用同尺寸。具体数值按任务配置，方向性变更才需要用户选择。

## 三、当前题材包：`dark_fantasy_v1`

- 玩家身份：银白刺发红挑染、黑高领长衣红内衬、银扣、红绷带手臂、黑柄长刀。
- 主要材料：暗色皮革、布、墨钢与少量暖金属；场景为暗色哥特地下城。
- 初始敌人：已存在哥布林及队长，更多生态和区域需新设计。
- 当前基础攻击以冷银/蓝色刀光为基准；职业差异、元素和稀有度仍要配套规则，不推断所有技能已定色。

### 参照的优先级与批准范围

1. 当前角色身份参照：`art/characters/hero_cool.png`；怪物：`art/characters/goblin.png`；环境：`art/environments/dungeon_hall.png`。
2. 已认可的动作表现参照：`docs/previews/v6_art/`，范围仅四招及配套效果。动作认可不自动推翻身份设定，也不证明所有批次造型完全一致。
3. 一旦本轮源图与身份参照有差别，任务必须记录差别和用户接受范围。不能默默以“最新生成”替代全局标准。
4. 废弃旧蓝衣方案、历史程序几何预览和 V5 接入缺陷不能作为正式新批次模板。
5. 生成工具没有参考图输入能力时，明确是文字约束、存在身份漂移。不要称之为真正参考图生图。

## 四、一体化设计的批准门

量产之前先形成一个“同场基准板”，最小包括：

- 一个玩家标准立绘＋头像＋裸动作＋配套刀光/命中。
- 一个普通怪标准姿势＋攻击提示＋受击/死亡。
- 一个可行走房间（含门和互动道具），与前两者同相机。
- 一组技能/物品图标＋一个 HUD 区块，缩小到实际屏幕尺寸。

用户认可这组作为 style/theme 的批准范围，再批次生产。每个批次做拼板核对，换生成工具/模型、角色比例、光向或描边规则后重做小样，不直接沿用旧批准。

**不保证的能力：** 文生图自动保持跨图身份、仅靠固定种子保持风格、批量生成无需看图、外观变化不影响动作/判定。统一是依赖规范＋参照＋组合评审，不是提示词里写“统一风格”。

## 五、换题材是否好做

| 变化级别 | 典型变更 | 可保留内容 | 必须重做/复验 |
|---|---|---|---|
| T1 表现替换 | 同比例换角色配色、装饰、场景材质、FX色板 | 玩法语义、事件、合格契约、部分构图和配方 | 受影响原画、图标、颜色/可读性与组合批准 |
| T2 视觉体系更换 | 新时代/阵营/服装/武器外观，仍保留横版动作逻辑 | 系统循环、生产流程、多数事件/接口设计 | 角色动作、怪物、场景、UI、声音、依赖资源和锚点 |
| T3 玩法随题材改变 | 刀变枪/盾/长柄，体型大变、相机改变、新运动方式 | 可保留的系统和公共工作方法 | 新动作/轨迹/判定/事件、技术适配、比例与关卡、全面回归 |

因此：**流程建好后会更好改、更可控，但不是零成本。** 当前 V6 的剑在 actor 中，换武器外观至少重做相关 actor；仅替换独立武器 PNG 无效。静态图标/背景通常比人体动作和 Boss 技能更容易替换。

## 六、正式换题材流程

1. 写变更范围：只换外观还是改动作/玩法；列出保留项与禁改项。
2. 新建 `theme_pack` 版本，不覆盖当前已认可题材。暂存提案目录，例如 `docs/design/themes/<theme_id>/`，只有执行任务才创建。
3. 按总清单梳理依赖：立绘→动作→技能/FX→图标/HUD；环境→道具/怪物→危险提示；材质→音效。
4. 先做一个完整试点：玩家一刀＋一个怪＋一个房间＋一个 UI/图标组，验证新题材在同场中成立。
5. 用户批准方向；数值规格由 AI 填默认，不占方向确认环节。
6. 按范围批次生产、逐类校验，每批次更新任务和替换映射，不同时改无关资源。
7. 接入区按稳定语义 ID 切换整个获认可包，避免半套新人物配旧场景/旧图标。resolver 若尚未实现，先交明确映射表和适配任务。
8. 先保留旧文件、配置和批准证据；验证完成后标 `superseded`，不删除旧题材。回退由显式切换旧映射完成，不靠 Git hard reset。

## 七、跨资源依赖例子

| 主变更 | 必查下游 | 通常不用重做，但需确认 |
|---|---|---|
| 主角服装/手臂/体型 | 立绘、头像、全部 actor、职业 UI、技能图标、宣传/预览、碰撞比例 | 固定语义事件、任务剧情 |
| 武器外观/类型 | 握法、actor、轨迹/接触、FX、图标/掉落、材质声音 | 同玩法的系统奖励与存档 ID |
| 某技能表现 | actor子集、起手/释放/命中/结束、图标、声音、实际判定窗口 | 未关联的待机与城镇 |
| 区域材质/透视 | 房间、地块/门/道具、环境FX、怪物相机/明度、环境音、缩略图 | 无变化的玩家操作规则 |
| 怪物生态/体型 | 设定、全部动作、危险提示、受击/死亡、碰撞/掉落显示、任务头像 | 未关联的玩家基础立绘 |
| UI 主题 | 面板状态、字体/按钮、图标框、HUD可读性、缩放/本地化 | 已认可世界动作与碰撞 |

每个换题材任务必须列出实际依赖，不机械重做全游戏，也不漏改仍引用旧设定的下游。
