# 美术资源全流程

日期：2026-10-14。性质：**统一生产与交接设计规范，尚未实现通用资源管理器**。适用两工作区的角色、技能、特效、场景、怪物、物品和 UI 资源。

关联：[风格与题材](15_统一风格与题材规范.md) · [全量资源清单](16_美术资源总清单.md) · [单项任务模板](17_美术资源任务模板.md) · [V6 已认可资源交接](13_V6动作资源与实装待办.md)。双区同步规则见根目录 `AGENTS.md`。

## 一、目标和边界

- 每个资源都有稳定身份、需求、参考、源文件、加工配置、预览、批准记录和实装待办。新增和修改都能追溯，不靠回忆复刻。
- 将“画风”“题材”“玩法语义”“导出技术格式”分开；以后换题材不从头重写生产过程。
- 当前工作区继续设计。文档可制定未来工具/接口，但不能把提案写成已实现能力；资源生产和实装另按用户任务执行。
- 现有 V3/V4/V6 是不同版本和局部管线，不假装已成为一个通用 manifest。统一公共元数据采用外层任务记录，既有 manifest 暂由接入区适配。
- 当前选择序列帧作为动作/战斗特效的优先成品；静态立绘、图标、场景仍采用各自格式。

## 二、共同流程（每类资源都必走）

| 阶段 | 要做什么 | 必须留下的产物 | 通过条件 |
|---|---|---|---|
| 1 需求登记 | 明确用途、范围、数量来源、依赖、是否替换已实装资源 | 按模板创建资源任务、稳定 asset ID | 功能语义和完成范围可判定 |
| 2 风格/规格 | 选定风格版本、题材包、已认可参考；定义画布/锚点/层级/时钟 | 参考列表、技术规格、批次目标、禁用项 | 不存在相互冲突的参照或技术假设 |
| 3 样张设计 | 先少量代表样张/关键动作/小场景板；记录真实生成或绘制方法 | 源图、完整提示词/配方、实际参考输入、弃用理由 | 人工看图；基本构图、身份、发力和风格成立 |
| 4 源图认可 | 用户选择方向或接受已有同类型样板 | 明确批准范围、日期、版本 | 没获认可不批量铺内容；小修改可按既有批准范围迭代 |
| 5 成品加工 | 切帧、抠图、标定、分层、烘焙、切片；采用类内统一规格 | 完整源图、配置、命令、导出包、manifest/切片表 | 能离线复现，导出不缺失、不裁切、不猜帧序 |
| 6 技术校验 | 检查格式、锚点、透明混合、事件/时间轴、引用和左右方向 | 自动检查报告及人工核对图 | 检查真实退出码；问题解决或有明确批准的豁免 |
| 7 成品预览 | 从导出包直接回放；放进相同基准场景/界面作组合对照 | 原比例、实速、细节图、必要慢放/裸动作 | 用户认可成品；风格对齐与技术通过分别记录 |
| 8 发布交接 | 打包说明、版本、依赖、适配点、实装与验收待办 | 自包含任务包、commit/远程发布信息 | 按 AGENTS 自动提交推送，远程可获取 |
| 9 实机接入 | 接收区同步、导入、绑定语义 ID、碰撞/事件/时钟/布局适配 | 接入改动、配置映射、实机录像和日志 | 在接收区运行，不在设计区冒充已完成 |
| 10 实机验收 | 与获认可预览逐项对比，测不同状态与回归 | 实机批准、问题单或退回任务 | 功能和表现都通过才升级为实机完成 |

出图次数和输出 PNG 数量不是完成标准；文字说“参考了”不等于生成器确实接收了参考图片。

## 三、状态与批准记录

任务按版本记录：`planned → spec_ready → source_review → source_approved → baked_validated → preview_approved → integration_ready → integrated → runtime_approved`。

- `blocked`：记录阻塞原因和安全恢复入口；`rejected`：保留弃用原因；`superseded`：指向替代版本。
- 草案/候选也可以提交，提交不是批准。批次源图认可可以覆盖同规格任务，但需写明覆盖清单，不能无限扩展。
- 新变更另开 revision，旧版批准不自动继承；临时实验不得覆盖已批准版本。
- 交接发布与接收区同步分开记录；远程推送不等于对方已 pull，更不等于已接入。
- 自动检查和用户审美结论分开。允许用户明确接受已知限制，记录具体限制而不是伪造测试通过。

## 四、资源任务的共同记录

每个任务至少包含以下内容，详见模板：

- `asset_id`：稳定功能语义，不带主题色、题材名和文件版本；`revision`：本资源迭代。
- `asset_type`、`scope`、`style_profile`、`theme_pack`、`contract_version`。
- 真实依赖 ID 和版本；`replaces`；受影响的动作、图标、UI、特效、预览及接收区文件。
- 参考文件与批准依据；来源/权利、生成能力、完整 prompt/负面约束/配方、实际工具版本和参考输入。
- 源文件、标定、加工配置、命令和依赖版本；随机种子若工具未提供就写未知。
- 导出入口、路径基准、尺寸、透明度、锚点、时钟、朝向、循环、事件；旧格式写清适配。
- 检查结果、预览路径、批准范围、实装/回归待办、发布/接收状态。

记录位于任务文档，源图和加工记录放资源目录。正式交接不能依赖 `temp/`、某台机器的隐藏路径或已经过期的下载 URL；凭证永不写入记录。

## 五、各类型的完整生产路线

### A. 角色/NPC/职业立绘与头像

**角色设定 → 身份与材质板 → 标准立绘 → 表情/转面样张 → 用户认可 → 头像/半身/全身裁切 → 场景与 UI 对照 → 技术检查 → 交接。**

- 输入：角色功能、年龄/体态/服装/武器/辨识点，当前题材和基准参照；先锁定正面、三分之四面、侧面和关键背面需要。
- 产出：无特效标准全身、颜色/材质板、需要的表情头像与半身；记录裁切区域和缩略图。
- 规格：头像示例 256×256、立绘示例长边 1536，属于可调默认值；不同用途不能硬塞进同一动作画布。
- 验收：同角色跨用途身份一致、脸和手不扭曲、轮廓清晰、裁切无误、实际 UI 缩小后能辨认。
- 修改角色外观需连带动作、技能图标、职业 UI、宣传图；不能只换立绘就说角色全部换题材。

### B. 玩家基础动作与技能动作

**动作意图/帧表 → 分相位动作板 → 持械关键原画 → 用户认可裸动作 → 补帧/校准 → actor 导出 → 同步刀光/接触事件 → 实速与慢放预览 → 交接/实机验收。**

- 输入：武器握法与尺寸、髋肩发力方向、起手/释放/接触/余势/恢复、前冲/浮空/取消与循环要求。
- 固定武器默认人物和武器一体原画；需要换武器/时装则先设计手腕轴、指遮挡和服装/武器分层，再批量生成。两条路线不得混用。
- 真实源姿势显式映射，不假定 3×2 或 4×4 排列；记录生成器多画/少画、重复/弃用帧。
- 类内固定解剖比例、root、画布；跳跃以虚拟地面 root 记录高度，不逐帧把最低鞋底吸回地面。
- 动作出图须绑定已认可原画的人工比例标尺与源图哈希；每张源表带同尺度直立基准，每个姿态检查头部尺度。不能用“约几头身”的 prompt、颈部最窄行估计、蹲姿外接框或手猜站高代替。鬼剑士导出门禁与例外边界见 [18](18_角色锚定与动作管线.md)；缺检查或超差的源图先退回，不批量、不实装。
- 输出包含语义动作、整数 duration_ticks、原画来源、可见握点/护手/刀尖、移动参考、循环与事件。基础动画不烘命中停帧。
- 验收先无特效实速，再看不同朝向、站立/跑/空中/接续与取消；人物不变形、握法不切手、剑与身体共同发力。
- 已有入口：`tools/bake_seq_v6.py`、`tools/test_seq_v6.py`、`tools/preview_v6.py` 仅覆盖当前四招；不是任意新动作的无配置万能命令。

### C. 技能表现完整包

**技能功能定义 → 统一相位/事件板 → 演员动作＋武器/召唤物＋轨迹＋命中＋状态＋图标 → 各部件校验 → 同场完整预览 → 用户认可 → 成套发布。**

- 必须列出 cast/windup/active/contact/recovery/loop/stop 等真实事件；“只有一张大刀光”不算技能包完成。
- 每个实际需要的部件登记依赖：起手、释放、投射物、尾迹、命中、持续区域、buff、结束、图标和音效事件。不存在的部件写不适用。
- 角色和刀光沿同一动作时钟；实际命中才开接触特效；连击段独立触发，不用每帧重复生成。
- 验收：挥空、命中、打断、连续释放、不同目标尺寸、近远距离与左右朝向；重复声音、特效泄漏和过度遮挡必须检查。
- 表现时间改变可能影响玩法窗口；先做影响分析交接，不能用“只是换素材”绕过战斗同步。

### D. 刀光/受击/投射物/状态/环境特效

**功能语义与可读性 → 颜色/形状/时长板 → 单效果样片 → 用户认可 → 前后/光强/物质分层烘焙 → 背景与组合回放 → 交接。**

- 刀光来自已认可可见武器轨迹；受击以真实接触点为锚；落地以落点；投射物以前进轴/速度为输入；buff 要声明 target-local 或 world-fixed。
- 输出分别声明 normal/add、straight alpha、锚点、是否随目标、方向、循环/start/stop；长一闪不塞进短命中画布。
- 刀光冻结动作时钟；受击/尘烟等特效时钟通常继续；持续状态在结束/死亡/换场时明确清理。
- 黑/灰/亮背景检查透明度与色边；前后景检查遮挡；多次叠加检查过曝与轮廓可读性。
- 物质层（灰尘、碎石、血滴等）不得只导出加法而丢失；已有光强不能又被 alpha 重复削弱。
- 程序生成可复用配方，但全游戏统一颜色/材质规则需要人工对照，不靠固定随机种子保证风格。

### E. 怪物/精英/Boss/NPC 世界动画

**生态/战斗职责 → 轮廓与比例 → 标准设定 → 行动与受击动作板 → 怪物＋武器同帧/分层设计 → 导出 → 与玩家同场对照 → 用户认可 → 接入 AI/事件。**

- 输入：物种/阵营/材质、玩家身高比例、攻击读条/危险区、攻击方式、受击/浮空/倒地/死亡机制。
- 普通怪至少审查待机、移动、攻击、受击、死亡；浮空/倒地/起身、转身与特殊技能按实际玩法登记。
- Boss 每个攻击登记起手提示、危险区、命中/结束与阶段切换；不能默认把普通怪放大就完成 Boss。
- 验收在与玩家相同相机和光照中做，注意体型、脚底、攻击可读性、玩家不会被完全遮挡；不能复用哥布林固定碰撞 ROI 作为所有怪物规则。
- 静态 NPC 可少动作，但头像、立绘与世界 sprite 身份必须一致。

### F. 场景/区域/城镇/房间/地块

**区域叙事与功能 → 色光气氛板 → 一间基准房 → 可行走平面与地标 → 前中后景拆分 → 连接/地块/道具 → 实比例拼装预览 → 技术/可读性验收 → 交接。**

- 输入：题材区域、相机、地面/景深、入口出口、碰撞/遮挡位置与可复用模块。
- 输出按背景、远景、中景、前景遮挡、地面、门/过渡、互动点、环境效果分类；纯装饰与游戏碰撞分开标记。
- 先锁定透视地平线和光源，再批量房间；不用每张不同角度的整图强行拼接。
- 默认参照 1280×720 实机视口，但房间宽度、卷轴安全区和拼装块可配置；不是每图都简单缩放为屏幕大小。
- 验收：移动/卷轴/出入口对齐、拼缝、角色脚底不悬空、敌我可读、前景不挡提示和交互、不同房间统一材质。
- 当前只有地下城基准背景，模块化场景导出器和房间数据契约需要后续实现；这里只设计，不声称已有。

### G. 武器/装备/物品/掉落与交互道具

**玩法分类与装备外观范围 → 功能轮廓板 → 原画 → 小图标＋世界显示＋可装备版本 → 用户认可 → 批量化/切图 → 清单校验 → 交接。**

- 输入：物品语义、稀有度规则、材质、职业/武器握法、是否真实改变身上外观。
- 图标示例原图 256、实际 64/48/32；须在最终尺寸看，不能只看大原图。框/稀有度角标尽量是 UI 公共层。
- 世界掉落/道具声明锚点、轮廓、交互/破坏/打开状态；装备图标和可穿外观不是同一个资源。
- 替换剑为枪、盾或长柄武器要检查 actor 内嵌武器、动作、接触范围和音效；非换图标即可完成。
- 后续换装需套件兼容矩阵，当前不承诺所有外观自动适配 V6。

### H. UI/HUD/菜单/字体/标识

**信息架构 → 低保真布局 → 风格样板与状态 → 图标/底板/九宫格/字体 → 容器与内容长短检查 → 成品切图 → 实机回归。**

- 输入：界面用途、分辨率缩放、信息优先级、普通/悬停/选中/禁用/警告/冷却状态。
- 输出：布局规格、组件状态、九宫格边距、atlas rect、字体来源与回退、头像/技能/道具图标映射。
- 不把动态数值、冷却、血量和文字烘进静态底图。文字识别/本地化、缩放、色弱辨识按需要验证。
- 要在带真实角色、场景和战斗效果的屏幕上对照，避免单看“漂亮界面图”掩盖遮挡与可读性。
- 已有 HUD 为局部程序绘制与头像接入；旧 `bake_hud.py` 不是全 UI 的正式风格模板。

### I. 音效/环境音/BGM（配套资源）

**事件/材质意图 → 声音风格样本 → 试听认可 → 无损母版/循环/变体 → 电平与时长校验 → 与动作事件合成试听 → 交接。**

- 与美术共享题材/材质/相位，不把 WAV 当视觉帧；技能包中记录声音依赖，不要求本轮新增音频。
- 合成需配方和种子；外部素材需来源/许可。循环检查接缝；音效变体不改变事件语义。
- 旧原创拟音有可复用配方，BGM/环境音的完整批量方案尚未完成。

## 六、统一导出约定（设计目标，按类型适配）

1. 目录使用仓库相对路径，入口明确路径基准；保留源/生成记录/标定/导出/验证/预览，发行任务说明用到哪些文件。
2. 静态资源 RGBA/RGB、动画统一动作时钟 60 Hz 与整数 duration_ticks；帧条/atlas/逐帧格式都需声明布局，不靠文件名猜。
3. alpha 模式、混合公式、色彩/导入设置、锚点、方向、单位、loop 与层级属于资源契约，改变时写适配/迁移任务。
4. 各类同规格批次共享尺寸规则，跨类型不强行统一画布；裁切需 trim_offset，翻转需锚点同步。
5. actor 包含武器与否必须显式标记；运动参考与物理位移分开；视觉变化若影响判定需复验。
6. 未来的主题 resolver、统一验证器、依赖图和批量生成调度器目前只是设计，不新增不存在的命令或声称已自动化。

## 七、复用、修改与迭代闭环

- 复用已有批准：列出复用 ID/版本/批准范围，仍要在新组合里预览；不把同图复制当新原画。
- 局部修改：从最近可复现版本新开 revision → 分析依赖 → 改源或配方 → 重烘受影响资源 → 旧新对照 → 新批准 → 发布 → 接收区回归。
- 失败定位：先源姿势/功能意图，再标定/分层，再导出/时钟，最后实机绑定；不能用更亮的特效遮住发力或碰撞错误。
- 复盘写入任务“原因/防复发检查”并按需要更新本规范；不只写“这轮好了”。
- 换题材按 [15](15_统一风格与题材规范.md) 的试点和依赖流程，不直接覆盖当前已认可资源。

## 八、每项交付的验收勾选

- [ ] 资源身份、用途、风格版本、题材和依赖明确。
- [ ] 真实工具能力、参考输入和来源记录可核对。
- [ ] 成品与源及配置完整入库，离线可复现，无 `temp/` 依赖。
- [ ] 类别必需的动作/状态/层级/时钟/锚点与透明度齐全。
- [ ] 有技术报告，也有实际看图/试听的组合对照和批准。
- [ ] 本轮修改范围、已知限制、接入区待办和实机验收目标明确。
- [ ] 相关文件已 commit/push，接收区需先 pull；没有将未执行步骤勾为完成。
