# 回城交易、分解与耐久服务

沿用“先补功能，玩法循环和精确数值后定”。依赖[35物品所有权](35_物品背包与掉落拾取.md)、[32数值](32_数值与等级系统.md)和[34城镇](34_城镇联通与赫顿首批.md)。当前收费、材料、磨损参数均为E-ADAPT，不声称原版平衡。

## 入口与边界

NPC交谈后点“物品服务”，单击右侧背包或左侧穿戴格选择目标。林纳斯/辛达可出售、回购和修理；卡妮娜可交易；诺顿可交易和分解。服务仍需回城、靠近对应NPC，纯Session入口也检查权限，不只隐藏按钮。

本轮不扩展NPC商品库，不加入强化成功率、附魔材料费、制造或复活。原装备整备/技能管理入口保留。

## 交易与所有权

- 出售按选中编号和数量处理；穿戴、仓库、待领取区和锁定物品不能卖。每次确认显示所得金币，取消不改变物品。
- 完整出售保留原实体编号；部分出售堆叠时创建独立售出堆叠，背包只减所选数量。
- `profile.services.buyback` 持有售出物，仍保存在gear/stacks实体表，但不计入随身数量；35所有权校验把回购区纳入唯一归属。
- 回购按原成交总价取回同一实体，品质、强化、附魔、耐久都不重抽。当前需要背包空格，不自动合并回购堆叠。
- 同角色最近20笔、跨交易NPC共用且保存后仍可回购；超出容量时最早一笔及其实体清除，窗口明确提示。调整容量不会使旧记录无法读档，下次出售按新容量收口。
- 完整交易在候选副本上完成；背包满、金币不足、目标变化或保存失败，整个操作不提交。

## 分解

只处理配置支持、位于背包且未锁定的装备。确认页显示原装备消失、不能回购，以及具体材料与数量。

分解删除该装备实例，再将配置材料放入普通材料背包。容量检查包含现有堆叠余量；材料放不下时恢复原装备、编号、金币和全部堆叠。材料“铁质碎片”当前为功能样本，原生图标来自原STK，未来养成消耗另接。

## 耐久与修理

- 新装备保存 `durability_max`、`durability`、`wear_progress`；旧档缺少字段时补满耐久。每件装备的上限随实例保存，调默认值不重写已持有装备。
- 默认满耐久40；每20次对怪造成正伤害减武器1耐久，每10次受到正伤害减其它穿戴装备1耐久，实际战败额外减穿戴装备3耐久；撤退不触发战败扣损。
- 磨损来自公开 `combat.damage` 事实，按冒险及event_id去重。忽略零伤害与过期冒险；不改战斗AI、动作或内部状态。适配桥通过延后调用提交档案。
- 耐久归零仍保留装备和外观；数值层跳过该实例的基础、强化、附魔和套装贡献。武器伤害和防御变化通过公开update_numbers同步到真实战斗。
- 修理所选支持背包/穿戴装备；“修理穿戴”一次处理所有受损穿戴部位。锁定装备允许修理，不解除锁定。
- 费用为每件缺失耐久×配置单价，先完整报价再确认；满耐久不收费，金币不足不部分修理。修理后属性恢复。
- 正常服务写盘失败不改变活跃角色；真实战斗磨损保存失败会提示，当前这次候选磨损不提交，后续进度仍按现有存档恢复规则处理。

## 配置与事务

配置唯一入口[services.json](../../game_dnf/data/services.json)：回购容量、默认上限、命中/受击阈值、战败扣损、各物品卖价/修理单价/分解产出。启动用[检查器](../../tools/check_dnf_services.py)校验正整数阈值、价格和材料类型，非法配置不启动。

`items/services.gd` 提供 quote/command/wear/valid；服务确认携带当前实体与价格的指纹、稳定事务编号。目标或价格变化必须重新确认，重复提交不能重复付钱/发材料。`loop_root.service_action` 先检查实际NPC、写入完整候选，再替换活跃Session。

存档升级为 `dnf_loop_save/4`，继续读取1/2/3。旧目录不覆盖，保持原子写与有效备份恢复。新增目录项的零数量视图可补齐，非法归属、售出编号、交易记录或耐久拒绝读取。
