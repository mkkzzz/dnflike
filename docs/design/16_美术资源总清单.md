# 美术资源总清单与依赖台账

2026-10-14。用途：按项目功能穷举需要登记的美术类型，给新增、修改、换题材提供入口。**这是设计台账，不是“所有资源都已完成”的证明。** 每个具体角色、技能、房间、物品按本表创建实例任务，数量由对应功能设计决定。

入口：[全流程](14_美术资源全流程.md) · [题材规范](15_统一风格与题材规范.md) · [任务模板](17_美术资源任务模板.md)。

## 一、资源身份和拆分规则

- 语义 ID 设计为 `<type>.<subject>.<purpose>`，例如 `actor.player.base.combo.1`、`fx.hit.light`、`scene.region_a.room.entry`。ID 不嵌入红蓝配色、题材名或文件版本。
- `subject` 是玩法角色身份，不是立绘里的名字；展示名由题材提供。改变动作语义不能仅沿用 ID 换个不同功能。
- 每个实例在任务记录中绑定 `revision`、`style_profile`、`theme_pack`、资源契约和依赖；当前旧资源可保留路径，用映射记录对应语义 ID。
- 静态立绘、动作和图标是不同实例；一个技能任务可以成套交付，但各组成资源必须有 ID 和缺失/不适用状态。
- 用于运行的同姿势引用、同 PNG 多次播放不算新原画；统计“源姿势/独立成品/播放片段”分别列出。
- 下表 workflow 对应 14 文档第五节 A–I。P0 当前核心表现/交接，P1 第一版闭环，P2 扩展；优先级不意味着立刻生产。

## 四、依赖图与修改范围

- 玩家身份 → 立绘/头像/actor/职业UI/宣传。
- actor（含武器）＋相位表 → slash前/后层＋接触/落地事件 → 技能组合预览。
- 怪物设定＋机制 → 动作/武器/危险提示/受击与死亡 → 关卡组合。
- 区域设定＋透视/材质 → 房间/门/道具/环境FX/怪物明度/环境音 → 同场基准。
- 技能语义 → actor/FX/图标/声音；物品语义 → 图标/掉落/装备展示/UI。
- UI profile → 公共组件/字体/品质框/状态；具体技能和物品只填内容，不重造风格。

依赖变更时将下游标为“待复验/待重烘”，不用自动把上游未改变的全部任务都重做。源码、配置、参考变化都算依赖，不只统计PNG。

## 五、新增与局部修改操作

### 新增一个东西

1. 找总表对应类型，确认功能语义，创建唯一 asset ID 或技能/区域任务包。
2. 用模板填写风格、题材、需求和类内规格，列出已有可复用依赖与缺失项。
3. 按该路线做小样→批准→加工→技术报告→从导出包回放的预览。
4. 批准后发布交接，实装区只更新本任务映射和必要依赖，验证后登记实机完成。

### 修改一个东西

1. 定位当前批准版本，不覆盖它；建立新revision并说明变更原因。
2. 检查依赖图：例如只改火花颜色可重烘hit，不用重生全部角色；改握法则actor/slash/接触都要复验。
3. 交付旧新对比与明确替代清单，保留旧版可回放；新版批准后切换映射。
4. 接入区验证未受影响内容仍正常，更新接收证据；失败回退显式旧版本而非删库/重置。
