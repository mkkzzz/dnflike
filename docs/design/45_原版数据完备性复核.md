# 45 原版数据完备性复核

> 起因：使用者指出「原版本体的所有内容、数据肯定都有迹可循，没有的话游戏跑不起来」。
> 本文逐条复核此前得出过的「没有数据 / 不可解析」结论，记录**错在哪、正确结论是什么、证据在哪**。
> 原则：**先穷尽 pvf 内的证据，再下结论**；任何「不可读」都必须写明试过哪些路径。

## 一、已确认的错误结论（全部推翻）

### 1. `.act` 动作脚本「字段为空」——错

| 项 | 内容 |
|---|---|
| 曾经的结论 | `.act` 的 `[MOTION]`/`[TRIGGER]`/`[BEHAVIOR]` 都是空数组，是空壳 |
| 实际情况 | `.act` 与 `.ai` **同一种字节码格式**：`b0 d0 05` + 4 字节基址（`.ai` 常见 508、`.act` 常见 852）+ 5 字节定长指令 |
| 错因 | 旧脚本按 `[TAG]` 文本字段解析二进制，自然全空；不是文件没内容 |
| 证据 | `monster/goblin/action_goblin/attack1.act`（62 字节 / 11 条指令）解出 `op05 853 / op07 301397 / int 100 …` |
| 修正 | `tools/parse_dnf_ai.py` 已支持 `.act`（`--act`），全库 18371 个 `.act` 可反汇编 |

### 2. 召唤「没有数据」——错

| 项 | 内容 |
|---|---|
| 曾经的结论 | `.mob` 无 summon 字段、`summoncage.ani` 无事件，故召唤无法实现 |
| 实际情况 | 召唤逻辑在 **`summon.act`** 里（如 `monster/newmonsters/realsky/mirkius/action/summon.act`，507 字节 / **100 条指令**） |
| 错因 | 同上——只找了 `.mob` 的文本字段和 ANI，没解 `.act` |
| 证据 | `summon.act` 含 `op05 1747 / int 61523 / op05 712 / int -20 / int -300` 等参数块 |
| 待办 | 语义仍需解（`op05` 的目标是动作还是生成物 ID） |

### 3. `.ai` 「自定义 VM 不可执行，只能重写」——错（当时结论过强）

| 项 | 内容 |
|---|---|
| 曾经的结论 | 字节码无法解析，只能按行为重写 |
| 实际情况 | 结构规整：`b0 d0 05` + 4 字节基址 + **5 字节定长指令**，参数类型可判（`0x02`=int32、`0x04`=float32、`0x05/0x07/0x09/0x0a`=索引） |
| 证据 | 去掉 7 字节头后长度恰为 5 的整数倍（272→53 条、587→116 条、22→3 条）；全库 6966 个 `.ai` + 18371 个 `.act` 中 17347 个解码成功 |
| 尚缺 | opcode **语义**（哪个是条件、跳转、播放、生成），不是格式 |

### 4. HP / 攻击「基准值不可读，是引擎常量」——错

| 项 | 内容 |
|---|---|
| 曾经的结论 | `monster_base`（160 HP / 20 攻）只能估，pvf 里没有 |
| 实际情况 | 真源是 **`monster/monsterbaseparameter.tbl`**：1099 整数 = **11 列 × 99 行**，全部单调递增 |
| 证据 | 列 7/9 = `150 / 300 / 450 / 600 / 750 / 900 …`（等差 +150，按等级区间递增）；列 4/5 = `50 / 74 / 101 / 133 / 168 / 207 …`（二阶递增，推断为经验）；列 1/3 = `0 / 5 / 11 / 17 / 23 …`（等级区间） |
| 错因 | 只解析了 `boss/common/named/summon/chaos` 五张表，**漏了总表 `monsterbaseparameter.tbl`** 与 `monsterapcdifficultybonus.tbl` |
| 待办 | 用该表替换运行时的 160/20 假基准（需先验证列含义，见第三节） |

## 三、仍未定论（下一步必须解，不能再当「没有」）

| 项 | 现状 | 下一步 |
|---|---|---|
| `.act`/`.ai` 的 opcode 语义 | 已知 `0x02`=int、`0x04`=float、`0x0a`=音效/字符串 ID（`die.act` 的 `0x0a 298848` 与 `.mob` 的 `[speech on situation]` 一致）；`0x05`=动作/状态、`0x07`=事件/效果（301397/301398/301399 连续）、`0x09`=条件 | 用 `passiveobject.lst`/`effect` 反查 `0x07` 的 ID 段，用 `.act` 与 `.ani` 同目录同名建立动作 ID 表 |

| `.tbl` 24 列中未用的 20 列 | 只用了 level/hp_pct/attack_pct/def 四列 | 逐列做单调性与取值分布分析，与 `.mob` 字段做相关 |

## 四、方法论教训

1. **二进制文件先看魔数与长度**：`b0 d0 02/04/05` 三种魔数分别对应 int 表、float 表、脚本；长度减去 7 字节后是否整除 5，能直接判断是否定长指令流。
2. **同一扩展名可能有两种解码路径**：`.act` 被旧脚本当文本字段解析，这是所有「空壳」误判的根源。
3. **「查不到」要区分三种情况**：路径写错（ANI 目录）、解析器不支持（`.act`）、真的没有（目前尚无确证案例）。
4. **表要查全**：`monster/` 下 8 张表，漏一张就得出「基准值不存在」的错误结论。
