# 消耗品冷却与死亡恢复

承接[35物品](35_物品背包与掉落拾取.md)、[37耐久](37_回城交易分解与耐久服务.md)及[29战斗接口](29_新版工程框架_接口契约.md)。冷却、恢复量、初始复活币数量和每次冒险复活次数上限为 E-ADAPT；复活币图标、使用动画、粒子与音效使用原版资源，不冒充完整原版经济。

## 当前交付边界

正式可用：药剂统一使用、物品/分组共享冷却、HUD倒计时、死亡记录原子保存、失败重试、死亡后原地复活或返回城镇、读档恢复。

死亡后画面中央显示复活提示：按 X 消耗 1 枚复活币原地复活，或点击“返回城镇”。复活币余额、本次冒险已复活次数、恢复比例和保护时间同时显示。原地复活会回到同一间房，保留怪物、血量、掉落、已完成进度和冒险时钟；外层写盘成功后才调用战斗恢复。

## 消耗品

- 配置唯一入口[recovery.json](../../game_dnf/data/recovery.json)。每种物品定义等级、单品冷却、共享组/组冷却与公开效果；当前只有既有恢复药剂，沿用原图、价格和物品身份。
- 数字快捷键和鼠标快捷格统一调用 `Session.use_consumable`，只消耗未锁定的背包堆叠。仓库、待领取区、空库存、等级不足、满血、死亡、暂停、菜单及过期冒险快照均不消耗。
- 共享组与单品两个截止时刻都满足后才能使用。同一药剂绑定多个格子不能绕过冷却，HUD对应格同时变暗并显示剩余秒数。
- 冷却使用 `combat.read_view().time_ms` 的模拟时钟，暂停不减少；同一次冒险的切房保留，新冒险重置。读档不恢复中断战斗，因此不保留已结束冒险的冷却。
- `run.consumables` 保存单品/组截止时刻及使用事务，拒绝重复提交。外层先预检公开效果，再同步写完整候选，成功后才治疗；保存失败不消费、不治疗、不启动冷却。恢复提示显示实际补充量，不把超出上限的部分当作已治疗。
- 公开效果预检与应用之间不等待或推进模拟。若已确认且保存后的效果仍被战斗端异常拒绝，保留已提交效果供同会话重试，重试不再次扣费；中断战斗仍按既有回城策略，不提供运行世界快照或回退保护。

## 死亡与放弃

真实 `combat.player_defeated` 经延后调用进入外层候选。按run/event_id记录死亡，耐久扣损一次，进入 `defeated` 状态；此时不写通关奖励，也不提前将冒险登记为settled。

死亡保存失败时，活跃角色保留原耐久/账目，战斗保持真实死亡画面，窗口提供“重试保存”；原事件保留至提交成功。普通保存也必须先提交该事件，不能绕过死亡事务。提交后才开放放弃操作。

“返回城镇”先原子结算无奖励失败，再按既有入口返回实际城镇位置；已经领取的物品、金币和任务进度保留，未领取掉落遵循35。退出/回城/撤退也改为候选写盘后再切换状态，失败可重试。

不重复处理相同死亡事实；旧死亡事件在未来复活后重发也不能再扣耐久。主动撤退仍不按死亡扣损。

## 原地复活

纯规则 `Recovery.quote/revive` 对待处理死亡报价，检查复活币余额、次数、目标指纹和事务。报价返回 `coin_cost`、`coins`、`affordable`、已用次数、恢复比例与保护时间；每次成功交易只扣 1 枚复活币并清 pending，回到相同 run。新角色和缺少该字段的旧档默认获得 3 枚复活币；初始余额与每次冒险最多 3 次是 E-ADAPT，后续经济系统可替换。

战斗协议 `combat.can_revive(spec)` / `combat.revive(spec)` 绑定 run、room、death_id，保留怪物/房间/掉落与冒险时钟，重建玩家并恢复 HP/MP 百分比，清除死亡和临时效果，保留技能冷却并给短暂保护。外层写入候选存档成功后才调用；战斗端拒绝时不重复扣币，外层保留 `pending_effect` 供同会话重试。

美术与效果入口为 `tools/bake_dnf_revive_assets.py` → `game_dnf/assets_local/revive_v1/`：

- 复活币图标：`sprite/Item/IconStackable.img` 帧 5；
- 复活币旋转：`common/etc/animation/usecoin.ani` + `sprite/Common/Etc/UseCoin.img`；
- 粒子：`common/etc/animation/usecoinparticle.ani` + `sprite/Common/Etc/UseCoinParticle.img`；
- 音效：`sounds/ui/coin_in.ogg`；
- 布局参考：`ui/usecoin/usecoinwindow.ui`。该窗口是深渊模式专用，普通死亡提示改用现有原版窗口框与中文文字，因此不声称逐像素复刻该 UI。

复活特效放在战斗视图的独立 CanvasLayer 上，使用原版 34px 币和 19px 粒子，不放大；单帧推进上限 50ms，避免真实帧卡顿一次跳过整段效果。截图见[复活提示](../screenshots/revive_prompt_20261031.png)。

## 存档与验证

格式升级 `dnf_loop_save/5`，继续读取1/2/3/4；新增run字段先验证结构、有限时刻、次数与去重记录。死亡待选择的存档重读时，由于没有运行世界快照，结束为无奖励失败结果；不重复扣耐久或复活费。中断的普通战斗仍安全回城。

```powershell
tools/run_dnf_loop.ps1 -Test -RecoveryOnly
python tools/bake_dnf_revive_assets.py --check
python tools/check_dnf_recovery.py
python tools/test_dnf_recovery_config.py
```

`RecoveryOnly` 现在验证药剂、真实死亡保存失败重试、按 X 扣复活币、同房复活、怪物/血量/位置保留、复活特效计数、第二次死亡后返回城镇及读档；独立战斗 `run_dnf` 验证战斗 API 的 HP/MP/保护与 stale death_id 拒绝。状态和数量见[看板](../project/01_进度看板.md)，本轮交付见[报告](../reports/ws1/2026-10/2026-10-31_原地复活与复活币提示.md)。
