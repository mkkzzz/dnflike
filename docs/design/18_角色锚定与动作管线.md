# 18 角色锚定与动作管线

2026-10-15。状态：**方向已收敛，标准路径待首轮测试确认**。本文汇总 2026-10-15 的讨论结论，过程记录见 [技术探索](../reports/ws1/2026-10/2026-10-15_角色锚定与动作管线技术探索.md) 与 [S2 第二版](../reports/ws1/2026-10/2026-10-15_S2第二版_3D驱动动作精修.md)。

## 一、要解决的问题

1. 同一角色的所有动作外观要统一。V6 四招是文字生图逐张生成的，已经出现身份漂移：下装颜色、领口、绷带位置都不一致。
2. 转职（狂战士 / 剑魂）后外观会变，但要继续兼容转职前的基础动作。
3. 武器（太刀 / 巨剑 / 短剑等）要能切换，动作不重做。
4. 动作要有幅度、打击要有力，至少不低于已验收的 V6。

## 二、已确认的设计约束

| 编号 | 约束 | 说明 |
|---|---|---|
| D025 | 转职锁体型 | 身高、比例、骨架、握点、root、锚点在所有转职间不变；只换服装、配饰、发型 |
| D026 | 武器通用、单手持 | 剑系各类武器全职业通用，不随转职变化；全部单手持；基础动作不随武器变化。会改变动作的技能 / buff 算新动作工作量 |
| D027 | 标准身份与绷带臂 | 以 V6 造型为标准身份（2026-10-15 负责人确认，取代 `hero_cool.png`）：双前臂红绷带、无常驻火焰，是鬼剑士共有特征，跨转职保留 |
| D028 | 否决纯 3D 直出 | 3D 渲染图不作为最终画面（负责人评审：效果太差） |
| D029 | 时装混搭 | 支持按部位混搭；先定槽位框架（见第七节），混搭功能本身随时装系统实现 |
| D030 | 标准原画母版 | 标准原画集以 standard_v1 `sheet_main_c1` 为母版（配套 `sheet_pose_head_c1`），身份规格见 [任务包](../tasks/art_tasks/char_swordsman_standard_v1.md) 第一节；A5 部件拆解、A7 太刀三视图未生成 |
| D031 | 动作库重做 | 全部玩家基础动作按标准原画重做，路线取本文第五节的 S4；以首轮测试的 G2 画质门为去留判据，不通过按第五节退回 S0 折中 |

## 三、各方案评估结论

| 方案 | 结论 | 依据 |
|---|---|---|
| E1 云端参考图生图（`ContentImage`） | **不可用** | 服务端强制改写提示词，身份和姿势都锁不住 |
| E2 参数化骨架 + 关键帧 | **保留，作为数据层** | 握点、护手、刀尖坐标精确；可导出姿势图和深度图 |
| E3 武器分层 | **保留，作为数据层** | 同一份动作挂三种武器，前后遮挡和刀光长度自动适配 |
| E4 / S2 图生 3D 模型驱动直出 | **否决作为最终画面** | 两轮尝试后，动作幅度和打击感接近 V6，但画面精细度、剪影、造型感明显不如；3D 模型可保留作辅助素材 |
| S0 维持现状 | **保底** | 已实装；基础动作分层可换武器但刀和身体不同步发力；V6 攻击动作一体原画，不能换武器 |
| S1 自动筛选 | 增强项 | 色板、比例、剪影检查，只能减轻漂移 |
| S3 云端线稿生图 | 建议放弃 | 身份只能靠文字，预期效果和 S0 差不多 |
| **S4 参考图生图 + 骨架约束 + 武器分层** | **主线，待首轮测试** | 唯一可能同时满足画质、一致性、换武器的路线 |

## 四、两种参考图生图

| 维度 | 原生生图（多模态模型自带，如 Codex 内置生图） | ComfyUI（本地模型 + ControlNet / LoRA） |
|---|---|---|
| 锁身份 | 直接交参考图，偶有偏差 | 训练 LoRA，稳定但需要素材 |
| 锁姿势 | 参考图 + 文字，造型张力好、角度不精确 | ControlNet 按骨架图精确锁定 |
| 位置对齐 | 要事后标定（可程序自动做） | 与引导图逐像素对齐 |
| 局部修改 | 指令改图，未改部分也可能变 | 掩码局部重绘，其余像素不动 |
| 可复现 | 不可（模型版本与随机种子不公开） | 可（参数全部可记录） |
| 准备成本 | 零 | 装环境 + 调参 1~3 天 |
| 能在哪做 | 任何具备该工具的工作区 | 装好环境的机器（ws2 已有） |

- **能不能做参考图生图，取决于工作区所用的 AI 工具，不取决于是哪台机器**。立绘和动作帧生成不限工作区。
- 已有先例：V3 / V4 帧图由原生生图生成，其中包括"以 `art/characters/hero_cool.png` 为身份参考，去掉 16 个姿势里所有武器并补成握拳"（见 `art/sheets/v3/generation.json`）。
- ws1 当前工具只能文字生图（V6 由此产生漂移），做不了参考图生图。
- 原生路线的短板可用程序补救：
  - 位置：自动标定，剪影 + 关键点匹配回骨架；
  - 刀角度：挂武器层时改用骨架数据；
  - 局部修改：只取编辑结果里刀所在区域贴回原图；
  - 可复现：结果和提示词直接入库，以资产为准。
- 补不了的只有"多次分开生成之间的身份偏差"，要靠首轮测试来判断。

## 五、标准路径（候选，待首轮测试确认）

**骨架管姿势与位置，参考图管身份，生图模型画关键姿势，武器单独一层。**

1. **标准身份**：以 V6 造型为准（D027），按第七节先取舍漂移项、生成标准原画集，认可后锁定；生成时须保存生成记录。
2. **骨架关键帧**：每招 5~8 个关键姿势，采用 V6 式定格节奏，导出姿势参考图和握点坐标。
3. **生成**：参考图 + 姿势参考图，生成**带标准太刀**的关键姿势。带刀画是为了保证刀和身体同步发力，避免重蹈 V5 "空手姿势挂剑"的问题。一招的所有姿势尽量放在同一张图里生成。
4. **去刀**：改图去掉刀身、补出握拳，并拆出握柄前的手指层。
5. **组装**：自动标定 → 合成武器层（身后武器 → 身体 → 身前武器 → 手指层）→ 刀光取护手到刀尖的扫掠 → 按 V6 契约导出（60Hz、整数 `duration_ticks`、锚点、不预烘停帧）。
6. **变体**：
   - **S4a 原生生图优先**：零安装，任何具备工具的工作区都能做；
   - **S4b ComfyUI 后备**：S4a 的姿势精度或身份稳定性不够时启用，S4a 产出可作 LoRA 训练素材。

### 首轮测试（不限工作区）

> **2026-10-15 负责人决定（[D031](决策清单.md)）：全部玩家基础动作按标准原画重做。** 本首轮测试即该决定唯一的准入测试——G2 画质通过才逐动作重做，不通过就按上表退回 S0 折中，不靠"再多迭代几轮"硬推。

用标准原画 A2 + attack1 骨架姿势参考图，生成带刀关键姿势 → 改图去刀补握拳 → 挂太刀、巨剑、短剑 → 与 V6 同场并排对比。

| 验收门 | 看什么 | 不通过怎么办 |
|---|---|---|
| G1 身份 | 关键姿势与标杆是否同一人 | 调整参考图 / 提示词，或转 S4b 训练 LoRA |
| **G2 画质（决定去留）** | 带刀关键姿势与 V6 并排对比 | 最多迭代 2 轮；仍达不到就停止 S4，退回 S0 折中：攻击动作按武器大类各画一套 |
| G3 换武器 | 挂回标准太刀后能否还原原图；再换巨剑、短剑 | 改进去刀和手指层的处理 |
| G4 动作 | 同场的裸动作与命中对比 | 调整关键帧或节奏 |

## 六、训练素材（仅 S4b 需要）

标准身份改为 V6 后，V6 的 26 个源姿势按第七节取舍、剔除漂移后可直接作素材；V3 / V4 是另一套造型（红头带、红袖），不能用；`hero_cool.png` 与 E4 的 3D 模型属旧身份（单臂火焰绷带），也不再用作素材。补齐顺序：

1. 标准原画集 A1~A5 本身；
2. 挑选符合规格的 V6 单体，标注残余差异；
3. LoRA v0 生成 → 筛选 → 补入素材 → 训练 v1。

## 七、标准原画与槽位框架（下一步）

所有生成都以标准原画为参考，所以**标准原画必须先定**。V6 四张源图（`art/sheets/v6/`）之间存在漂移，需要先逐项取舍，形成书面身份规格，再生成标准原画集，经负责人认可后锁定。

### 槽位框架草案

| 层级 | 槽位 | 说明 |
|---|---|---|
| 职业固定（不可换） | 素体（脸型、体型、肤色）、双前臂红绷带 | 受 D025 / D027 约束 |
| 时装（可混搭） | 头饰、发型、上衣（含风衣）、下装、腰带、鞋（含护膝护胫） | 每个槽位每帧分身前 / 身后两个子层，前后顺序逐帧写进 manifest |
| 装备（独立系统） | 武器外观 | 按 D026 与武器分层处理 |

- **风险**：2D 混搭意味着"每个姿势 × 每个部件"都要有图。生成管线能否按槽位分层出图（例如对素体做分区局部重绘），**尚未验证**，需要作为首轮测试的附加项。
- 混搭能力验证通过前，动作帧先按整套导出；槽位框架只约束命名、掩码和层级，不阻塞 S4 主线。

### 生成工具

标准原画必须用支持参考图的生图工具生成，并保存生成记录。当前会话的生图工具只接受文字输入，需要负责人确认 ws1 用哪个工具（例如 Codex 内置生图）执行。
