# 美术资源任务模板

2026-10-14。每个资源/技能套件/房间批次从本模板复制，按 [14](14_美术资源全流程.md) 的阶段执行。以下字段是**设计记录模板**，不是现有工具的可执行 JSON schema。

建议任务位置：`docs/art_tasks/<task_id>.md`；只有实际任务创建时才新建该文件。当前旧版本无需搬目录，在任务中登记实际路径即可。

---

## 1. 身份与需求

| 字段 | 填写 |
|---|---|
| task_id / asset_id | 唯一任务、稳定语义 ID；批次逐个列子 ID |
| revision / replaces | 本轮版本、替代版本；新增写无 |
| asset_type / workflow | 类型、14文档路线A–I |
| style_profile / theme_pack | 已认可profile与题材版本 |
| scope | 本次做什么、不做什么；固定武器还是可换装 |
| gameplay_purpose | 功能用途/事件、实际使用场景、玩家要读到的信息 |
| owner / integration_owner | 当前制作/设计工作区，接入负责人/工作区；未知写待分配 |
| lifecycle | 按阶段填写，预览批准不写成实机通过 |

需求：
- 设计方向与成功表现：待填写。
- 功能清单/数量来源：待填写，不随意用“整套”隐藏缺失项。
- 本轮待用户确认的**设计向**决策：如握法、画风、分层、题材方向；没有新决策可写沿用批准。
- 尺寸、帧数、配色数值等配置：AI提供默认值与原因，不机械要求用户逐个拍板。

## 2. 依赖与影响分析

| 依赖 ID/文件 | 版本/批准依据 | 用途 | 变化后本任务的动作 |
|---|---|---|---|
| 待填 | 待填 | 身份/动作/材质/技术契约等 | 重生/重烘/只复验/不受影响 |

- 受影响下游：立绘/头像/actor/slash/hit/UI/场景/声音/碰撞/事件/预览等，列实际项。
- 保留项和复用批准范围：待填写。
- 技术兼容：接口不变、需适配或需玩法重设计；不能仅写“换图零代码”。
- 旧版回退入口和替换映射：待填写。

## 3. 参考与来源

| 参考文件/来源 | 实际用途 | 批准状态 | 是否真实传入工具 |
|---|---|---|---|
| 仓库路径或合法外部来源 | 身份/画风/材质/动作/布局 | 日期和批准范围 | 是/否/工具不支持；不能以prompt路径代替上传 |

- 版权/使用许可与原创范围：待填写。
- 工具能力：是否可看图、文生图/图生图、透明输出、批量/一致性控制；记录实际参数接口，不凭另一机器能力推断。
- 完整提示词、负面约束/配方保存位置：待填写。
- 实际工具/版本、返回文件、调用结果、种子（未知也记录）：待填写。不保存凭证。

## 4. 类别规格（不适用项明确写不适用）

| 公共字段 | 默认/实际约定 |
|---|---|
| 文件与路径基准 | 仓库相对路径、manifest/atlas入口 |
| 尺寸/分辨率/比例 | 类内统一，原始像素与实机尺寸分别记录 |
| 像素/色彩处理 | 是否量化、缩放、去溢色、滤波，不重复后处理 |
| 透明与混合 | RGBA/RGB、straight/premult、normal/add具体公式 |
| 朝向/翻转/单位 | 默认朝右、y向下；翻转时锚点和向量一起变化 |
| 画布/root/trim | 定锚或逐帧trim_offset、无裁切padding |
| 版本兼容 | contract_version、旧格式适配与接入约束 |

类别补充：
- 立绘/头像：转面、表情、材质/色板、裁切、安全区和最终缩略尺寸。
- 动作：演员和武器同方案、握法/手指遮挡、真实相位、整数duration_ticks、root/握点/护手/刀尖、循环、前冲/跳跃、取消/事件。
- 技能包：actor、起手/释放/尾迹/命中/持续/结束、投射物/召唤、图标和音效ID；缺项写原因。
- FX：后/前层、光/物质、contact/root/target/world锚、action/effect时钟、暂停/结束/死亡清理、方向/长度安全区。
- 怪物：生态职责、体型比例、攻击/受击/死亡和按机制需要的其它状态、预警/危险区。
- 场景：相机/地平线、步行面、卷轴/拼缝、层级/遮挡、门/交互/碰撞独立数据。
- 装备/道具：图标/掉落/可装备外观分别列出、部位/握法/稀有度、适配兼容矩阵。
- UI：布局/九宫格、组件状态、内容长短/缩放、字体许可/回退，动态信息独立。
- 音频：事件/变体、格式/电平/循环、动作时序和版权。

## 5. 源图样张与批准

| 候选/批次 | 源文件 | 实际主体/原画数 | 接受/弃用与原因 |
|---|---|---:|---|
| 待填 | 待填 | 待填 | 不猜网格与独立帧数 |

- 源样张批准：日期、用户原意、批准文件/版本、接受的已知偏差。
- 未获批准范围：待填写；不自动批量扩大。
- 模型工具切换/身份漂移/跨图差异：记录并重做代表小样。

## 6. 成品加工与可复现性

- 源文件/生成记录/标定/加工参数路径：待填写；正式交接不能只在temp或本机隐藏目录。
- 具体命令和依赖版本：待填写真实存在的命令；未来工具写“待实现”，不提供虚假可执行入口。
- 实际姿势映射、复用和弃用：待填写。
- 导出manifest、文件数、哈希或生成报告：待填写。
- 环境差异与需要手工校准的步骤：待填写。再烘焙不等于能重现一次随机生图。

## 7. 校验与成品预览

| 检查 | 必需证据 | 结果/问题 |
|---|---|---|
| 技术 | 格式/引用/边界/锚点/混合/时钟/层级/事件的报告 | 未执行不写通过 |
| 单体 | 实比例静态或裸动作实速、必要慢放与标定图 | 待填 |
| 组合 | 同场人物/怪物/场景/UI或完整技能包 | 待填 |
| 变更 | 同比例旧新对比、受影响下游复验 | 待填 |

- 预览绝对路径＋仓库相对路径：待填写，直接告诉用户“去哪看”。
- 视频真实帧率/速度、GIF是否丢采样：待填写；慢放不能冒充实速。
- 用户成品批准：日期、版本、范围、接受的限制；技术通过≠美术认可。

## 8. 发布交接（两个工作区共同填写）

- 交付包：源/配置/成品/报告/预览/本文全部入口。
- 原画与资源契约的已知限制：待填写。
- 本轮相关文件的提交/分支/远程发布结果：实际commit后记录/汇报；未推送写失败原因，不能只写“完成”。
- 接收区同步结果：由接收区确认，不能制作区代勾。
- 接收区需要的适配：入口、坐标、尺寸、层级、alpha、时钟、事件、物理位移与UI布局。

## 9. 实装待办与实机验收

- [ ] 接收区同步并确认任务revision与资源入口。
- [ ] 按契约导入/绑定，旧资源替换范围与保留项明确。
- [ ] 处理必要的碰撞/事件/位移/朝向/循环/清理适配。
- [ ] 以已认可预览为基准录制实机并核对接触/遮挡/可读性。
- [ ] 跑受影响功能回归，提供退出码、日志和明确完成标记。
- [ ] 用户实机认可或记录待修问题；只有真实完成才勾选。
- [ ] 接入改动和证据自动提交并推送，制作区可回看。

## 10. 修改复盘

- 现象与根因：源设计/标定/加工/契约/实机绑定，不写模糊“AI没画好”。
- 改动及新证据：待填写。
- 防复发检查/需要回写的公共规范：待填写。
- 下个revision的明确待办：待填写。

---

**模板使用完毕的最低条件：** 用户能找到要看的媒体；制作人能复现加工；接入人不用猜路径/锚点/时钟/混合/替换范围；两区能从Git取得同一版本，并分清预览与实机批准。
