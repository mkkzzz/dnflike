# DNF 原版拆解与还原路线

> 新版还原工作的共同入口。适用 `game_dnf/`；旧工程设计与历史验收保持原适用范围。
> 目标是可自由修改的本地 Godot 游戏。全系统拆解目录已建立，原版规则仍须逐项取证，不能把目录齐全称为完整还原。

## 一、为什么先拆解

用户2026-10-22反馈新版的场景、美术、UI、动作与战斗均存在问题，要求各工作区依据同一套设计推进。
当前版本验证了原资源消费与基本游戏流程；原资源、原动作片段和自定义规则共同构成现有表现。
继续逐个凭观感修补，会把不同来源和不同理解混在一起。
下一阶段先建立“原版依据 → 规则 → Godot实现 → 实机对照”的闭环，再批量接入内容。

本路线不撤销既有视频验收；既有验收不扩大为原版一致性验收。

## 三、参照对象

首要参照是用户本机“情怀60复古”的实际可玩行为，而非任意年代的官方DNF或相邻整合包。
“60级”是用户指定的目标身份，尚不能据此判定资源包内全部内容都属于该版本。

已证实本机有多个不同字节的 PVF；当前运行包使用其中备份的动作元数据。
客户端实际加载哪个PVF、补丁覆盖顺序、与服务端的配套关系尚未锁定。
这些问题未核实前，原文件中读出的字段只能作为该文件的事实。
另一目录存在 DNF1031 服务端虚拟机，现阶段仅登记候选，禁止默认为配套或混入本版。

## 四、推荐实现路线

保留当前能运行的样板作为比对基线，逐项替换已经查明的适配部分。
不以“先反编译整个客户端”为前置条件，也不因文件可读便假定 Godot 已支持其行为。

| 层 | 责任 | 边界 |
|---|---|---|
| 原始来源 | 保存原文件、来源包、相对路径、SHA256、版本差异 | 不修改已发布资源版本 |
| 提取与解析 | 还原记录结构、索引、字符串、引用、原始字段 | 未知字段原样保留并报告 |
| 标准数据 | 表达动画、状态、事件、判定、地图、物品等稳定对象 | 原字段与适配字段分开，携带证据ID |
| 行为执行 | Godot消费状态机、时间线、事件和判定 | 不让美术节点自行决定命中或推进另一套时钟 |
| 本地服务 | 属性、掉落、任务、经济与存档等本地权威状态 | 原服务器行为未知时显式登记替代方案 |
| 编辑与覆盖 | 玩家可读配置、开发工具和独立覆盖层 | 原版基线可复现，自定义改动可关闭、可追踪 |

先实现高复用能力，再扩内容。例如原地图加载器、ANI字段支持、判定盒与事件执行器覆盖后，后续房间和技能可共用。
原引擎中无法直接移植的功能，按实际需要做定向分析与Godot重实现。
只有文件/脚本和实机实验都解释不了的关键规则，才进入更深的二进制分析。

## 五、推进顺序

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| R0 版本与证据 | 确定有效配置、补丁、来源边界；登记五类缺陷与对照样本 | 参照身份可复现；未知项有清单 |
| R1 一间房的完整品质 | 同一角色/衣装/武器、一个原版房间、一种怪物、原HUD；覆盖三连/受击/切房 | 五类对照均有证据，用户确认该范围品质 |
| R2 数据执行能力 | 扩ACT/ATK/ALS、地图/物件、技能/怪物解析和依赖校验 | 支持项与不支持项可机读，失败不能静默忽略 |
| R3 单机闭环 | 城镇、任务、背包、装备、成长、商店、正式结算与存档 | 一条从创建角色到升级装备的流程完整且可重载 |
| R4 全内容接入 | 按本版有效职业、副本、怪物、装备与任务清单分批转换 | 每批依赖闭合，统计覆盖范围，差异可追踪 |

R1不是扩大现有五房样板，而是建立值得后续复制的质量基线。
R0未锁定的行为可以在隔离实验中研究，但不得填成该版本已确认规则。
无法确定的原版数值不以网上其他版本的表格补齐。

## 六、所有工作区如何使用

1. 从本文进入，先核对[进度看板](../project/01_进度看板.md)、本区状态和资源版本锁。
2. 按全系统目录认领模块；按协作总纲登记会碰撞的公共文件。
3. 开始实装前，任务包中必须有参照对象、证据ID、预期行为、差异ID、依赖与验收场景。
4. 原版事实写入模块规则记录；临时实现写入适配记录，不回写为原版事实。
5. 交付来源/解析/实机三方面证据，接收方验证后登记接收，用户确认后才填实机验收。

本路线给出建议任务边界，不固定ws1/ws2/ws3的永久职责，不代替其它工作区认领或接收。
无需各区重新猜一套“像DNF”的规则；发现冲突时补证据、保留分歧，再统一基线。

## 七、什么才算完成拆解

全系统目录覆盖目标功能，只代表范围明确。
完整拆解还需要：有效内容清单、逐字段含义与单位、引用关系、状态与事件时序、公式/随机规则、异常路径、实机证据，以及与当前Godot的差异。
原版含有但单机版不实现的系统，也须列明范围取舍及依据，不能从目录中悄悄消失。
现阶段不得声称已获得完整源码、完整有效数值或完整原版设计。
