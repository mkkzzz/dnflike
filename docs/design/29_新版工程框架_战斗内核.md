# 新版工程框架：战斗内核

> 上级入口：[新版工程框架](29_新版工程框架.md)。接口字段格式见[接口契约](29_新版工程框架_接口契约.md)。
> 本页定"怎么组织"，不定原版字段语义；语义按[证据与版本](26_DNF原版拆解_证据与版本.md)逐字段登记。

## 一、设计原则

1. **数据驱动**：动作、判定、伤害、受击、技能、怪物行为都由内容包驱动；代码只实现"字段怎么生效"，不写具体技能。
2. **玩家与怪物同构**：同一套实体、动作执行器和结算管线；区别只在控制器（输入或AI）和数据。
3. **一字段一处理器**：每个原版字段的执行逻辑只存在一个文件中，修正一次，全部内容生效。
4. **确定性**：同初始状态+同命令序列 → 同事件序列。用于回放回归，也为以后自动对照留口子。
5. **单一时钟**：World 推进全部模拟时间；表现层只读，不另起时钟。

## 二、每帧管线

World 每个模拟步按固定顺序执行，顺序本身是契约，调整须改本页：

| 步 | 阶段 | 做什么 | 主要输入 |
|---|---|---|---|
| 1 | 时钟 | 计算每个实体本步可用时间（停帧冻结、攻速缩放） | 停帧表、属性 |
| 2 | 控制 | 控制器产出意图（移动/朝向/请求动作） | 输入缓冲、AI数据 |
| 3 | 动作图 | 判定能否开始/取消/接续动作，扣费、进CD | 动作图、取消窗口、资源 |
| 4 | 时间线 | 推进 ANI 时钟，触发帧事件（音效/特效/位移/盒体） | ANI 帧表 |
| 5 | 运动 | 速度积分、重力、落地；经 MapQuery 约束走区与阻挡 | 速度、MapQuery |
| 6 | 判定 | 攻击盒×受击盒相交，按攻击实例去重 | 当前帧 Box6 |
| 7 | 结算 | 字段处理器分阶段执行：命中前检查→伤害→受击反应→命中后 | HitContext |
| 8 | 状态 | Buff/异常计时、周期效果、到期移除 | 状态实例 |
| 9 | 提交 | 死亡/清除、输出事件、生成快照 | — |

## 三、实体

实体是数据对象（非 Node），由若干部件组成，部件缺省即不参与对应阶段：

| 部件 | 内容 | 用于阶段 |
|---|---|---|
| Transform | x（横）、y（纵深）、z（高度）、速度、朝向±1 | 5、6 |
| Action | 当前动作、ANI 时钟、帧号、动作实例序号、排队请求 | 3、4 |
| Body | 当前帧的受击盒/攻击盒（来自 ANI，经朝向变换） | 6 |
| Stats | 血蓝、攻防、攻速等；玩家来自 Profile 快照，怪物来自 MOB | 1、3、7 |
| Reaction | 硬直/浮空/倒地/起身状态与计时、霸体/无敌标记 | 3、7 |
| Status | Buff/异常实例列表 | 7、8 |
| Control | 控制器引用 | 2 |
| Hits | 已命中记录（攻击实例→目标） | 6 |

实体类型：玩家、怪物、投射物、可破坏物。投射物与可破坏物同样走判定与结算，不另写一套。

## 四、动作层

**动作定义（ActionDef）** 由编译器生成，一个动作 = ANI 帧表 + 关联攻击信息 + 资源消耗 + 取消规则 + 位移。

**动作图（ActionGraph）** 描述"在什么状态、什么输入下能进哪个动作"，包括普攻三连接续、跳跃、后跳、格挡、跑攻、空中攻击、技能取消。
原版中这部分有的写在 CHR/SKL，有的写在引擎里。写在引擎里的部分也放进内容包的动作图数据（标 E-INFER），**不写进代码分支**，查清后改数据即可。

**ANI 执行器** 只做三件事：按原帧时长推进、给出当前帧盒体、在跨帧时发出帧事件。
等待帧、循环、全局项等原字段保留，语义未确认的不擅自截短（遵守26的约束）。

## 五、判定层

- Box6 原始六值原样保存；朝向镜像与锚点换算只在 core 的一个函数里做，判定与调试叠加共用。
- 相交：攻击盒与受击盒在横、纵深、高度三轴都重叠才算命中。
- 去重键：攻击者 + 动作实例 + 命中组 + 目标。命中组默认"攻击盒连续出现的一段帧"，可被 ATK/SKL 的多段字段覆盖。
- 判定只产出"谁被哪个攻击实例打中"，不计算伤害，不触发任何表现。

## 六、结算层

**HitContext** 携带攻击者、目标、攻击信息、技能及等级、命中组序号、命中点；各阶段处理器读写它，最后统一落到实体与事件上。

| 阶段 | 典型字段/逻辑 | 说明 |
|---|---|---|
| 命中前 | 无敌、格挡正背、霸体 | 可终止本次命中或改写反应 |
| 伤害 | 基础攻击、技能倍率、防御、暴击、取整 | 伤害管线由有序步骤组成，每步可单独替换 |
| 受击反应 | 硬直、推开、浮空、倒地、弹地 | 写入目标 Reaction 与速度 |
| 命中后 | 停帧、状态附加、反馈提示 | 停帧作用对象本身是一个可取证的字段 |

**字段处理器** 放在 combat/fields/，一字段一文件，启动时自动发现。每个文件声明：对应原字段、所属阶段、证据等级、执行函数。
内容包里出现但没有处理器的字段，编译与启动时都要报告，不能静默忽略。

**停帧** 按实体冻结（冻结对象由字段决定），不再冻结整个世界；世界时钟照常推进，未被冻结的实体与特效继续运动。

## 七、控制层

控制器接口统一：读取只读世界视图，输出命令。

- 玩家控制器：把输入缓冲转为命令；缓冲时长、预输入规则属于动作图数据。
- 怪物控制器：消费 MOB/AI 编译数据（感知、选招、冷却、移动）；未解析的 AI 指令报告为未支持，暂用适配层行为并标 E-ADAPT。
- 调试控制器：回放录制的命令序列，用于回归和问题复现。

## 八、状态层

Buff/异常为数据定义 + 通用实例：持续时间、叠层/刷新规则、周期效果、属性修正、在结算阶段的挂钩。
D016 的五种异常与技能 Buff（如血怒）都走同一框架。

## 九、表现与反馈（L4，属 view 模块）

内核只发事件，下列组件各自订阅，互不依赖：

| 组件 | 订阅 | 数据来源 |
|---|---|---|
| ActorView | 快照 | 多图层纸娃娃（衣装/武器前后层）+ ANI 帧 |
| FxView | 特效提示事件 | 原版特效 ANI、混合模式 |
| 跳字 | 伤害事件 | 原版位图数字与连击图 |
| 镜头 | 命中/停帧事件 | 震屏参数（基线未知部分走适配层） |
| 音频路由 | 音效提示事件 | ANI 帧音效、CHR/ATK 命中音 |
| 受击闪白 | 命中事件 | Shader 参数 |

调手感时只改这些组件或其数据，不碰判定与结算。

## 十、调试与验证

- 盒体叠加：显示当前帧受击盒/攻击盒与命中点。
- 事件时间轴：按帧列出动作、命中、伤害、停帧、音效事件。
- 单步与慢放：暂停后逐模拟步推进。
- 回放回归：固定命令序列 → 事件序列摘要比对；改动导致事件变化时必须是有意的。
- 字段覆盖报告：每类原版字段的出现次数、处理器状态、证据等级。
