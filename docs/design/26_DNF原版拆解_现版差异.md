# DNF 原版拆解：现版差异

> 上级入口：[还原路线](26_DNF原版拆解与还原路线.md)。这里记录已从当前实现确认的行为，不能据此断言原版相反。
> 具体源文件指纹与首轮结构读取见[审计记录](../reports/ws2/2026-10/2026-10-22_DNF原版拆解首轮审计.md)。

## 一、优先级

- P0：参照版本、来源冲突、共同坐标/时钟和阻断正确解析的问题。
- P1：直接影响用户指出的五类品质，且会被后续内容重复依赖的问题。
- P2：单机流程、内容与系统覆盖问题；重要但依赖前面的契约。
- P3：覆盖确认后做性能、工具与维护性优化，不用于掩盖正确性缺口。

优先级是工作顺序，状态以[待办](../project/02_待办.md)与各区状态文件为准。

## 三、已经读到的具体线索

以下仅为备份文件E-PARSE，不是实际运行版本已确认设计：

- CHR记录基础属性、动作列表、攻击信息列表、武器声音/命中信息；只复用身体ANI会漏掉其它依赖。
- Attack1.atk记录damage bonus、push aside、lift up等字段；单位/结算方式仍需查引擎与实机。
- 上挑SKL包含副本consume MP与cool time，以及不同模式/等级表；当前固定蓝耗不能冒充原表。
- 拔刀SKL的副本cool time字段与现版冷却不一致；且该文件含后期上限线索，不能照抄成目标60版。
- MAP含tile、far/middle/near sight scroll、背景layer/order、pathgate pos、怪物/物件记录。
- goblin.mob指向Animation_Goblin2；现版消费Animation_Goblin。必须先核原怪物ID与变体，不能用文件名相似证明匹配。
- 单独抽取的goblin/action_goblin/attack1.act实际引用Kinol相关动作与装备层；不能把同目录同名文件默认视为普通哥布林的执行链。

这批线索支持“先依赖图、后执行器、再批量接入”的路线。

## 四、修复约束

1. 每次修复写明对应diff_id、原版证据、适配代价、接口变化与受影响内容。
2. 无来源的临时参数保留E-ADAPT标签；不覆盖原始值。
3. 同一个规则由一个数据/执行入口负责，避免构建器、模拟与表现各写一份窗口/时钟。
4. 新回归覆盖实际输入和边界；另外保留原版对照，自动化通过不替代观感验收。
5. 对其它模块的依赖变更先更新规则契约与交接，不让各区靠猜测兼容。
