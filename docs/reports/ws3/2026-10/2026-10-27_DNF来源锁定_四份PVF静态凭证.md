# DNF 来源锁定（T0）：四份 PVF 静态凭证

> 任务：[DNF 原版还原共同基线 v1](../../../tasks/design_tasks/dnf_restore_baseline_v1.md) T0 来源锁定。
> 本轮只做**本机可做的静态取证**；运行期加载证据（客户端实际加载哪一份）不在本机，见第六节。
> 证据等级按[证据与版本](../../../design/26_DNF原版拆解_证据与版本.md)第一节：本节结论均为 E-FILE，解释性内容标 E-INFER，未证项标 E-UNKNOWN。

## 一、结论

1. 本机的共享资源库 `library_v1` 里存有客户端的三份 `Script.pvf` 原件（根目录、`ImagePacks2/`、`Video/`）和一份相邻的 `111Script.pvf`，共 **4 份**，逐字节 SHA256 已复算。
2. 四份**互不相同**：客户端根目录与 `Video/` 是一类（文件头前 4 字节为版本号 `0xBF58` = 48984），`ImagePacks2/` 与 `111` 是另一类（36 字节 GUID 前缀 + 版本号）。
3. 当前资源库（`pvf_config.sqlite`，336,082 个文件）是用 **`111Script.pvf` 备份**建的，不是客户端里任何一份；这是既有事实，本轮复核一致。
4. 客户端实际加载哪一份、补丁覆盖顺序、服务端配套，**仍未锁定**。本机不是客户端所在机器，加载证据必须由有客户端的工作区补。

## 二、四份 PVF 的身份（E-FILE）

路径均相对资源库 `library_v1/`。复算哈希与库内 `来源文件与哈希.csv` 一致。

| 角色 | 客户端内相对路径 | 字节数 | SHA256 | 文件头特征 | 本机副本 |
|---|---|---|---|---|---|
| 客户端根目录 | `Script.pvf` | 183,230,422 | `3c0e8050082ddf922abe0fe9643f3550cf42ab14576caf2ba6b1aeb3881bcea4` | 前 4 字节 `58 bf 00 00`（版本 48984） | `assets/12_config/Script_fa278d/e59021b91422e0fd46ec_Script.pvf` |
| ImagePacks2 | `ImagePacks2/Script.pvf` | 202,396,005 | `3893d5d1506bcc332ca4b6438f6f884d128481641483bee9478cad8d0221fe01` | 36 字节 GUID `fa08bf71-4395-6a4b-a3e3-2617c9fee116`，随后 `58 bf 00 00` | `assets/12_config/Script_375033/471bf50854d764e6dde4_Script.pvf` |
| Video | `Video/Script.pvf` | 182,490,884 | `cfea184b6a26252e41fd419765eadd07fb748c5e0759f04d937d21cce7a99542` | 同根目录，`58 bf 00 00`（版本 48984） | `assets/13_video/Script_4bb5be/d0035f246e13792aca8f_Script.pvf` |
| 相邻备份 | 客户端**上级目录** `111Script.pvf` | 202,404,709 | `f48850456b7dc0107278fb3f3a74fd68ee404889b95880f3204ce10fbd179be0` | 与 ImagePacks2 相同的 GUID 前缀 | `config_source/111Script.pvf` |

补充事实：

- `Video/Script.pvf` 是首轮审计**没有记录**的第 4 份（原审计只列三份）。它是否参与加载未知。
- `111` 比 `ImagePacks2/Script.pvf` 正好大 **8,704 字节**，但两者从第 48 字节起就开始分叉，**不是**"前者 = 后者 + 尾部追加"的关系（做过前缀相等性检验，不成立）。
- 客户端根目录与 `Video/` 两份的前 4 KB **除第 5~7 字节外完全相同**；第 5~7 字节像是随构建变化的种子/长度字段（E-INFER，未解析）。
- `ImagePacks2/` 与 `111` 的 GUID 前缀相同，说明它们出自同一套打包工具/同一来源谱系（E-INFER）。

## 三、资源库的配置来源（E-FILE）

`library_v1/config_summary.json` 记录：`source = <客户端上级目录>/111Script.pvf`，`source_sha256 = f4885045…79be0`，`pvf_version = 48984`，`files = 336082`，`source_unchanged = true`。

即：**当前所有动作/技能/地图配置的解析结果来自 111 备份**。若客户端实际加载的是根目录或 ImagePacks2 那份，现版配置与运行版本之间就存在未量化的差异——这正是首轮审计留下的最大风险，本轮不缩小该风险，只把来源列清楚。

## 四、本机为什么做不了加载证据

- 本机（ws3，`D:\dnflike`）**没有客户端目录**：`D:\`、`C:\`、`E:\`、`F:\`、`G:\` 均未找到 `ImagePacks2/` 或 `Script.pvf`（`D:\WeGame\apps\DNF` 是官方现代客户端，不是"情怀60复古"，不能当参照）。
- `library_v1/summary.json` 记录构建机：客户端 `D:\情怀60复古\情怀60复古`、输出 `D:\dnf like\dnflike\temp\dnf_unpack_probe\library_v1`。按[工作区登记](../../../project/03_工作区登记.md)，`D:/dnf like/dnflike` 是 **ws2** 的路径；这两处字符串在 JSON 里是 GBK 乱码，路径含义为还原推断（E-INFER）。
- 结论：**加载证据只能在 ws2 那台机器上取**，或者把客户端拷到本机后再取。

## 五、复现方式

在资源库根目录对四份文件做 SHA256 即可复算（PowerShell）：

```powershell
Get-FileHash 'D:\dnflike-assets\dnf-native-assets-v1-20261022\library_v1\config_source\111Script.pvf' -Algorithm SHA256
```

四份的完整哈希见第二节；与 `来源文件与哈希.csv` 第 133、1428、2046 行的记录一致。
客户端三份的存放位置由该 CSV 的 `path` 列给出（`Script.pvf`、`ImagePacks2/Script.pvf`、`Video/Script.pvf`），说明它们在客户端目录里确实同时存在。

## 六、运行期加载证据怎么做（交给有客户端的机器）

目标是回答一句可复现的话：**客户端启动到进入游戏时，实际打开的是哪一个 `Script.pvf`**。不改动任何原文件。

1. **记入口**：客户端启动方式（exe 或启动器）、exe 的 SHA256、客户端版本号、显示器与分辨率、窗口模式、帧率设置。这些与加载证据一起记，缺一不可复现。
2. **抓文件访问**：用 Process Monitor，过滤条件 `Path contains Script.pvf` 且 `Process Name is <客户端 exe>`；启动客户端走到选人/进图，导出 CSV/XML 存本地证据目录（不入库）。
3. **抓目录现状**：记录三个候选（根目录、`ImagePacks2/`、`Video/`）的字节数与 SHA256 —— 装载前后各一次，确认取证过程没改文件。
4. **重跑一次**：同样步骤再跑一次，两次结果一致才算可复现。
5. **登记**：把"实际被打开的相对路径 + 读取次数 + exe 哈希 + 测试环境"写进[证据与版本](../../../design/26_DNF原版拆解_证据与版本.md)第二节的清单，同时保留 E-UNKNOWN 项（补丁顺序、服务端配套）不填默认值。

## 七、本轮没做的事

- 没有解析任何 PVF 的加密/封装层，没有因为文件可读就断言其语义（`ImagePacks2/` 与 `111` 的 GUID 前缀只当格式特征记录）。
- 没有运行客户端、没有挂载 DNF1031 服务端虚拟机、没有把三份客户端 PVF 与 111 备份做内容级 diff（需要先解封装，属 R2 解析能力）。
- 没有改动 `library_v1` 与任何原文件；本节所有哈希都是只读复算。

## 八、下一步

1. ws2（或本机收到客户端副本后）按第六节取加载证据，填 T0 的"有效 PVF"一栏。
2. 若要比较"111 与客户端实际加载那份"的差异，需要 PVF 解封装工具（库已用 `PyDnfEx` + `dnf-pvf-parser-ts` 建过），属 R2；在此之前所有从 111 读出的规则都只代表该备份。
3. 补丁顺序与服务端配套仍无证据，保持 E-UNKNOWN。
