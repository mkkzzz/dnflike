# 有效等级重建与封印解除修复

沿基础精通的等级重建调用继续调查，发现技能35“封印解除”的实际接入错误：现版会给未学习技能凭空加级、满级继续增加、把增量乘以被动等级，且漏掉目标“残影之凯贾”。本批按原列表与原调用条件修复；完整装备加级、保护代码中的目标重映射及最终伤害仍未完成还原。

## 原代码与原配置

指定原客户端内层SHA为 `187ad34ab6bfff040d9b12bb145bdda0bba29f82aaa41183280b0ae42e914b84`。技能35来自 `skill/swordman/ghostpowerup.skl`，SHA为 `82c42036e33e71cf28b96b4aea94b3a3f3ae47f6ce4e9cb429feb8c6af09da17`；原最大等级1，静态数据完整列表为 `[5,25,36,41,84,75,82]`，不是“首元素5表示数量”。原LST依次指向鬼斩、刀魂之卡赞、冰霜之萨亚、侵蚀之普戾蒙、残影之凯贾、瘟疫之罗刹、冥炎之卡洛对应文件，原路径保留在证据中。

原 `CD9E50` 首先调用通用 `861D80` 重建，再处理技能35、27、63的专属分支。技能35分支 `CD9E60..CD9F4E` 要求自身有效等级大于0；逐项取得静态目标后，要求目标对象存在、有效等级大于0且小于 `905D50` 返回的上限，才把目标 +59C 增加1。增量不乘被动等级。`905D50` 实际读取目标安全字段 +54。

本批重放该分支的真实有效等级getter、缓存查询、上限getter和写入；静态向量选择 `905E90` 与受保护的目标解析 `908510` 是明示ABI边界，输入为未经修饰的原静态列表，不能据此声称复杂装备/模式对静态目标的改写已还原。运行上限使用已有原SKL `max_level`，本批没有重放完整SKL对象构造/字段复制链。

## 通用有效等级重建取得的规则

| 顺序 | 原规则与验证范围 |
|---|---|
| 基础复制 | 遍历255个对象槽，存在的技能 +590 复制到 +59C；此步本身不限制上限 |
| 角色 +52FC | 只在正值时处理；跳过技能ID191～209和基础等级0；模式15且技能 +54C 非0时也跳过；结果取字段 +54 与有符号32位相加结果的较小值，没有下限1夹取 |
| 装备槽 | 原循环遍历26槽，本批两种装备取得服务均明示返回空，不能代表装备已还原 |
| 两份列表 | 依次处理角色 +4C98、+5560，实际执行28字节迭代器、职业匹配、目标缓存查询；职业11或当前职业0匹配，目标基础等级非0才处理；每一条都执行 `max(1,min(上限,当前有效等级+增量))` |

列表不能先合计再夹取。例如基础60、上限100，先+50后−50得到50，反过来得到60。角色 +52FC 的生产来源、两份列表的加载来源及全部装备分支仍待追踪；负等级、溢出、上限0仅作算术边界，不能解释成游戏允许的输入。旧列表为空、安全存储、模式谓词及 `113B500` 容器清理为夹具/ABI边界。

## 实装

- 技能生成器从原记录读取7个目标ID并保留顺序，去除手写六目标表和无消费端的10%伤害元数据；静态列表缺失或非法时拒绝生成。
- `SkillBook.effective_levels` 返回独立有效等级表；“封印解除”只对已有正等级且未到上限的目标加1，不修改购买等级或存档输入。未学习和不存在的目标保持未学习，重复刷新不累加。
- 实际 `main.update_numbers` 和动作表使用同一有效等级结果。原静态目标通过已有源ID映射解析，补回84“残影之凯贾”。本批没有把未闭合的通用重建机制直接移植为猜测公式。
- 完整重建技能运行表，逐项比对只有技能35定义及内容包依赖SHA变化；动作、效果、对象和图像资源引用相同。战斗资源清单只同步运行表依赖SHA，没有重烘图像。
