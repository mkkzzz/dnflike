# 神殿莲花箱掉落与原小地图

神殿周边的莲花箱使用原 `[item]` 配置预先分配道具。箱子耐久耗尽后，隐藏的道具进入当局地面掉落账本。拾取按原物品 ID 入库，同一箱子的重复通知和同一物品的重复拾取均被拦截。

目标 PVF 的 DGN21 与 1031 备份服务端的掉落组逐字段相同。`CBattle_Field::add_item_curr_map` 的 `0x8302D7D` 以 MAP 子项首值索引 DGN 掉落组。`0x8302E67` 把第二个值交给 `CObjectDrop::generateSpecificItem` 作为次数，第三个值为 `-1` 时关闭 `generateRandomItem`。组 0 的源顺序为黄金圣餐 1068、神圣葡萄酒 1069、蓝色圣经 1070、圣杯 1071、邪恶药剂 1072，权重依次为 1000、1500、500、500、3000。`0x853825F → 0x85334A4 → 0x80CBABE` 每次抽取 0 至 10000，`0x853829C` 取累计权重严格大于抽值的第一项，6500 及以上落空。MAP3006 有一次两抽配置。

目标客户端 `0x7DD58F` 将预分配的道具关联到具体箱子。`0xA394F0 → 0xA392A0` 在破坏阶段释放，`0xA3943F..0xA3945A` 用箱子的原世界 X/Y 与出生高度建立掉落。当前工程按当局、房间和箱位稳定生成，复用拾取存档。掉落落地轨迹和光柱仍沿用现有表现，本机随机流和原服务端随机流独立。五件道具已从目标客户端的原物品档注册，使用效果及冷却待按原客户端核对。

战斗右上角使用原单机小地图。源 `DungeonMinimap.ui` 指定 18 像素格距，`0x102DA15` 读取已加载房间，`0x102DA92` 按原 MAP ID 和坐标选择房间底图变体。`0x102DF10` 和 `0x102D918` 让当前门可达的未知邻格每 250 ms 切换问号图。`0x102D0F0..0x102D1EE` 为本局实际首领显示原问号底和橙色骷髅，玩家进入后切到当前房标记。另一个候选首领格按普通房间规则显示。原窗口拖动、折叠与多人标记仍待接入。

- 原服务端 `0x8538234` 离线回放通过 15 个案例，包括权重边界、连续两抽、一次落空与零抽。夹具为随机数输入、容器迭代与物品创建回调。
- 箱子回归覆盖原 MAP 中空箱与带道具箱、耐久阈值、两抽配置、战斗事件进入真实账本、拾取距离及重复事件。缺少任一道具的原图时，神殿战斗入口拒绝切换。
- 小地图无界面测试走两组真实起点与首领抽取，窗口渲染测试核对四个场景的格位和可见橙骷髅像素，旧路线测试确认退出后没有神殿专属界面。证据为目标原版配置、代码和当前工程实绘，原客户端未运行。
- 罐子带陷阱和召怪的状态仍留在正式入口之前。原先预留的隐藏怪物不参与当前门判定，实际生成后进入客户端场景怪物表。两种延时陷阱的原警告 ANI、难度时长与生成顺序已取证，陷阱实体和效果待接入。
