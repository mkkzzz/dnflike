# 神殿破罐召怪与房门重锁

神殿周边 3 张原 MAP 的 4 个特殊长罐已接入隐藏怪物，原表共 7 条候选。罐子击破后按原顺序释放预留的章鱼 250 和信徒 260，保留原等级、世界坐标和各自的实体编号。房门随实际活怪状态开关，房间清场事件只发送一次。

## 原版依据

- 目标内层客户端 SHA256 为 `187ad34ab6bfff040d9b12bb145bdda0bba29f82aaa41183280b0ae42e914b84`。目标与 1031 备份的 16 张带特殊物件的可达 MAP 逐字段一致。备份 `0x835FF6A → 0x834E5E8` 在全局地图目录装载时为候选抽 0 至 99。抽值小于等于截断后的分数百分比才预留，原 `1/500` 也可由抽值 0 选中。目标 `0x7DD2E8..0x7DD3BA` 把预留怪按父物件序号关联到罐子。当前工程在本机第一次装载此原地图目录时生成一次，各局共享预选结果，使用本机随机流和战斗内实体编号。
- `0xA394F0 → 0xA362E0 → 0xA35970` 只在达到破坏阶段时释放预留内容。地面分支用 Z=0，抛出分支用罐子 Z+10。抛出包按顺序给 X、Y 速度、两个方向和跳高，分别覆盖 X 50–149、Y 25–74、跳高 40–99。原包的父朝向为右，与抛出速度符号独立。`0x87B690 → 0x876A20` 接收抛出包，进入状态 10，模式 2 基础重力为 −1500。初次抛出保留并重启原待机 ANI。章鱼分支播放原 `ZGM_SPRING`。`0x87B50E` 收到物理落地事件 5 后，在同一调用依次提交状态 11 和 0。通用中间态与等待态之间没有独立绘制时刻，两种怪均当帧回到原待机。
- `0xE5C012 → 0x8A55F0` 将实际生成的敌人加入场景。`0x6F524B` 设置门锁，`0x8A06B0 → 0x8A0878` 在重新清场时解锁。隐藏名册不参加场景门判断。当前实现把门状态和已提交的清场回执分开，过门判定、门动画、战斗 HUD 和出口提示读取同一门状态。

## 验证与范围

- 原启动包离线回放验证 5 个场景，包括地面、抛出上下限、原坐标高度和强制地面。工程从真实迷宫入口跨门进入 MAP3006，验证预留但未出现时门可开、往返保留原编号、破罐后关闭、实际过门被阻止、击杀后再开门、三只混合怪依次生成、回房无重复生成。测试使用固定抽签和直接伤害夹具控制分支，实际场景、怪物、物件、回执和渲染均通过正常战斗会话。
- 罐子陷阱的警告时钟及分派已有原代码证据。火爆、毒雾和接触妖精的效果接入仍在进行。祭司的召唤另走 OBJ48024 代理和自身状态链。神殿正式城镇入口继续等待这些玩法和原任务接线。
