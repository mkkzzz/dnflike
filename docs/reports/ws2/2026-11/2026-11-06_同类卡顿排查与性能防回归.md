# 同类卡顿排查与性能防回归

## 结论与范围

用户指出技能面板卡顿已重复发生，要求检查剩余同类问题并防止复发。以 `2c8e7a20` 为修复前基线，扫描全部运行 GDScript 的配置复制、高频回调、拖拽预判与界面重建路径。

发现并清理 21 处运行调用：武器外观查询、奖励/结算、装备穿戴/拖拽、强化预览、装备悬停、技能详细说明、装备管理，以及数值 API 内部的详情/怪物数值/命令/存档校验。原先这些调用都会复制含全量装备/技能的配置。现在统一为共享只读引用。

服务配置原来每次读取文件并合并物品服务总表，强化配置每次预览重新读文件，现改为会话缓存。数据消费者只读配置，报价与 profile 仍按原事务边界复制。扫描未发现另一个在点选技能时销毁整窗的残留入口；任务追踪已有签名去重，HUD 更新数值而不逐帧创建控件，未对这些已有有效机制做无谓重写。

同时，真实格挡详细说明暴露 `guard_factor` 缺失错误：编译 SKL 覆盖了手写运行定义。数值加载器仅保留格挡仍在使用的两个运行参数，显式编译字段优先；不广泛合并所有旧技能字段，避免带回过时招式规则。技能详情与战斗共用同一参数。

## 防复发措施

1. 移除易误用的 `Numbers.config()`；运行只读走 `shared_config()`。可变整库改名 `config_snapshot()`，仅供测试/离线调试，旧调用会在脚本加载时暴露。
2. 新静态检查禁止运行调用整库快照、直接深拷贝共享配置及技能点选/加退点重建整窗。覆盖常规 Numbers 路径及本地 preload 别名；这是一组针对已知复发模式的检查，不是完整调用图或所有性能问题的证明。
3. 反例单测故意放入旧写法，验证检查器确实拒绝；正例保留小字典与事务复制、其它缓存配置、测试快照和正常转职重建。
4. 新 headless 性能测试使用真实窗口/说明/预览/拖拽函数，预热后取三次中位数，设置宽于本机正常波动的预算；检查数值/服务/强化配置与角色档案不被读取路径修改。原技能面板 viewport 控件身份和输入回归继续保留。
5. 检查接入正式启动、战斗回归、内容流水线及 GitHub Actions。标准循环 `-Test` 先跑反例与 UI 性能再进其它规则。未修改 Git hooks、Git 配置或远程分支保护。
