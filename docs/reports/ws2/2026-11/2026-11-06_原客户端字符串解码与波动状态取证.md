# 原客户端字符串解码与波动状态取证

继续用户要求的原代码优先路线。本批在原生客户端内定位并还原了字符串解码算法，恢复资源/接口引用，进一步找到鬼剑士波动技能的进入状态与逐帧处理分支。新增的是可复用的只读取证能力和代码证据，尚未修改游戏动作时序，也不把反汇编称为完整源码。

## 确定的原程序

- 输入：用户指定目录下的情怀60复古/DNF.exe，外层 SHA256 为8748e19abf6155ca5a20d13244eaca0b9442c3d7569e8e5002bddffeeb9366ac。
- 实际分析对象：其资源10/EXERESX/0，外层文件偏移734740、长度55905117；内层 PE SHA256 为187ad34ab6bfff040d9b12bb145bdda0bba29f82aaa41183280b0ae42e914b84，ImageBase 为0x00400000。
- 全过程只读文件，在Python中翻译整数运算，没有启动客户端、加载其DLL或执行原生指令。原始文件分析前后字节一致。
- 主目录7z目录可读，共2232项，代码后缀只有已知训练场三份C和一份NUT。另一目录服务端7z包含虚拟机磁盘/内存等13项，不是松散技能源码；另一客户端zip无法被本机归档工具正确打开，未声称已遍历。不同版本资料未混入当前实现。

## 字符串解码

直接搜索 normalwave、swordman、.ani 等明文此前无结果。原生错误消息附近的引用指向变换后的宽字符串，其调用入口提供了可检查的解码链：

| 虚拟地址 | 可见操作 |
|---|---|
| 0x01194FC0 | 宽字符入口；调用公共解码器时传单位宽度2 |
| 0x01194FA0 | 单字节入口；传单位宽度1 |
| 0x01194E70，关键区间0x01194F2D～0x01194F5E | 从头部生成长度与初始key，调用实际字节运算 |
| 0x01194610～0x0119466E | 逐32位字与尾部字节解码、更新key |

对本次观察到的0054头：tag = header[1] & 0xFE；单位数 = uint16(header+2) XOR ((tag<<7) OR tag)；初始key = tag OR 0x9A714CA0。完整32位字按 `plain = cipher XOR key`，然后 `key = key*0x1003F+plain`；不足4字节的尾部按低字节XOR，之后 `key = key*0x107+plain_byte`。所有key运算保留低32位。

工具只接受上述精确内层哈希，只扫描已观察到的两块原生数据区域及头部形式，限制长度、边界、严格解码和唯一结尾NUL，并仅索引ASCII可显示内容。最终恢复19869条（本次均为UTF-16存储），不代表所有字符串、函数或游戏行为已恢复。

```powershell
python tools/audit_dnf_native_strings.py --client-exe 'D:\纯60复古\情怀60复古\DNF.exe' --query 'CNSwordman::procAppend' --query 'HADOUKEN'
python tools/test_dnf_native_strings.py
```

输出默认位于temp/skill_logic_audit/native_strings_verified.json。query附带的pointer_candidates只是原代码区中的地址字节匹配；必须再检查指令边界和调用，不能把每个匹配直接当函数调用。工具无第三方包依赖；本次临时静态反汇编使用temp/source_audit_deps下的pefile和capstone，没有改变仓库依赖。

## 波动技能已找到的原生链路

| 地址或字段 | 证据及当前解释 |

| 0x00CC899D～0x00CC89D4 | 初始化状态字段后，虚函数0x49C传入9，随后0x12C设为当前动作。CHR的etc_motions[9]正是character/swordman/animation/wave.ani |
| 0x00CC8B1E～0x00CC8B7C | 判断源技能ID 0x14（20）；分普通/特殊鬼剑士，写对象ID20001/20070，取技能特效，并将触发帧字段写为3 |
| passiveobject/passiveobject.lst | ID20001对应character/swordman/normalwave.obj，ID20070对应normalwave_ds.obj；与上述分支交叉印证 |
| 0x00CB252B～0x00CB2555 | 当前动画帧字段为0时检查等待计时，达阈值后调用0x005821D0并传1 |
| 0x005821D0 → 0x010857E0 → 0x01091D60 | 将帧索引换成累计动画时间，再跳转动画时钟，支持“退出等待帧转入第1帧”的解释 |

| 0x00CB25FB～0x00CB2620、0x00CB27D5～0x00CB2819 | 当前帧达到触发帧字段，且未触发标记为0时，进入对象生成调用并写入一次触发标记 |
| 0x00CC8AA0～0x00CC8AFA | 等待阈值计算扣除若干原动作帧时长，再按角色字段换算；此角色字段、所有取整和速度修正尚待完整确认 |
| 0x00CC90A1～0x00CC90BD | 另一个结束相关字段由换算后的技能时间加静态参数形成；后续使用点0x00CBA589仍需核对 |

CHR来源SHA256：576c7f66296b6dc9882280654a8378a95de6c677388c0a3e9b0050bfbfddb679。wave.ani及SKL/OBJ的哈希见[上一批等级列记录](2026-11-06_地裂波动剑等级列与对象大小修复.md)。这次不再仅靠“wave”文件名猜身体动作：有动作表索引、技能20分支、对象LST ID及逐帧调用共同约束。

仍不能直接把“触发帧3”写成某个固定毫秒：原生入口计算等待阈值，并设置运动/播放速度参数；原程序也存在跳转到保护区的函数，必须追完实际调用再解释。当前运行时的summon2和340ms触发与该链路不符；下一步据此实现身体/武器共用时钟、等待帧退出、专用挥剑特效和逐帧出波。

## 后续接入：地裂对象生命周期

本轮继续跟踪同一精确SHA的内层代码。对象工厂0x00A1D97D比较ID20001，分支0x00A1EFB1调用构造函数0x009EBA00，安装虚表0x015F9E74。对象更新0x009EBAF0先调用基类更新0x007F9E20，再检查当前ANI结束标记（+0x1EC的bit8）并请求删除。这是动画结束销毁的原生依据，不是按效果名称推断。

原OBJ的normalwavefire.ani共五帧、每帧65ms，总长325ms；最后两帧没有攻击盒。旧适配的1500ms寿命导致整段ANI反复播放，新进入范围的目标会在循环后的攻击帧受到伤害。现已使用动画结束生命周期，并让显示层从模拟快照读取相同的loop值，避免所有对象被强制循环。

同时去掉旧适配额外叠加的520px/s平移：原OBJ未提供运动控制配置，已读出的派生初始化0x009EBB30～0x009EBC77只设置大小、百分比与固定伤害，源ANI图片和攻击盒本身已随帧推进。此处严格区分：销毁规则有直接原生指令证据；零额外平移是删除无来源适配、遵循已知配置的实现决定，通用基类所有运动分支尚未穷尽，不能据此声称完整运动模型已证明。

速度调查另确认0x008284A0保存两类速度类型并通过虚函数+0x700取实际速度，随后调用+0x704/+0x708。波动入口先传CONST/CAST，再在技能20分支传ATTACK/ATTACK。结束字段的使用点0x00CBA573～0x00CBA587检查当前状态0x18和状态计时，再与+0x66CC比较；超时进入返回站立调用。仍需核对字段+0x3194写入点、动画速度和取整后才能移植完整状态时钟。

验证：技能专项45项、独立战斗240项、正式完整循环435项和Python技能编译11项通过，日志分别在temp/full_restore/wave_lifetime_test.log、wave_lifetime_combat.log。新增反例覆盖左右朝向、锚点固定、324ms仍显示/325ms移除、消散期新目标不受伤、结束后不重启攻击，以及显式移动/循环对象的原有传递契约。首轮测试夹具错误选用了冰波的非对象hit，已改为明确构造的共享传递夹具并重跑；最终日志无SCRIPT ERROR，不能只看COMPLETE计数。

本轮没有替换身体/武器/挥剑特效资产。summon2与340ms出波依然是待替换的旧适配；整招表现、角色移动、取消条件、速度换算和全游戏其他功能仍在还原目标内。

## 后续接入：身体、武器、专用刀光与原生时钟

已经按上述原生状态链替换normalwave的summon2和固定340ms触发。身体使用CHR动作表索引9的wave.ani，保留源10000ms等待帧；状态控制器在等待阈值后跳到第1帧，专用NormalWaveSlash同时附着，第3帧只创建一次对象。等级伤害列及325ms对象生命周期保留。

### 新增原生依据

- 虚表槽0x016F76A0及其他四份同类表中的+0x5FC对应0x008284A0；+0x700对应0x00828420，按枚举1/2/3/4读取移动/攻击/非武器攻击/施放速度。+0x704对应0x008285B0，+0x708对应0x00828AA0。
- 0x00828AAE～0x00828AC1将第二速度写入保护字段+0x3194；随后乘浮点常量100.0与0.001并调用0x01091E60设置当前ANI百分比播放速度。这闭合了上轮未确认的+0x3194来源。
- 等待阈值采用(CAST_TIME - frame1..3时长)×1000/CAST_SPEED整数截断；技能20分支随后切换ATTACK/ATTACK，结束阈值为CAST_TIME×1000/ATTACK_SPEED整数截断加SKL static[0]。
- 附着虚函数+0x134对应0x00811060；0x008110AA读取+0x3194，并调用相同ANI播放速度方法。地裂附着处0x00CB25D6传入启用速度同步的参数1，确认刀光采用角色动作速度。
- 原字符串MONOCHROME在0x01821468；引用0x01061F58～0x01061F75映射为枚举5。原武器wave前两帧包含type5/RGB255，渲染层为该武器层保留纯色RGB与源alpha。其他复杂混合公式仍不据此推定。

基准速度1/1时等待50ms，第3帧150ms，恢复结束450ms；攻击2/施放0.5时分别100/150/350ms；攻击0.5/施放2时分别25/225/650ms。运行时使用毫秒连续区间跨越来派发帧事件；原客户端每次更新的量化、保护函数与极端速度/负等待分支仍需进一步比对，不能将这几组算例扩展为所有特殊状态完全一致。

### 武器接入暴露的真实缺口

旧武器包只有24个动作。直接用当前全技能动作清单重烘会遇到bloodyraveslash引用超出某原IMG的问题，已保留失败日志，没有跳过检查或伪造空帧通过。本轮增加不可变weapon_appearance_v2元数据包，明确依赖v1的原PNG和manifest哈希，给155件当前装备、63种外观、126个前后层追加已核实的wave。

原武器wave第一帧50ms、总长550ms，身体第一帧10000ms、总长10500ms；直接使用同一个绝对ANI毫秒会把武器夹到最后一帧。本轮显式按身体帧号选择原武器帧，同时保留源武器时长。这是结合源帧42～50和装备层绑定所作的适配；原客户端装备逐帧绑定函数仍待独立追踪，不冒充已完整反编译。

源图、尺寸、依赖、版本、复现及真实截图见[本批任务包](../../../tasks/art_tasks/native_wave_v1.md)。新增一个原刀光图集；combat重建只追加wave/jump动作元数据、刀光及来源哈希，没有改写既有图像。jump为此前后跳所声明的原动作，本批重建补齐记录。
