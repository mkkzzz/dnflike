# 原技能身份与旧档别名合并

前两批有效等级修复暴露了另一条旧档问题：同一原技能可同时存在旧训练ID和规范ID，旧训练项仍使用旧的手写数值，武器奥义则只命中规范ID。本批按相同原SKL路径统一运行身份，并迁移重复购买记录；这是本项目的兼容迁移策略，不是原DNF的存档格式或退款规则。

## 身份依据

| 旧ID | 规范ID | 原SKL |
|---|---|---|
| physical_crit_up | physicalcriticalhitup | skill/swordman/physicalcriticalhitup.skl |
| hp_source | basichpmaxup | skill/swordman/basichpmaxup.skl |
| short_sword_mastery | shortswordmastery | skill/swordman/shortswordmastery.skl |
| blade_mastery | blademastery | skill/swordman/blademastery.skl |
| heavy_sword_mastery | heavyswordmastery | skill/swordman/heavyswordmastery.skl |

匹配使用原路径完全相等，不按名字近似或去下划线匹配。规范定义的原ID经 `skill/swordmanskill.lst` 核对；五份原文件SHA与当前内容包记录一致，具体源ID、旧/新上限和字节SHA见[迁移证据](skill_identity_migration.json)。新增源路径/源ID唯一性检查，避免后续生成两份同源定义。

## 迁移规则与保留数据

- 运行配置只保留规范定义，旧ID作为入口别名；旧命令和原记录查询仍可解析到规范ID。原SKL、生成运行表和购买总预算未修改。
- 旧/新两份都存在时保留较高已学等级，保留该份完整购买账目；相同等级优先保留规范ID的账目。不会把两份等级相加。
- 未保留的重复账目从有效购买表移出，原有“总SP−已花SP”公式自然释放对应额度，不额外增加总SP，也不在每次加载再次退款。免费授予记录仍为0成本。
- 每次实际合并记录旧/新等级、两份完整账目、保留方向及释放SP到 `skill_alias_history`；历史不参与被动计算和SP消费。JSON浮点整数回读统一成整数，重复规范化及往返保存保持一致。
- 迁移先验证所有相关记录，再一次性写回：旧等级越界、非整数、账目长度不符、负数/字符串成本或不一致历史均拒绝。`Session.restore` 操作候选副本，失败不替换当前角色；已有迁移历史的会话也能加载不含可选历史的新档。
- 迁移后旧太刀精通进入规范技能13，能收到武器奥义对应列。已存的等级不会按当前职业学习上限自动删减，购买、退点继续遵循既有校验。

实现位于[技能身份模块](../../../../game_dnf/stats/skill_identity.gd)、[数值API](../../../../game_dnf/stats/api/numbers.gd)和[存档接收入口](../../../../game_dnf/flow/session.gd)。此批没有直接改写用户磁盘上的既有存档，迁移在游戏正常读取/保存流程内发生。
