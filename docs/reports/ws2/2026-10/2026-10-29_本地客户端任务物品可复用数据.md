# 本地客户端任务、物品可复用数据核查

用户要求检查本机60级客户端数据，判断任务和物品表如何实装。本轮只读取原文件，新增取证工具，没有修改游戏内容或存档。

## 结论与旧结论更正

**已有可读的繁体中文源，本机另一套客户端还有可读的简体中文源。** 2026-10-28交接“111没有中文”和旧任务包“只有键名、必须另找中文串表”的判断不成立；本区上一轮引用了该结论，在此更正。此前[前期取证](2026-10-23_前期任务城镇NPC取证.md)已记录CP950正文读取路径。

stringtable.bin同时存放标签、路径、文本键与直接文本。任务/堆叠物品常用连续type-9表ID和type-10键下标，经n_string.lst找到STR正文。`.kor.str`后缀不能证明内容是韩文。

[机器可读证据](2026-10-29_本地客户端任务物品可复用数据.json)保留源哈希、编码、覆盖统计、原表/键/行号、样本和版本差异。以下数量是本轮文件快照，不表示已经实装或筛选好60级内容。

## 全量正文覆盖

“名称解出”表示严格按指定编码读取原文，未润色或简繁转换，不保证每项译法、时代与开放状态符合目标版本。

| 范围 | 111备份 | 简体客户端 |
|---|---:|---:|
| QST文件 / 名称解出 | 3716 / 3521 | 3233 / 3049 |
| 条件 / 完成正文解出 | 3701 / 3514 | 3231 / 3057 |
| EQU文件 / 名称解出 | 74475 / 57331 | 65246 / 53336 |
| STK文件 / 名称解出 | 10491 / 8861 | 10233 / 9769 |
| quest.lst中的ID | 2824 | 3026 |
| equipment.lst中的ID | 67184 | 60536 |
| stackable.lst中的ID | 14499 | 13951 |

111有1个EQU不是对齐B0D0脚本、STK正文79处严格解码失败、扫描文本字段240处缺失引用（QST66、STK174，包含对白）。简体客户端本轮QST/EQU/STK解析失败0、所扫描字段缺失引用0、正文解码失败0。这不等于未知字段、公式及全部规则已得到验证。

**索引归属优先于后缀**：111的stackable.lst有4138条路径以EQU结尾，主要是配方，不应全部当成可穿戴装备。跨版本共有ID中，任务5个、装备2个、堆叠物品231个指向不同路径；路径相同也仍需核对规则。不能直接按跨PVF字符串下标拼接数据。

## 建议实装次序

1. 现有111结构基线保留，直接使用本版本正文解除中文阻塞；简体客户端作为独立来源，仅对ID、规范路径、字段语义核对一致的条目复用文本，差异隔离。包内有60级以后、活动与历史内容，低等级过滤不能独自代表60级白名单。
2. 补数据编译层：原ID及索引归属、任务前置/目标/职业条件奖励；装备完整属性范围/槽位/重量/价格/耐久；消耗效果/堆叠/冷却组；图标与文本来源。保留旧样板ID和存档兼容。
3. 先接现有任务原奖励、1106/1112药剂和任务材料，贯通Inventory、装备数值、消耗品、商店/掉落/任务发奖；现行全局99堆叠及固定药效/冷却需能表达所选源数据。
4. 再接108/4302和格兰后续章节。现行任务运行时仅支持会面、击杀、通关、收集四类，缺NPC/地图/怪物映射或处理器时不开放相应内容。章节展示顺序与真实前置分开。
5. 逐批跑契约/模块检查，再做真实接取、目标累计、条件选奖、交付、存读档、写盘失败回滚和任务进度检查。文本可读不代表玩法实装、经济或原版一致性验收。

## 复现与验证

新增 `tools/audit_dnf_reusable_data.py` 与 `tools/dnf_pvf_archive.py`，只读源文件，输出限定temp。命令中的PVF路径使用各机现有源文件位置。

```powershell
python tools/audit_dnf_reusable_data.py
python tools/audit_dnf_reusable_data.py --pvf <本机简体客户端PVF路径> --encoding gb18030 --output temp/reusable_data/client1031_text_audit.json
python -m unittest discover -s tools -p test_dnf_reusable_data.py -v
```

5项专项检查通过：同键不同表、直接文本/简体编码、9/10相邻边界、缺键/重复键、非法下标/流对齐。新PVF读取器对111备份8项代表文件的SHA256与原提取库一致；两套源的全量扫描已实际执行。本轮未跑引擎，不关闭T0实际加载PVF等待项。
