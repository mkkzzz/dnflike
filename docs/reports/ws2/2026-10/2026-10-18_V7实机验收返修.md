2026-10-18 使用者实测后退回 c5。此前引擎检查通过只证明资源与战斗技术链路，不能证明动作自然或 GM 真正可见。

## 运动和衔接实现

1. 源图先通过人工真发顶/下巴语义标记、同源站高、比例/哈希门禁。失败图没有进入补间；新三连先后退回大头、过小头及错误刀向候选，使用通过复核的 c3/c4 局部修订。
2. 在有效来源之间将原生头高上限收敛为 54px，只缩小较大的有效头部；已小于上限者不放大，实际控制标尺为 53.7214–54px。围绕下巴收敛头部，头部四角作为刚性约束；这属于候选 rig 适配，不延伸原 c3 的用户认可范围。
3. 离线先对齐头部、真实握点、另一只手与地面，再使用 [RIFE ncnn Vulkan 官方 RIFE 4.6](https://github.com/nihui/rife-ncnn-vulkan/releases/tag/20221029) 的运动场和遮挡权重。**同一运动场**处理预乘颜色、alpha、手指层，最后转回 straight alpha。没有使用该模型生成新身份或放大图片。
4. [RTMLib](https://github.com/Tau-J/rtmlib) / [RTMPose](https://github.com/open-mmlab/mmpose/tree/main/projects/rtmpose) 只起草关节点，保留原始点、人工复核覆盖图和绑定哈希。逐腿约束在交叉步态中产生折叠，已从离线步态补间排除；攻击/反应补间只补肩肘与真实手部约束，运行时短状态桥接才临时对齐四肢。不能将姿态模型预测直接当成准确骨骼。
5. 早期 DIS/TPS 方案出现双头、手臂弧圈和衣摆重影；加入逐腿网格后又出现交叉腿纹理折叠，均拒收。最终改为少量稳定锚点和带遮挡的对应场，复核了三连、idle、步态、落地、起身代表帧。旧试验未引用纹理已移到本机 `temp/` 保存，不进入游戏消费目录。
6. 游戏使用相邻原生帧的连续采样；状态改变或同招重新受击时，保存**实际已显示的混合姿态**，通过共用解剖网格逐渐进入新状态。中途取消从当前混合姿态继续，不先弹回 idle。命中停帧同时冻结片段和过渡，查询刀线不能额外推进时钟。连招短桥接放在起手内完成，避免将上一刀的收招叠在下一刀整个引剑段。
7. 落地使用完整 18 tick 恢复，身体从屈膝逐渐回到真实 idle 姿势；起停、防御结束、起身/复活也接到该 idle。它是视觉恢复，未额外锁住输入或重复增加物理跳高。

武器只绘制一把原生贴图，通过与身体/手指相同的握点及投影平面摆放。水平扫砍中两手沿同一柄投影；切换武器不换身体、不重置动作。真实贴图刀口侧绑定在矩阵上，测试直接检查实际刀口朝向相对扫砍运动为正，并对实际 Sprite2D 像素坐标与命中线进行对比。低位巨剑穿地和跑停收刀穿地由离线检查拦下，改为明确的手腕投影/上方收刀轨迹；没有运行时缩短武器或夹刀尖到地面。

## 复现入口

```powershell
python -m pip install -r tools/requirements-motion.txt
python tools/setup_motion_model.py
$env:SWORDSMAN_RIFE_MODEL = (Resolve-Path temp/motion_model/rife-v4.6)
python tools/bake_swordsman_motion.py --install
python tools/test_swordsman_motion.py
python tools/review_swordsman_motion.py --movies
powershell -ExecutionPolicy Bypass -File tools/run_demo.ps1 -Test
```

网络需要代理时，模型安装命令可加 `--proxy http://127.0.0.1:7890`；不修改全局网络或 Git 配置。RIFE 权重只在本机缓存，官方归档/两份模型文件的 SHA256 固定在 `tools/setup_motion_model.py`，实际使用哈希也写入导出 manifest；MIT 原文在 `tools/licenses/rife-ncnn-vulkan.txt`。游戏不依赖 Python、姿态模型或 RIFE 推理库，只消费原生烘焙图。

完整生成来源、头部复核、关节点诊断、手部标定、离线腕部轨迹和输出哈希随源包/导出包保留。重跑局部 `--only` 时 package 会显式标为不完整，不能安装；完整覆盖及资源一致性通过后才能进入游戏试玩。
