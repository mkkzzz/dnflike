# 第二轮动作验收与重做

## 当前结论

用户认可 c6 的 idle 和现有采样流畅度；**没有认可行走、奔跑和三连的动作设计**。转身必须立即翻面；受击需要在真实战斗里能看清。本记录优先于此前 c6 技术交付小结，不能再以增加补间数量解决本轮问题。

| 用户意见 | 处理与证据 |
|---|---|
| idle 可以 | 冻结实际安装的 idle 时钟、帧引用与贴图哈希，见 `art/animations/players/swordsman/v7/sources/base_batch_c7/idle_approval.json`；不是整套认可 |
| 步态像重复同一步，奔跑呆板 | 原 c4/c5 源图中多个连续关键姿势重复同一条前腿，缺少清晰的对侧承重/过步。平滑补间不能补出缺失的动作语义；重做来源关键姿势 |
| 转身像纸片 | 删除自动 turn 过渡和 cos 横向压缩，朝向当帧切换为 ±0.5 等比尺度；保持当前姿态和步态时钟 |
| 三连头几乎不动、身体/刀无力 | 成人头部尺度门禁保留，头部位置不能锁死。重新设计蓄力、踩地转髋、胸肩传力、双手带刀、余势与回正 |
| 没看出受击 | 已有 HIT 映射；但短受击的极值姿势在状态混合期间就开始恢复，削弱了表现。改为一 tick 起始过渡，极值停留三 tick，再走原恢复；不改伤害、无敌或硬直时长 |
| 帧数/流畅度可以 | 本轮不增加帧密度，不把采样数当作新原画张数 |

## 研究依据与观察边界

- [Animation Mentor：完整步态教学](https://www.animationmentor.com/blog/tutorial-animating-human-walk-cycle/)明确区分接触、下沉、过步、上升和另一侧接触；强调髋胸反向转动、足底接地及手臂延迟。用于组织本轮左右两步，不照抄角色或时长。
- [AQWorlds Infinity 官方跑步返修日志](https://aq2d.com/posts/yougottawalkbeforeyoucanrun/)讨论了从旧动画逐帧匹配到高刷新率后仍需调整跑步弹性，并强调放进实际横向移动中看。这里借鉴的是开发者公开的比较方法；本机官方 GIF 返回 403、浏览器截图超时，**未冒称已逐帧看完其持刀动画**。
- [GDC：Powerful and Effective Animation for 2D/3D Games](https://www.gdcvault.com/play/1021657/Powerful-and-Effective-Animation-for)以 Skullgirls 讲关键帧、预备、拖形和时间分配。用于检查起手/释放/余势的差异，不推断该作品的未公开帧表。
- [Dead Cells 原画作者 Thomas Vasseur 的制作自述](https://www.gamedeveloper.com/production/art-design-deep-dive-using-a-3d-pipeline-for-2d-animation-in-i-dead-cells-i-)强调先用少量关键姿势把动作和节奏做成立，再组织插值；本轮据此先复核身体动作，而不再全套加密。只引用公开文章，不声称观看了其受限媒体。
- [Ghan Lek 的双武器动作练习复盘](https://ghans.artstation.com/blog/0YrB/anti-mage-animation-reel-breakdown)区分保持 idle 轮廓的跑步与胸部参与的跑步，并指出连段里上一刀余势与下一刀预备撞在一起会显得机械。这是作者个人 DOTA2 角色练习，**不是 DOTA2 官方动画**。
- [Halo Infinite 动画作者作品集](https://marcellis.artstation.com/projects/aGyndz)给出持剑 run 00:27、sprint 00:35 的明确查看片段；这是后续视觉研究入口，尚未取得播放器逐帧证据。
- [DFO 官方男鬼剑士页](https://www.dfoneople.com/gameinfo/character/Slayer%28M%29)与[发行商官方 Katana ZERO 预告](https://www.youtube.com/watch?v=-MvvmPKGEHA)已定位。当前未取得可逐帧核对的播放器画面，不能写成已完成视频观察。其他作品的持刀跑动视觉研究仍需补证。

以下是本项目针对自身缺陷的设计判断，不冒充上述作品的官方制作规范：

| 片段 | 需要真正画出的关键姿势 | 回放前检查 |
|---|---|---|
| walk | 近腿接触→承重→远腿过步→远腿接触→承重→近腿过步 | 相同两条腿交替；接地脚向后扫、摆动脚离地前送；衣摆不遮没膝踝关系 |
| run | 两侧分别接触、压缩、蹬地/过步和腾空 | 前倾来自整体重心；持刀手在后髋附近控制刀尖净空，空手参与平衡；不能重复同一侧飞奔姿态 |
| attack1/2 | 方向相反的加载、蹬地转髋、胸肩展开、双手过目标、余势 | 头跟随躯干平移/倾转，不能像固定头贴纸；脚下支撑先于手臂放出 |
| attack3 | 下沉引剑→腿髋伸展→胸肩上带→双手上挑→回正 | 身体不能直立不动只转刀；刀口朝向与扫过速度匹配；三种实际长度不过地 |

## 本轮代码验证

Godot 完整回归实际执行 `[DEMO_TEST] COMPLETE checks=427 failures=0`。新增 idle/walk/run 三种状态的即时翻面检查，以及真实 Monster._attack→Player.take_hit 的扣血、HIT、可见后仰、击退和原硬直结束检查。当前资源契约 10 项通过，包含获认可 idle 的逐字节保护。它们证明技术行为，不证明新步态和挥刀已经完成。

## c7 源图试做

实际调用内置 image_gen，真实传入已认可 c3 比例图与 standard_v1 身份图；试做文件、完整提示词、额外骨架引导及实际输入哈希保存在 `art/animations/players/swordsman/v7/sources/base_batch_c7/`。设计图实际为 1672×941 RGBA，去刀编辑为 1671×941；逐文件尺寸见生成记录。均未达到请求的整张 2560×1440，没有放大。

- `run_near_c1`：持刀后置姿势试做；站姿发顶碰边，拒收。
- `run_far_c1`：请求另一条腿承重，结果近/远腿重叠仍不清楚，拒收。
- `run_alternation_c2`：实际传入程序绘制的双色腿骨架引导；生成结果仍有歧义，且站姿发顶裁切，拒收。证明“传了骨架”不等于姿势可用。
- `attack1_c1`：保存蓄势/切过目标/余势三姿势样张；比例标定、手指/身体/武器分层和连贯动作评审均未完成。源图带刀只用于发力设计，不能作为自由换武器运行资源。
- `attack1_c1/body_c1`：已试做去刀身体，逐像素放大复核发现草拟下巴点有落在领口者，保留为未签字草稿；未将草点写成 G1 通过。`body_c2` 头部缩小编辑又出现跨姿态头部尺度不一致，拒收，不能按提示词的百分比声称实际已经一致。

上述图均未进入游戏。不会把“新样张”登记成“已经修好”，也不会用用户对旧比例或流畅度的认可替这些新源图签字。

## 录像纠正

旧 `gameplay_native_2k.mp4` 的流元数据实际是 1920×1080，虽然对应 PNG 帧缓冲为 2560×1440；原命名错误，已撤回该 2K 录像说法。MovieWriter 在窗口后来改尺寸之前就采用工程的 1080p 覆盖值，单看捕获脚本中的 window_set_size 不足以证明电影分辨率。旧录像保留为 1080p 历史证据；本轮转身/受击改用逐帧原生 PNG 再编码，并检查视频流尺寸。

本轮实际得到 134 张连续 render_frame 的 2560×1440 PNG，直接编码后流元数据确认 `2560x1440, 60 fps`，没有缩放；见[实机回放与第一刀源姿势](../../../previews/v7_c7_feedback/index.html)及旁附 JSON 的每帧哈希/时间线。转身、真实轻受击和重受击在同一个真实游戏实例中回放；这不是 c7 步态或三连已实装的录像。

## 续做入口

先补可观察的官方持刀跑动参考；修正近/远腿明确的接触和过步源姿势，逐姿势通过比例与肢体语义检查，再输出完整两步裸动作。三连先做一刀的完整发力样片、同身体三武器回放与方向评审；按 [14 全流程](../../../design/14_美术资源全流程.md) 的样张门获认可后，再推广到其他两刀。不要先整套烘焙后再问发力是否成立。

## 第一刀方向认可与闪烁反馈

用户回复“感觉还不错，可以继续完善”，认可的是 `attack1_c1/source.png` 的蓄势/切过目标/余势方向，绑定哈希见 `art/animations/players/swordsman/v7/sources/base_batch_c7/attack1_c1/direction_approval.json`；不扩展为完整三连、步态或可换武器验收。去刀身体 c3 逐像素复核真发顶/下巴后 G1 通过，原生380px站高下实际头高54.39–55.15px，只缩小。继续完善代表片段。

用户同时指出受击闪了一下，确认来自旧无敌期的每两tick透明度切换，非掉帧。V7 改为保持 alpha=1 的轻微亮色渐退，原无敌/伤害/硬直不变；完整回归实际428项通过。另存42张原生2K哥布林真实命中逐帧录像 `docs/previews/v7_c7_feedback/hurt_no_flash_native_2k.mp4`，旁附时间线记录每tick实际 visible_tint；全程 alpha=1，流尺寸确认2560×1440，60fps。旧含闪烁录像保留对照。

## 连续样片的中间失败（未实装）

第一轮分层运动虽通过来源与刀口数值检查，但出现抹头和收脚变形，拒收。仅保护神经残差不足以防抹头：Delaunay 三角形会穿过头部四角边界，需要约束头部整个内部区域；该区域仍按源图身体轨迹移动。二维手臂IK在转体投影中强行维持屏幕骨长会把肘部外翻，已拒收；不能以骨长数值正确替代三维动作投影。新补一张真实收招源图，原图与G1/导出记录在 `art/animations/players/swordsman/v7/sources/base_batch_c7/attack1_recover_c1/`。后续继续补实际过渡姿势，不把失败补间交给用户当成修复成品。

## 跨工作区文本绑定修正

同步 ws3 可破坏物改动后，完整引擎回归 434 项通过。发现 Windows 默认 CRLF 与 Git 的 LF 规范化导致源配置哈希失配：逐项验证仅换行等价、可还原旧字节，再重绑定配置/导出记录，迁移凭证见 `art/animations/players/swordsman/v7/sources/base_batch_c6/lf_binding_migration.json`。保留原烘焙配方，全部 PNG 哈希、已认可 idle 片段及其时序均未变化，没有把格式迁移冒充重新烘焙。生产脚本显式写 LF，消费副本和预览文本固定 LF；资源检查同时核对配置、比例审计、身体 manifest、关节和迁移凭证哈希。安装入口另加已认可 idle 的逐字节保护，阻止后续整套重烘覆盖。
