# UI二轮精修与清晰度

## 用户要求与交付范围

用户认可上一版组件样式方向，追加HUD黑条、版式/层级、物品说明、大立绘、像素清晰度与ASDFGH六项修正。全中文、原资源、不用临时色块的约束继续生效。
本轮只改流程/城镇/UI表现与配套构建、验证、资料；保留ws1公开combat/api，不改main.gd、view/、ui/combat/和战斗内核。

| 反馈 | 根因及修正 |
|---|---|
| HUD黑带 | 城镇地面在屏幕y508结束，HUD中心透明处露出清屏色。每列原地面末48px按1:1延续到HUD之下；未加纯色遮盖。另修WindowCommon组装边缘空隙导致的窗底齿状黑条 |
| 排版层级 | 背包原位置压住HUD，页签最小宽与间距不符。原图分段裁掉48px空白，装备区与8×4网格不缩放，窗口置于(484,22)、可见高476；商店同顶部并排。页签字体/内距校正；任务分类、目标与奖励分层；地图标题让开顶栏；结果独立全屏并隐藏HUD |
| 物品说明 | 原普通窗板误用。改为Interface/Global.img的0/1/2、4/5/6、8/9/10九片，24×25原生组合、6px边距；细金边半透明黑底，品级/名称/类型/要求/效果/操作分区，悬停避让仍有效 |
| 大立绘 | 原先误取Map/Npc/NpcFace01.img第8帧64×130。对白改用Interface/npc_dialog_face.img第0帧林纳斯186×226透明上半身，1:1绘制、浮在底部对话板左侧；正文不压人物。商店仍可使用小头像 |
| 清晰度 | 源图本身为旧版低分辨率像素素材；另有整帧800×600渲染再放大的字体问题。loop入口改CANVAS_ITEMS，逻辑800×600，动态文字按物理窗口分辨率绘制；贴图nearest/整数缩放不变。加入原始800×600、两倍1600×1200显示选择，默认按屏幕可用区选择能放下的一档 |
| 技能键 | HUD固定ASDFGH：A拔刀、S连突、G格挡，D/F/H未配置保持空槽；Z上挑、X普攻、C跳跃继续可用但不进入技能栏。药剂改1，实际输入验证H不吃药、1扣药并恢复HP。没有伪造D/F/H技能 |

背包负重原先固定1.2且进度一直满，现按持有物品计算与原进度条裁切显示；试炼物品weight仍为E-ADAPT，未冒称恢复原版物品表。
结算提示随翻牌更新，原卡牌金币装饰与奖励文字错开；领奖事务仍只支付一次。

## 清晰度与视觉边界

原HUD为800×92、大立绘186×226、地面块224×235，放大后能看到原始像素属于素材分辨率限制，不能靠调整设置生成高清细节。本轮未AI补画、模糊滤镜或重采样源图。
动态字体在1600×1200窗口直接绘制，源图仍按2×整数像素显示；800×600对照单独保留。文字方案依据[Godot多分辨率说明](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)，实际帧缓冲尺寸及鼠标点击已验证。
手机页缩略图采用浏览器正常缩小，弹层可切适合屏幕/原始像素；不再把1600图额外强制放大成3200来评审。
完整美观/原版一致性仍待用户复核。本轮窗口锚点和删空白为适配设计；原客户端同条件逐状态对照尚缺，战斗场景边缘留空/T2世界接入仍属后续范围。
