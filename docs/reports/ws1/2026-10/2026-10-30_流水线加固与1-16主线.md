# 流水线加固与 1～16 级主线

基线 `0dd5d408`。本项把内容接入从"记得按顺序跑工具"收束为可重复的原子流程，并把 1～16 级关键路径从源任务编排到运行时事务。设计口径沿用既有结论，不再重开决策。

## 一、流水线加固

| 原风险 | 现在的行为 |
|---|---|
| 战斗资源构建中途失败，现行 `combat/` 已被删空 | 完整构建先落到 `temp/`，成功后 `os.replace` 换入；旧树保留到换入成功，失败不动现行资源 |
| 重建后 Godot `.import` UID 全部变化 | 换入前只把**仍然存在同名资源**的旧 `.import` 带入暂存树，稳定 UID；不复制已删除资源的孤儿导入 |
| 重跑路线生成覆盖手工入口、前置、等级与隐藏状态 | `build_dnf_dungeon_route.py` 默认保留已有条目；只有显式 `--refresh-existing` 才刷新路线，并保留 `requires`、`min_level`、`hidden`、`dungeon_region` 等运行字段 |
| `dungeons.json` 写一半进程退出 | 路线与批量写入改为临时文件 + 原子替换 |
| 重应用城镇房间清空运行配置 | `apply_dnf_town_rooms.py` 只更新名称、资源、落点与走区，保留 `dungeon_region`、`dungeon_entry`、NPC 站位、标签与镜头；NPC 锚点从原版 `[NPC]` 表导入，不再手填 |

`python tools/pipeline_dnf.py dungeon` 增加 `--refresh-existing` 透传。三个加固点各有独立单元测试，并已并入 `tools/run_dnf_loop.ps1 -Test`：

```powershell
python tools/test_build_dnf_combat_assets.py
python tools/test_build_dnf_dungeon_route.py
python tools/test_apply_dnf_town_rooms.py
```

`pipeline_dnf.py verify` 从四道闸门扩为五道：副本契约、BGM 覆盖、走区一致、任务进度、1～16 主线。

## 二、1～16 级主线

`game_dnf/data/campaign_1_16.json` 固化 **41 个必需源任务**：

- 第 1～4 章主线、第 6 章、第 7 章开头，以及源前置要求的时空碎片桥接；
- 排除独立教学/居民委托、G.S.D 陪战分支、16 级后任务与其它时空碎片分支，避免把可选支线混入关键路径；
- 源任务 4465～4474 的自动接取/交付只对 `the_last_mehmet` 生效，运行时由 `auto_quest_ids` 白名单控制，不扩散到其它任务。

内容与运行时同步补齐：

| 范围 | 结果 |
|---|---|
| 副本 | 格拉卡 `grakkarak` 五房路线接入森林入口，源 BGM/怪物/奖励可用 |
| 城镇 | 新增西海岸 · 魔法师公馆与莎兰；罗莉安落在西海岸、索西雅落在赫顿酒馆，使用原地图锚点、原 sprite/立绘/语音 |
| 任务目标 | 支持 `clear_map` 按副本格完成；1614 映射到 `draconiantower` `[2,1]`，房间清除事件发 `map.cleared` |
| 任务事务 | 接受时发放 `[depend give item]`；`[monster reward item]` 进入任务掉落；`[clear reward item]` 在通关后按难度/持有上限发放 |
| 自动流转 | 自动接取/交付可跨服务、拾取、战斗事件推进，写盘仍走现有候选事务 |
| 难度 | 原难度 2 落为 `expert`，四档系数 1.0 / 1.25 / 1.5 / 1.75，选择与结算界面同步 |
| 物品 | `items_native_v2` 重烘 3,792 种物品图标、1,740 帧、两页图集；运行时改读 v2，v1 保留 |

当前统计：12 个城镇、19 个副本条目（17 条当前可选 + 1 条隐藏 + 1 个旧样板）、117 个房间、15 个 NPC 站位；运行任务 120 条，史诗 97 / 941，1～16 主线 41 / 41、缺失 0。
