## 一、交付与运行

| 产出 | 作用 |
|---|---|
| `tools/export_dnf_map.py` | 只读完整库，导出副本格、地图、图块、物件、怪物、门对象、原始 token 与诊断；IMG 解码为 PNG |
| `tools/test_export_dnf_map.py` | 5 项规则单测 + 1 项完整库导出集成测试（库缺失时跳过） |
| `game_dnf/scripts/native_map_loader.gd` | 读取导出 JSON，建房间节点、层级、视差、门状态、走区查询 |
| `game_dnf/scenes/map_preview.tscn` | 独立验证场景，不进入 main.tscn |
| `tools/run_dnf_map.ps1` | 缺导出时自动导出；`-Test` 无窗口检查，`-Capture` 屏幕外截帧 |

```powershell
python tools/export_dnf_map.py            # 输出到 game_dnf/assets_local/native_maps/lorien/（Git 忽略）
tools/run_dnf_map.ps1                     # 打开验证场景：PgUp/PgDn 换房，←/→ 平移，O 开关门，F2 走区
tools/run_dnf_map.ps1 -Test               # 无窗口检查
```

导出物只写入 `temp/` 或 `game_dnf/assets_local/`，工具拒绝其它路径；源码库只含工具、加载器与文档。

## 二、坐标与结构解释

| 项目 | 解释 | 证据 |
|---|---|---|
| 地图 x | 屏幕像素；每个 `[tile]` 一列宽 224 | E-PARSE：图块 IMG 画布 224；右门 x 在 lorien 各图为宽度−10～−16 |
| 地图 y | 地面纵深，screen_y = y + 120 − z | E-INFER：通行网格 30 行×12 = 360，贴齐 480 高画布底部；全库 2488 图中上门 y 有 298 张、下门 y 有 471 张恰在走区边缘，其余假设明显更差 |
| 通行网格 | 每列 14×30 格，格 16×12；0 可走、2 阻挡 | E-INFER：全库 19582 个怪物出生点 92% 落在 0 格；其它取值未知 |
| greed 字母 | 字母−A 为门位掩码：右1 上2 左4 下8 | E-INFER：24 种位序全库对比最优；lorien 六格门全部互相成对 |
| 起点/领主 | `[start map]`/`[boss map]` 为候选格坐标对 | E-INFER：值域与 `[size]` 2×3 一致；随机规则未知 |
| 格→地图 | 地图 `[dungeon]` 含本副本且 `[greed]` 含该格字母即为候选 | E-INFER：一个格可有多张候选，选择规则未知 |
| 门对象 | `[pathgate object]` 10 个 ID 依次为左普/左领主/左墙、右普/右领主/右墙、上普/上领主、下普/下领主 | E-INFER：与 passiveobject.lst 文件名完全对应 |
| 门图像 | IMG 路径 `%d%d` 由 `[int data]` 每对第二值补两位；第一值 0 常显、1 关、2 开 | E-INFER：补出的文件均存在（普通 01、领主 05）；与 Close/Open 动画名一致 |
| 特殊物件 | `id,x,y,z,N` 后接 N 组 `[类型]+5 值` | E-INFER：lorien 全部记录可整除切分 |
| 层序 | distantback < middleback < bottom < closeback < normal（按 y 排序）< close | E-INFER：按标签名排序，原版绘制顺序待录像 |
| 视差 | 远/中景按 far/middle sight scroll 百分比滚动并横向重复 | E-INFER；near sight scroll 只保留原值，未应用 |
| 背景 y | 背景按 ANI 原 pos 绘制（y=−80）；dgn `[background pos]` 80 只保留 | E-UNKNOWN：两者是否抵消需原版截图 |
| 动画帧 | 色值项 9 作 modulate，项 10=1 视为向下一帧插值，项 11 type 2 视为加色 | E-INFER：用于门开启淡出与光效 |

视口按 640×480 试验（DNF-D004），只在验证场景内设置，不改 `project.godot`。

## 三、诊断（lorien 导出）

导出无 error/warning，112 条 info：
96 条为粒子工厂物件（ID 5、6，无 `[basic motion]`）只保留数据未渲染；16 条为各图未解释标签只保留原始 token
（`[event monster position]`、`[monster specific AI]`、`[NPC]`、`[pvp start area]`、`[player number]`、`[type]`、`[map name]`）。
怪物 10 值记录只解释 ID 与 x/y/z，其余 6 值未知；门对象附带的 `LeftDoor.til` 等门口通行图块未应用。
s0、s1、5、6、7 号图的 greed 字母不在本副本格中，导出但未装配。

## 五、需要 ws2 补的原版证据

1. 洛兰副本实际房间顺序：同一格多张候选（如右上格 EE 有 4/9/b1/bn12/s3）时实际出现哪张，是否随机。
2. bn10 或任一房间的整屏录像（左端→右端平移），用于核对背景 y、远中景视差、near sight scroll 与层序。
3. 门开启过程录像：淡出时长、光效是否加色、领主门颜色与本导出对比。
4. 走区边缘实测：角色贴上/下边缘与左右门口时的位置，核对 12 单位行高与门口通行图块。
5. 怪物 10 值记录其余字段、`[monster specific AI]` 与事件怪物的实际效果。
6. 视口分辨率与缩放（640×480 是否原版逻辑视口）。
