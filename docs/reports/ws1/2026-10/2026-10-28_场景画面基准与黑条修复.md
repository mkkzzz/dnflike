# 场景底部黑条与门悬空：根因与修复

## 一、用户现象

城镇与副本场景最下方是一条黑带；城镇靠"把每列地砖末 48px 复制一条"补上；下方门不贴底，卡在黑带上方。

## 二、根因

三套纵向量没有统一基准，且副本里的一次补偿方向用反：

1. 原版 TIL 地砖的纵向范围是 245…480，背景层 −80…295（洛兰 15 张图与艾尔文逐张一致），世界美术底就是 480；画布按 600 布置，差 120。
2. `view/map_stage.gd` 原先把地图根节点设成 `-screen_y_offset`（−120）。这行只对锚点成立（`ground_to_screen()` 已给门/物件加 120），地砖与背景是屏幕空间、没有这 120，于是被净上移 120，世界底从 480 掉到 360 → 底部 120 黑。
3. 循环入口又用 `battle.scale = 1.25`、`position.y = 130` 把 640×480 的战斗视图塞进 800×600 画布，`360×1.25+130 = 580`，剩 20 px 黑（1080p 下 36 px），门底正压在这条线上。
4. 城镇把世界底对齐到 HUD 顶 508（`town.position.y = 28`），但 HUD 图 y=0…47 是镂空（alpha 统计 12%～21% 不透明），508…556 没有世界内容，于是用每列末 48px 地砖复制填补。

## 三、修复

新增 `game_dnf/view/world_frame.gd` 作为唯一基准：画布 800×600、`ART_DY = 80`、`MAP_DY = 200`、HUD 顶 508。

| 文件 | 改动 |
|---|---|
| `view/world_frame.gd` | 新文件：画面基准常量与推导说明 |
| `scripts/native_map_loader.gd` | 地砖/背景 +`ART_DY`，`ground_to_screen()` 加 `ART_DY`（锚点合计 +200） |
| `view/map_stage.gd` | 去掉根节点 −120；相机窗口 640 → 800；调试网格用 `MAP_DY` |
| `view/battle_view.gd` | 角色/敌人/物件/特效/残影/跳字统一经 `_canvas()` 加 `MAP_DY`；HUD 传入画布宽高 |
| `flow/loop_root.gd` | 删除战斗 `scale=1.25` 与 `position.y=130`；城镇不再位移 |
| `town/native_town.gd` | 删除 `extend_ground()` / `append_strip()`（48px 补条）；脚点与门锚点改用 `MAP_DY` |
| `ui/combat/*` | 底栏、通关/暂停浮层、提示、怪物血条按视图给的 800×600 布局，不再写死 640×360 |
| `scripts/main.gd` | 独立战斗入口也套同一份内容变换（headless 不受影响） |

结果：背景 0…375、地砖 325…560、HUD 508…600，画面 0…600 每一行都是原图像素；下方门锚点 548，贴在地面上；没有任何缩放、拉伸或复制。

## 四、验证

- `tools/run_dnf.ps1 -Test`：143 项 failures=0。
- `tools/run_dnf_loop.ps1 -Test`：348 项 failures=0（新增 5 项：城镇美术底边 ≥556 且无补条节点、战斗美术底边 ≥556、战斗根节点无缩放无位移、地图根节点纵向偏移为 0）。
- 本机原先缺 `assets_local/loot`，循环套件会挂 5 项掉落断言；按 `python tools/bake_loot_sprites.py --library <完整库>` 补齐后全绿。

## 五、遗留

- 视觉最终以用户实机为准；HUD 底栏内的系统字体与程序矩形仍属还原缺口 G05/G06，不在本次范围。
- 城镇角色最深可走到画布 552，会被 HUD 顶部 508 以后遮住下半身，符合"原版世界底在 HUD 之下"的排布，实机若觉得碍眼再单独调可行走上限。
