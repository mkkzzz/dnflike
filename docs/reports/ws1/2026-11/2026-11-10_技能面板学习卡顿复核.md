# 技能面板学习卡顿复核

## 结论

当前技能面板的“加点”没有复现秒级死锁或整窗重建。拉取 ws2 的一百余个提交后，如果不先导入新增资源，首次运行会大量报 `res://.godot/imported/*` 缺失；这类资源扫描和补导入会让界面看起来卡死。完成一次 headless import 后，正式流程中的加点回调约 **43 ms**，退点约 **45 ms**，连续第二次加点约 **41 ms**。

之前发布的优化仍在：[2c8e7a20](https://github.com/mkkzzz/dnflike/commit/2c8e7a20) 之后的 `shared_config()`、节点原位刷新、保留树/滚动和说明局部位图刷新没有回退。

## 复现与测量

| 项目 | 结果 |
|---|---|
| 未导入最新资源的 `--numbers-only` | 出现大量缺失 `.ctex` / `.oggvorbisstr`，不能作为有效运行结论 |
| 完成 Godot 4.7.2 headless import 后 | 导入无 `SCRIPT ERROR` / `ERROR:` |
| 正式加点回调 | **43.457 ms** |
| 正式退点回调 | **44.663 ms** |
| 第二次连续加点 | **41.364 ms** |
| 面板首次打开 | **8.994 ms** |
| 面板热开中位数 | **7.453 ms** |
| 技能切换中位数 | **0.004 ms** |
| 长说明刷新中位数 | **1.936 ms** |

测量使用可丢弃的 60 级剑魂档，走正式 `game.act("numbers.skill")`、存档提交、HUD 同步和技能面板局部刷新，不是只调用数值接口。

## 回归补充

- [test_ws1_panel_contract.gd](../../../../game_dnf/tests/flow/test_ws1_panel_contract.gd) 新增真实加点/退点事务和临时存档路径，防止只测“界面刷新”却漏掉存档与 HUD 同步。
- [test_ws1_skill_learning_latency.gd](../../../../game_dnf/tests/flow/test_ws1_skill_learning_latency.gd) 覆盖正式城镇入口的首次加点、退点和第二次加点，单次回调预算为 **250 ms**。
- 契约分别通过 33 项和 11 项。headless 技能面板性能工具保持通过。

## 处理建议

拉取大会新增资源批次后，先执行一次：

```powershell
& tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path game_dnf --editor --import --quit
```

再启动正式入口。若完成导入后仍出现超过 1 秒的卡死，需要保留 `%APPDATA%\Godot\app_userdata\格兰之森 · 单机版\logs` 最新日志，并注明职业、技能名、是否首次打开面板及点击次数；当前证据不足以把它归因于技能逻辑本身。
