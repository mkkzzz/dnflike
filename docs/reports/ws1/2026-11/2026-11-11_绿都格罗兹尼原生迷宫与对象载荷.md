# 绿都格罗兹尼原生迷宫与对象载荷

本批把 `grozni.dgn` 的普通 block 8 接入隐藏正式 `native_maze` 路线，闭合 8×3 源网格、15 个连通房、13 张唯一 MAP、129 只普通路线怪、Cypher 领主、67 个场景对象和两首原曲。结论只到 `runtime`：四张墙门原图、树投手行为动作、stone/odesabox/cover 可破坏契约、封印门、任务、城镇入口与用户实机验收仍未闭合。

## 一、来源与多迷宫选择

- 原路径 `dungeon/village/cartelarad/grozni.dgn`，SHA256 `6573a9ef1a05fb400c903b97b2ae89543504fb5cdf804d778c1bc26a289b5970`。
- DGN 本地化名称为 `綠都格羅茲尼`，正式名称使用简体 `绿都格罗兹尼`；最低等级 53、basis level 56。
- `[worldmap pattern info]` 指向 `WorldMap/SelectdungeonSlot/cartel.img`；任务源位于 `westcost/grozni`，route region 使用 `westcoast`。
- DGN 有 10 个 `[maze info]` block。block 0～7 是 quest 3907～3911/3919～3921 变体并带 escape，block 9 是 quest 3917 + escape + hell；block 8 是唯一同时没有 `quest connection`、`escape hell`、`hell dungeon` 的普通布局。

## 三、对象与可破坏物

全部布局共 121 个对象，其中 116 个 passive object、5 个 special passive object；61 个没有 `[basic motion]`。

普通路线 67 个对象：

- 25 个 `groznyintree0`、3 个 `groznyouttree0`、3 个 `groznyouttree1`、1 个 `groznyouttree2`、1 个 `groznyouttree3`、3 个 `cartel_table`、1 个 `cartel_chair`：可渲染静态障碍。
- 21 个 `stone`、5 个 `odesabox`、4 个 `cover`：结构上符合 `NativeBreakable.supports()`，但 OBJ 没有 HP/阶段/破坏动作契约，运行 prop 为 0。
- `cover` 还带未知 trap 2000/2010；gap 顺序保留 `native_breakable_source, native_special_object, 2000, 2010`。

本批没有新增 `[special passive object item]`，`NativeBoxLoot.required()` 为 false；继续使用 `items_original_v10`。Stone/Odesabox/Cover 的粒子帧和粒子表已编译，但不能据此宣称可破坏行为已接通。

## 六、未闭合

- Cartel Arad 的 `ca_exitup010.img` 与 `ca_exitup08.img` 四个左右墙门帧在已发布图库中没有 validated IMG；本批只验证这些对象不属于普通路线绑定门，未制作替代图。
- Tree Thrower 的 `shootTree.act` 行为、攻击投射物/伤害、声音和实际选招仍未接通。
- Stone、Odesabox、Cover 的 HP、阶段、破坏动作/音效和 trap 2000/2010 未取证。
- Cypher 六招虽然入运行表，但阶段、移动/瞬移组合、冷却共享、目标选择和六招实际命中仍需原客户端同条件验收；bookshelf/Dark Crow 的多招排序同样不能只靠表顺序宣称完成。
- 封印门 60043、事件怪 61728、quest 3907～3921、九套 quest/hell 布局、任务奖励、城镇入口、结算与回城链未接入。
- `westcoast` 当前城镇选择器只指向 Sky Tower 路由；Grozni 仍是隐藏 `FlowSession.depart` 入口。
- 自动化与 headless 通过不代表原客户端同画面、声音、手感或用户验收。
