# 协作总纲

> 所有工作区（人 + Agent）的**开工入口**。本文只规定协作方式，不写项目内容。
> 项目内容入口见 [文档索引](07_文档索引.md)。

## 一、工作区

本项目有多个并行工作区，每个工作区 = 一份独立 clone + 其使用者 + 其 AI Agent。
清单见 [工作区登记](03_工作区登记.md)。

**开工前必读**（按顺序）：

1. [进度看板](01_进度看板.md) — 现在到哪了
2. [待办](02_待办.md) — 卡在谁那里
3. [交接日志](04_交接日志.md) — 最近发生了什么

## 二、同步节点

| 时机 | 动作 |
|---|---|
| 开工前 | `git fetch` + 读上面三份；发现"卡在自己这一侧"的待办，主动向使用者提出 |
| 提交前 | `git fetch`，确认是否落后于远程 |
| 提交后 | `git push` + 更新看板自己那行 + 追加交接日志一行 |
| 收工前 | `git status` 确认无残留（跑过引擎后也应保持干净） |

## 三、分支与冲突（纯 main）

**不使用功能分支**，所有人提交到 `main`。

- 提交前必须 `git fetch`；落后则 `git pull --rebase`，不制造多余的 merge 提交
- 禁止 `git push --force`、`--amend`、跳过 hooks
- 冲突时**保留双方成果**；无法判断时停下并与对方沟通，不要自行丢弃他人改动
- 预判会与别人改同一文件时，先在 [工作区登记](03_工作区登记.md) 的"占位"表登记一行

## 四、提交规范

格式：`<类型>：<描述>`

| 类型 | 用于 |
|---|---|
| 设计 | 设计文档、方案 |
| 实装 | 接入游戏工程的改动 |
| 修复 | 缺陷修复 |
| 资源 | 美术 / 音频资源 |
| 文档 | 纯文档改动 |
| 工具 | 脚本与工具 |

不得提交：凭证、私钥、未授权素材、`temp/` 产物，以及跑引擎产生的噪音文件。

## 五、信息在哪看（权威范围）

| 想知道什么 | 去哪里 |
|---|---|
| 当前进度 | [01_进度看板](01_进度看板.md) |
| 卡住了什么、等谁 | [02_待办](02_待办.md) |
| 某次交接 | [04_交接日志](04_交接日志.md) |
| 某版本资源状态 | [05_版本注册表](05_版本注册表.md) |
| 工作区与占位 | [03_工作区登记](03_工作区登记.md) |
| 设计内容 | `docs/design/` |
| 怎么写文档 | [06_文档规范](06_文档规范.md) |
| 全部文档地图 | [07_文档索引](07_文档索引.md) |

同一事实只在一个地方维护。若发现两处描述不一致，以本表指定的权威位置为准，并修正另一处。
