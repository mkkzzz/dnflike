# 文档规范

> 目的：让文档在规模增长后仍然可读。核心约束是**单个文档不膨胀**。

## 一、单文档体积上限

| 文档类型 | 上限 | 超出后怎么办 |
|---|---|---|
| 项目级（`docs/project/`） | 150 行 | 拆出子文档，主文档只留结论与索引 |
| 设计（`docs/design/`） | 300 行 | 拆成 `NN_模块.md` + `NN_模块_子主题.md` |
| 过程文档（`docs/reports/`） | 不限 | 天然按次归档，不必拆分 |
| `README.md` | 60 行 | 超出部分移入 `docs/`，只留链接 |
| `AGENTS.md` | 120 行 | 细则移入 `docs/project/`，只留入口与红线 |

**拆分判断标准**（满足任意一条就该拆）：

- 读一遍超过 5 分钟
- 包含超过 3 个不相关的主题
- 超过 3 个月仍在被追加（说明它是"流水账"而非文档）

**反例**：README 若持续吸收功能清单、键位表、管线细节、进度记录，会膨胀成一份无法阅读的巨型文档；正确做法是这些内容各有归属（见第三节），README 只保留基础须知。

## 二、README 定位

README 只放**基础须知**，控制在 60 行内：

1. 项目是什么（一句话）
2. 怎么跑起来（启动命令）
3. 怎么验证（测试命令）
4. 去哪看更多（指向 [文档索引](07_文档索引.md)）

**不放**：完整功能清单、操作键位表、美术管线细节、历史进度记录、版本说明。

## 三、目录职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `docs/project/` | 协作规则、进度、待办、登记、日志、版本表、文档规范与索引 | 设计内容、过程记录 |
| `docs/design/` | 设计文档（长期维护、持续修订） | 一次性过程记录 |
| `docs/reports/<ws>/<YYYY-MM>/` | 过程文档（按工作区 + 月份归档） | 设计内容 |
| `docs/tasks/<类别>/` | 任务包（单项规格、批准、交接） | 通用规范 |
| `docs/previews/` | 评审媒体（GIF / MP4 / 预览图） | 源文件 |
| `docs/screenshots/` | 实机证据 | 概念图 |
| `art/` | 源图、生成记录、导出资源 | 过程文档 |

**硬规则：`docs/` 根目录不再新增文件。** 过程文档一律进 `docs/reports/<ws>/<YYYY-MM>/`。

## 四、命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 过程文档 | `<YYYY-MM-DD>_<主题>.md` | `2026-10-14_V6实装错位修复与验收.md` |
| 工作区 ID | `ws<N>` | `ws1` |
| 资源版本 | `v<N>` | `v6` |
| 资源语义 ID | `<type>.<subject>.<purpose>` | `actor.player.base.combo.1` |
| 任务包 | `<类别>_<范围>_<序号>.md` | `art_uppercut_01.md` |

## 五、新增文档流程

1. 按第三节判断它属于哪个目录
2. 若预计会超过第一节的上限，直接按"索引 + 子文档"结构创建
3. 创建后到 [文档索引](07_文档索引.md) 登记一行
4. 不得在 `docs/` 根目录新建文件
5. 新增后检查是否需要同步 [进度看板](01_进度看板.md) 或 [待办](02_待办.md)
