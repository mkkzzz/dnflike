# 文档规范

> 目的：让文档在规模增长后仍然可读、多区并发时不冲突。由 `python tools/check_docs.py` 自动检查。

## 一、单文档体积上限（脚本检查）

| 文档 | 上限 | 超出怎么办 |
|---|---|---|
| `README.md` | 60 行 | 移入 `docs/`，只留链接 |
| `AGENTS.md` | 120 行 | 细则移入 `docs/project/`，只留指引 |
| `docs/project/`（含 `status/`） | 150 行 | 拆出子文档，主文档只留结论与索引 |
| `docs/design/` | 300 行 | 拆成 `NN_模块.md` + `NN_模块_子主题.md` |
| `docs/reports/` | 不限 | 天然按次归档 |

满足任意一条也该拆：读一遍超过 5 分钟；包含 3 个以上不相关主题；超过 3 个月仍在被追加（说明它在当流水账用）。

## 二、单一事实与并发

- **易变数值只写一处**：回归项数、资源数量、版本状态等只在 [进度看板](01_进度看板.md) / [版本注册表](05_版本注册表.md) 写，其它文档链接过去，不抄数字。过程记录（`docs/reports/`）里的数字是当时的快照，可以保留
- **不写"最后更新"行**：多个区同时改必然冲突，更新时间用 `git log` 查
- **多人共写的内容按区拆文件**（如 `status/ws<N>.md`），或设计为只追加并在 `.gitattributes` 设 `merge=union`（如交接日志）
- 状态词只用 [状态词总表](05_版本注册表.md#状态词总表)

## 三、README 定位

只放基础须知：项目是什么、怎么跑、怎么验证、去哪看更多。
不放：完整功能清单、键位表、美术管线细节、进度记录、版本说明。

## 四、目录职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `docs/project/` | 协作规则、进度、待办、登记、日志、版本与状态词、文档规范与索引 | 设计内容、过程记录 |
| `docs/project/status/` | 每个工作区一个状态文件，只由本区修改 | 其它区的状态 |
| `docs/design/` | 设计文档（长期维护） | 一次性过程记录 |
| `docs/reports/<ws>/<YYYY-MM>/` | 过程文档，按工作区 + 月份归档 | 设计内容 |
| `docs/tasks/<类别>/` | 任务包（单项规格、批准、交接） | 通用规范 |
| `docs/previews/` | 评审媒体 | 源文件 |
| `docs/screenshots/` | 实机证据 | 概念图 |
| `art/` | 源图、生成记录、导出资源 | 过程文档 |

**`docs/` 根目录不新增文件**（脚本检查）。

## 五、命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 过程文档 | `<YYYY-MM-DD>_<主题>.md` | `2026-10-14_V6实装错位修复与验收.md` |
| 工作区 ID | `ws<N>` | `ws1` |
| 资源版本 | `v<N>` | `v6` |
| 资源语义 ID | `<type>.<subject>.<purpose>` | `actor.player.base.combo.1` |
| 任务包 | `docs/tasks/<类别>/<task_id>.md` | `art_tasks/art_uppercut_01.md` |

## 六、脚本检查项

`python tools/check_docs.py` 检查：相对链接有效、反引号里的仓库路径存在、表格列数一致、体积上限、`docs/` 根目录无文件。新增文档后在 [文档索引](07_文档索引.md) 登记一行。
