## 状态词总表

全项目只用下表的中文状态词；需要机读时用右列，与 [14 美术资源全流程](../design/14_美术资源全流程.md) 的生命周期一一对应。

| 中文状态 | 机读态（14） | 含义 | 谁能填 |
|---|---|---|---|
| 规划中 | `planned` / `spec_ready` | 已立项，规格编写或已就绪 | 产出方 |
| 源图制作 | `source_review` / `source_approved` | 源图生成、评审中或已批准 | 产出方 |
| 预览认可 | `baked_validated` / `preview_approved` | 已烘焙校验，离线预览获用户认可 | 产出方（需用户认可） |
| 已发布 | `integration_ready` | 已提交推送，等接收方接入 | 产出方 |
| 已接收 | — | 接收方已同步并校验入口（交接用） | 接收方 |
| 已实装 | `integrated` | 已接入游戏工程并通过回归 | 接收方 |
| 已验收 | `runtime_approved` | 实机试玩获用户认可 | 接收方 / 用户 |
| 阻塞 | `blocked` | 记录阻塞原因与恢复入口 | 任何人 |
| 已弃用 | `rejected` | 保留弃用原因 | 产出方 |
| 已替代 | `superseded` | 指向替代版本 | 产出方 |
| 搁置 | `on_hold` | 主动暂停、保留资料（14 未定义，本项目扩展） | 用户决定 |

交接日志、版本表、资源总清单、任务包都用这一套，不再新造状态词；括号补充（如"待试玩评审"）只作说明，不算新状态。

## 二、登记规则

- **新增版本**：先在本文加行，再按 [21 目录规范](../design/21_美术目录与资产归档.md) 建对应类别/身份/版本目录，不把新版本塞入历史演示包
- **编号规则**：`v<N>` 单调递增，禁止复用已退役编号
- **状态回填**：产出方最多填到"已发布"，之后由接收方填
- 与 [美术资源总清单](../design/16_美术资源总清单.md) 的分工：本文记录版本级状态，总清单记录单项资产状态；两者冲突时以实机证据为准并回填
